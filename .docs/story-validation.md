# 物語と依頼の自動検証

物語や依頼を変更するときは、開始条件・会話・完了操作・得るもの・繰り返した結果を、本番データと実際の進行処理に対するテストへ反映する。テスト専用の進行規則や台詞を作らない。前提条件と結果を別々に検査し、進行を直接書き換えて到達できたと扱わない。

`vp run test:story` はブラウザなし、単一ワーカーで依頼・会話・親しさ・保存の関連検査を実行する。全体テストにも同じ検査を含む。重い検査は直列で行い、ブラウザ確認は並列実行しない。

## 依頼から表示と保存まで

`errand-playthrough.test.ts` は実行用の依頼定義を無条件で列挙する。本物の日替わり抽選と住民の予定から、その日の期限内に依頼元と受取人に会える場面を選ぶ。初期資材を明示し、受注・引渡しはサーバーと共通の `apply` を通す。親しさや依頼の進行は注入しない。

受注前と期限切れの選択肢、受注後・材料不足・引渡し可能・受取人に対する完了後の会話と選択肢を照合する。その段階の専用台詞が定義されている場合に実際に選ばれ、別段階の台詞は出ないことを確認する。すべての依頼と段階に専用台詞があることは要求しない。配達依頼元の完了後は進行値だけを確認し、専用台詞の選択は対象外。

必要な材料だけを消費し、報酬と親しさが一度だけ増えることを確かめる。相手違い、重複受注、重複引渡し、期限切れでは拒否理由と状態の不変を確認する。

受注後と完了後の状態をJSONにして実際の保存読込処理へ渡し、再開後も同じ会話・選択肢と重複拒否が保たれることを確かめる。追加した依頼を対象から除外して成功にしない。

`errand-resumption.test.ts` は全依頼を実 Player DO の受注・引渡しへ通し、それぞれの書込みを失敗させても保存済みの全記録が変わらないことを確認する。別の Player DO インスタンスへ再起動して再試行し、材料の消費・代金・親しさ・完了記録が一度だけ反映され、受注と引渡しの再送では全記録が変わらないことを検査する。時刻は本番の日替わり抽選から選び、開始材料は局所条件とする。住民への接触や経路はこの保存入口の検査には含めない。

## 検査の境界

予定から選んだ場所と時刻、持込み材料は明示した初期条件。そこまで歩く経路、採集による材料の入手、実ネットワークと実 Workers のストレージ、全住民の親しさの到達経路、全条件の組み合わせは、この検査だけでは証明しない。

選択肢や台詞の出力検査と、最終的な配置・読みやすさは分ける。出力データだけでは判断できない変更に実画面の確認を使う。


`craft-resumption.test.ts` は正本の全レシピについて、成功・失敗それぞれの実制作を Player DO へ渡し、保存失敗後の再開、材料・代金・スタミナと完成品、同じ要求の再送、内容の変更と古い番号の拒否を検査する。作業場への距離と部屋からの通知は `map-room/craft-resumption.test.ts` でスープの制作を通し、応答消失後の再送、同じ実行中オブジェクトでの保存再試行も確認する。拒否済みの要求は後から材料を足しても結果を変えず、新しい番号なら実行できる。再送の応答は別操作後の現在の状態を返し、出来事を再発行しない。

材料・技能・運搬力は局所的な開始条件で、各レシピまでの成長・採集・移動の到達性や全品質の分布はこの検査の対象外。保存先・通信先・時計・乱数の出力先だけを差し替え、制作と消費・経験値・品質・保存再開は本番処理を使う。実ネットワークや Workers のディスクを試したものとは分ける。

`storage-resumption.test.ts` は正本の全アイテムと使い減った道具を実 Player DO に渡す。預けられない大事なものは保存済みの全記録が変わらず、それ以外は預入・引出しそれぞれの保存失敗でも全記録を保持し、再起動後の再試行で品の数量・品質・作り手・耐久を保って戻せることを確認する。古い選択内容を再送しても品物・代金・親しさを変えない。持込みの品と運搬力は局所条件で、窓口までの移動・営業時間・部屋からの通信は対象外。時計と保存先だけを差し替え、実ストレージの障害そのものを再現したものとは分ける。
