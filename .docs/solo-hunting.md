# 一人で続ける狩り

## 目的と範囲

対象を選ぶと接近と通常攻撃が続き、プレイヤーは戦技、術、回復、離脱を選ぶ。常時の回避と位置調整を求めず、同じ場所で育つ感触と、次の相手へ進む目標を残す。戦闘は [[world#魔物]] に従って暮らしの一部とし、素材の売却、職人への依頼、装備更新を町へつなぐ。自動で次の敵を選ぶ仕組みや、放置中の自動回復は加えない。

## 完了の条件

新規キャラが初期資源から店で剣または杖を得て、通常の能力振りとスキルで戦える。スキル、薬、応急手当を使っても自動攻撃の対象が失われず、離脱は地面の指定または停止で行える。

狩りに持ち込んだ食事で継続でき、スタミナ不足なのに満腹で補給できない状態を短い狩りの必然にしない。座った休憩は最大値の増加に追いつき、回復待ちが狩りより長くならない。薬と料理の制限、採集・生産の消費、食事を買う意味は保つ。調整値と連続討伐の検証は実装と関連試験に置く。

序盤、中盤、上限付近に段階の異なる相手がいて、通常攻撃だけよりスキルを使う方が効率よく戦える。上位の素材は職人が装備に加工でき、自分の生活スキルを未開放の節目まで育てることを要求しない。生活スキルの上限と、既存の上位素材の解禁条件を変更して経路を作ったことにしない。

敵と素材は一対象一ファイルの設定資料を持ち、既存の地形と通路、生態、町の受取人と加工先を対応させる。新しい相手を置いたことと、マップ全体の生活・生態設計の完了は分ける。

剣と術の実行経路を規則の検査で照合し、実ブラウザでも通常の通路、対象選択、スキルと回復、討伐、補給、保存と再開を確認する。高い段階の検証用セーブは準備条件を明記し、初期資源からの到達を証明した実行と混同しない。面白さの持ち主の評価は、実装と検査から推測しない。

## 実装と確認

位置固定、自動攻撃を続けたままの戦技・術・回復、短い座り休憩、連続討伐に合わせたスタミナ消費を実装した。術の予約は相手と受付結果に結び付け、通信の揺れで攻撃間隔が早過ぎた場合も一度のキー入力を次の振りへ持ち越す。

砂丘と樹海に段階の異なる相手を追加し、[[hardened-scrap]]・[[root-resin]]・[[dense-jelly]] を職人の加工と買取につないだ。剣と杖の更新、水薬の製作は [[economy#狩りの材料から装備を更新する経路]] に従う。生活スキルの上限と未開放の節目は変更していない。

`apps/main/world/core/hunting-acquisition.test.ts` は初期所持金と能力ポイントからの購入・装備・技の条件、加工材料の通常の入手経路を確認する。`hunting-progression.test.ts` と `world/test/hunt-simulation.ts` は通常の能力ポイント以内の剣と術を各段階で照合し、依頼の材料と代金、完成期限、作り手、保存を確認する。`hunting-rest.test.ts` は座る直前の時間の付け替えを拒み、成長後の回復と食事を持ち込んだ連続討伐を確認する。`client/fight-skill-queue.test.ts` は早過ぎて無視された術の再送と、受付後の予約解除、別の相手への持越しの防止を確認する。

実ブラウザでは `scripts/check-hunting-start.mjs` が新規キャラの初期資源だけで剣・杖を実際の店から購入し、通常の通路、画面上の敵のクリック、一度の技入力、討伐と保存・再読込まで確認した。`HUNT_BUILD=mage HUNT_JITTER_MS=400` の実行では最初の通常攻撃だけを遅らせ、一度目の術要求が間隔判定に届かなくても、次の振りで受理されることを確認した。

`scripts/check-solo-hunting.mjs` はレベルと剣・術を指定して、各段階の戦闘、回復、報酬、保存を確認する。段階別の六通りを各一戦以上、剣の中盤と上限の術では食事と休憩を挟んだ連続討伐も確認した。最終の上限の術では、二戦とも各キー入力が一回ずつ受理された。町と HUD、戦闘と加工の窓も実画像で確認した。

高い段階は `apps/main/routes/api/player/hunting-fixture.dev.ts` による、認証済みの未使用キャラ専用の準備である。通常の能力予算と装備条件を守るが、経験値、装備、持ち込む食事と薬草を検証用に用意しており、新規から上限まで実時間で育てた記録ではない。`scripts/check-hunting-commission.mjs` も材料を明示して準備し、実際の職人への注文、代金と材料の消費、完成までの実時間の待機、受取・装備・保存を確認した。これらの準備経路は本番の出力に含まれない。

## 残る境界

今回のゴールは狩りの一巡であり、町やマップ全体の設計の完了ではない。`check:settings` にある既存の建物・部屋の資料不足と配置の干渉は [[backlog#設定資料と町の配置の整合]] に残す。新しい相手の個別資料も、生態と全地形の照合を終えた設計済みの資料にはしていない。持ち主が繰り返し遊びたくなるかという評価は、実装と検査から推測しない。
