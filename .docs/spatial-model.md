# 屋内外の共通空間

## 目的と現状

屋外と屋内を同じ実寸の空間に置き、外から見た建物の大きさと内側の大きさを一致させる。部屋ごとの座標が正しいだけでなく、異なる部屋が同じ使用空間を占有しないことを確認する。これは未完了の要件であり、現行のマップ切替と敷地検査だけでは保証していない。

現行の一棟内のセル座標と敷地への投影は `.docs/settings/README.md` の「一棟の共通座標」と同文書の「敷地と屋外の実寸」にある。実行時の `world/town/interior-plan.ts` は各階を別マップの中心へ配置し、表示用の倍率を適用する。この表示座標を世界の絶対座標とは扱わない。地域をまたぐ原点と全建物の配置・立体の占有、共通座標を世界全体の描画・移動・保存へ接続する処理は未完了である。

## 座標と境界の要件

物理的位置は世界を区別した実寸の座標で表す。マップとルームは空間の区画であり、チャンネルは同じ区画の接続者を分ける仕組みである。チャンネルを変えるたびに建物を別の物理的位置へ移さない。Durable Objects の分け方は [[world]] に従い、本書から変更しない。

各区画は親の空間への位置と向き、実寸の領域を持つ。建物の内部は外形と同じ元寸法から作り、壁厚・床厚・高さを含めて外形の内側へ収める。部屋の座標は建物と各階を通して同じ世界座標へ変換でき、逆変換で元の位置へ戻せる。見せ方の拡大率を物理寸法や移動距離へ混ぜない。

重なりの検査は外接矩形だけで終えない。屋外の区画が建物の敷地を含むことと、二つの部屋の使用可能な空間が重なることは別である。共有壁と床・天井の接触、親領域への包含、扉と階段の開口を区別し、二重の床や部屋、通れない接続を認めない。未設計の空間は空いていると推定せず、未照合として残す。


## 室内マップの親空間

既知の敷地を持つ資料案から作る室内マップは `MapDefinition.space` に親マップと実寸の座標系を保持する。`get-interior-map-space.ts` が建物と親の一致、外観の基準系、階高と表示範囲を検証する。`frame` の位置・幅・奥行はメートル単位で、原点の高さは基礎の完成床とその階の床高を足した値である。共通変換へ渡す鉛直の値は完成床からの実寸とし、描画の地面の高さや表示用の高さを混ぜない。

`get-map-space-point.ts` が親マップ内の実寸の点への変換を担う。入力の平面の位置は既存のマップ単位、鉛直の値は完成床からのメートルとし、平面の表示倍率を高さへ掛けない。`planarOrigin` と `metresPerPlanarUnit` は既存の二次元マップの座標から建物内の実寸へ戻すための原点と尺度である。歩行セルの中心を既存のマップ単位へ直してから原点を引き、尺度を掛け、`SpatialFrame` で親マップの実寸へ移す。屋外タイルの単位は `world/town/fit.ts`、室内の表示倍率は `interior-rules.ts` にある。

`MapDefinition.space.rooms` は、既知の資料案の同じ階の部屋 ID と、基準系の回転前のメートル単位の平面領域を保持する。`get-authored-room-space.ts` が元のグリッドを水平の連続した矩形へ変換する。家具と階段の記号は室内に含め、壁と共有戸口のセルは別扱いにして除く。この領域は室の平面の割当であり、歩ける床面や床開口の埋戻し、天井までの体積を表さない。階段の頭上高から全室の天井高を推測しない。未知の室や自動間取りへ部屋の実寸領域を補わない。

`assert-map-room-spaces.ts` は既知の室内領域について、ID の一意性と非空の形、基準系への包含、同じ階の矩形同士の正の面積の重なりを検査する。同じ室の重複も拒否し、境界の接触は許す。凹形の領域の空き部分を外接矩形で埋めない。この検査は一つのマップの基準系に限り、別マップ間の領域や天井を含む立体の非干渉を保証しない。

`get-map-room-footprints.ts` は各室の矩形を直接の親空間のメートル単位へ投影し、マップ ID・部屋 ID・親 ID と完成床高を保持する。四分の一回転なので二つの対角の点から各矩形を正確に投影できるが、部屋全体の外接矩形へまとめない。平面の表示倍率は適用しない。投影後に幅や奥行がゼロへ丸められた領域は、重なりがないものとして捨てず拒否する。

`assert-map-room-separation.ts` は全マップの親参照を検証した後で、異なるマップの部屋領域を照合する。直接の親 ID と完成床の実寸の高さが同じものだけを比較し、正の面積を共有する場合を拒否する。部屋 ID が同じでも別マップの重複を許さず、境界の接触は許す。高さの違いを丸めて同じ面へ寄せず、異なる親の座標も混ぜない。これは同じ平面の割当の重複検査であり、異なる床高の部屋が天井まで干渉しないこと、親の階層をまたぐ重なり、壁や床の固体の非干渉を保証しない。

親空間を持つ室内マップの生成では、`assert-interior-map-windows.ts` が同じ階の窓の在庫を資料案・室内・外観で照合する。各窓の位置・高さ・寸法と外向きの方向は親空間で比較し、欠落・余分な窓・重複や不一致を拒否する。これを各室の体積や全ての設備の立体の照合の代わりにはしない。

同じ親空間を持つ地上階の入口は `assert-interior-map-entrance.ts` が外観の開口と位置・完成床の高さ・寸法・方向を照合する。`assert-interior-entrance-cells.ts` は同じ開口から出入りと到着のセルが求められていることを確認する。上階の表示用の入口を街の開口として照合せず、街へ出る接続も追加しない。

`assert-map-space-registry.ts` は全マップを組み立てた時点で登録キーと ID、親マップの実在と参照の非循環を確認する。既知の座標系は `get-map-space-frame.ts` で表示の原点・尺度と実寸の基準系を検証し、点の変換も同じ検証を使う。親を持たないマップへ位置を補完せず、参照が終わることだけで世界の原点が設計済みとは扱わない。親の入れ子の変換や領域への包含、使用空間の立体の干渉はこの参照検査の対象外とする。

資料案の `parentMap` は参照先のマップ資料の `map_id` から解決した実行時 ID とする。設定資料の ID の接頭辞から実行時 ID を推測しない。親マップや敷地が未定の資料案と従来の自動間取りには `space` を補わず、未照合として残す。地域をまたぐ原点、各室の立体の占有、移動と保存で使う位置の切替は引き続き未完了である。

## 共通化した処理と残件

`lib/engine/spatial-frame.ts` は位置と高さ、平面の四分の一回転、点と方向、逆変換を扱う。原点は回転後の平面外接矩形の最小点と床の高さであり、幅と奥行は回転前の値とする。単位の換算は呼び出し側で行う。`scripts/lib/site-transform.ts` はこの処理を既存の敷地検査へ接続し、扉・建物・設備の平面の回転規則を共有する。地上階の部屋の敷地矩形は `scripts/lib/get-room-site-rectangle.ts` が投影する。戸口の連続マスは `get-grid-boundary-opening.ts` が調べ、境界の戸口は `get-site-door-pose.ts` が敷地の原点を含む同じ変換へ投影する。テストで四辺の戸口と投影後の部屋境界を照合する。無効な縮尺や座標から有限でない位置を返さない。共通変換は三成分の入力と変換後の位置を検証し、非有限値や欠けた座標を RangeError として拒否する。生成時には回転後の平面の両端も確認し、原点への加算で幅・奥行がゼロへ丸められる場合や非有限になる場合を拒否する。これは平面外接矩形の端の検査であり、任意の微小な距離の精度まで保証するものではない。戸口と部屋の資料を読む境界はこれを既存の不備の返し方へ戻し、窓は対象の ID を付けた不備として報告する。

生成済みの外観は `BuildingEnvelope.quarterTurns` に敷地の四分の一回転を保持する。屋根の軸や戸の方位から建物の向きを推測せず、元の建物の幅・奥行と敷地の原点から同じ座標系を再構成するための情報とする。この情報の保持だけで室内の表示座標・移動・保存が共通化したとは扱わない。

`world/town/floorplan/assert-authored-site-frame.ts` は、既知の外観の敷地・高さと回転からメートル単位の座標系を再構成し、回転後の内装の幅・奥行が外観の範囲と合うことを確認する。外観の生成を終えた書出しと、`planOf` が資料案を実行用の間取りへ採用するときに同じ検査を使う。外観がない場合は未照合とし、原点を補完しない。これは一棟の基準系の照合であり、各室の立体の占有や世界全体の原点・移動・保存の共通化ではない。

外観寸法と窓の投影、既存描画への高さの受渡しは [[architecture#資料の平面と描画への投影]] にある。

この変換があることは、世界の配置が完成した証拠ではない。全区画の実寸と親への配置、階の高さと外形、使用空間と固体の占有、接続面と相互の移動先を資料へ設計してから実行時へ接続する。世界全体の重なりと外観・内装の一致を判定できる検査も必要である。既存資料の未通過を消したり、未定の座標を仮の値で埋めたりして完了にはしない。
