# 場所と住民の設定資料

## この資料の役割

都市、マップ、建物、部屋、住民、モンスターごとに一ファイルを持つ。`index.json` が対象とファイルの対応を持ち、先頭のメタデータが ID、種別、参照元、関係する資料、設計状態、未解決点を持つ。既存のコードを確認して起こした現状整理と、生活を成立させるための設計を区別する。ファイルがあるだけで設計完了とはしない。

世界観は [[world]] が正であり、この資料から書き換えない。数値の戦闘調整や店の価格の正は引き続きコードにある。個別設定資料には、暮らしと場所のつながりを対象別に記述する。実行時の数値定義や調整用の一覧の代わりにはしない。同じ設定を複数ファイルの本文で決めず、対象の資料を参照する。

## メタデータと状態

先頭の `---` の間に JSON 形式のメタデータを持つ。JSON は YAML としても読める。`id` はファイル名と一致し、リンクもこの ID を使う。`source` は現状を確認した定義の場所であり、そのコードの自動配置が正しいという意味ではない。

`status` が「現状整理」の対象は、既存の設定と不足を記録した段階である。「設計中」は個別の設計案を持ち、まだ未解決の条件がある。「設計済み」は同居人、食事、水、熱、灯り、衣服、排泄物と汚水、灰、仕事、物流、寝床、収納、換気、通路が関連資料と整合した段階である。「描画照合済み」は、その設計と実際の画面、通行判定、人物の日課を照合した段階である。持ち主の承認はこれらと別に記録し、推測しない。

`design_gate` は「未通過」か「通過」を持つ。未解決の `issues` がある資料は通過にしない。未設計の `grid` は null とし、空の図を完成扱いしない。クイニョンとフエの内部は現行コードにはなく、地区や住民を設計済みのものとして捏造しない。

## 部屋の配列とグリッド

部屋の `grid.rows` は北から南へ行を並べ、各行は西から東へ同じ幅のセルを並べる。`cell_m` が一セルの実寸を持つ。`#` は壁、`.` は空いた床、`D` は出入口である。家具は一つにつき固有の一文字を持ち、`furniture` の symbol と対応する。

家具の rect は左上の x、y、幅、高さで占有を表す。access はその家具を使う人が立つセルである。持ち主、用途、入手元を持ち、寝台には眠る人を割り当てる。棚板や棒だけを伸ばして間仕切りを表さない。棚は奥行き、支える側板、置く物、取り出す側を持つ。

入口から部屋の使用面へ歩けることを先に検査する。家具の占有と、椅子を引く場所、扉を開ける場所、作業姿勢、火との離隔は同じものではない。床の到達性だけで生活を検証済みとはしない。connections は相手の部屋、対応する入口、階段や屋外への接続を持つ。全階を建物の共通座標に統合し、外観寸法とも合わせる。

## 同じ家具を時間で使い分ける仕事

`work_uses` は仕事をする住民、家具と椅子、材料や道具の収納先、対応する `routine_source` を持つ。日課の時刻はコードを参照し、資料へ別の時間割を作らない。食卓を手仕事にも使う場合は、食事との入替えと清掃、道具の回収を本文で決める。占有・灯り・収納容量を照合する前は status を proposed とし、pending に未照合の条件を残す。この項目を記入しただけで家具の使用や日課全体の成立を検査済みとはしない。

この形式は同じ建物の家具・椅子と収納区画を結び、私物の収納は本人または所属世帯のものを使う。担当住民、収納先と道具の作り手を design_dependencies に含める。参照の検査は家具と席の組、道具の所有と作り手、収納区画、コードの日課の動作を照合するが、容量・灯り・身体の動作や仕事量までは証明しない。

`kit.box.storage_item` は storage_room と storage_symbol が指す棚の contents 内の箱 ID を参照する。箱の外寸、底と側板の厚み、蓋の厚みは保管側だけに持ち、作業側へ写さない。作業側は包みの配置と保管時の離隔を持つ。包みの `origin_m` と `size_m` は空洞の幅・高さ・奥行の順で、底と壁の内面から測る。箱の空洞を共通の収納計算で求め、包みの外形と保管時の離隔、底への直接の支持を照合する。外形の配置は包みの中身や指の動作の証明ではない。各包みは所有者、作り手と出どころを持ち、作り手も部屋の設計の依存先へ含める。案の間は箱の参照を未記入にできるが、designed の仕事から実寸を持つ箱の参照を省略しない。収納家具へ箱を収めること、蓋の操作と持ち運び、灯りと作業量は別に照合する。

`table_setup` は家具の天板の北西を原点にした東西・南北の位置を持ち、箱と外した蓋の静止配置を表す。箱と蓋の幅は東西、奥行は南北へ向ける。外形は参照した箱から得て、実寸の work_surface による天板へ全体が載り、互いの離隔を保つことを照合する。designed の仕事では、この配置も省略しない。棚からの搬送と向きの変更、箱を支えながら蓋を持つ動作、腕と指、布と灯りの領域は別に設計する。

## 描画へ進む順序

1. 都市の供給と仕事をマップへ割り当てる。
2. 世帯と建物、住民の寝床・食事・仕事先をつなぐ。
3. 各部屋の家具、出入口、使用面を配列とグリッドで設計する。
4. 全階と外観、隣の建物、道、物の搬入出を照合して矛盾を解消する。
5. 設計済みのグリッドから描画と通行判定を組み立て、実画面と日課を照合する。

対象ごとの現在の設計状態はメタデータに、未完了の範囲は [[backlog]] に記録する。現在の描画や自動間取りを、この資料の設計済みの結果として扱わない。

## 自動検査

`bun scripts/check-settings.ts` は現在の対象の網羅、ID とファイルの一致、資料間の参照、家具の占有と使用面への到達を検査する。未設計の件数も表示し、通常の検査成功を設計完了と混同しない。`--require-designed` を付けると、未設計が残る場合に失敗する。扉の操作、階段や排煙の断面、収納と姿勢の個別検査もあるが、資料に定義した条件だけを照合する。未定義の生活の工程や、動作全体の干渉・日課を通過と推定しない。

## 一棟の共通座標

建物の layout は一セルの実寸、壁を含む計画矩形の幅と奥行、各階に属する部屋の ID を持つ。各部屋の origin は建物北西からのセル座標である。隣室は境界の壁セルを共有し、戸口は両室で同じ座標に置く。異なる部屋の床や家具を重ねない。全階のどのセルがどの部屋に属するかを説明できるようにする。

扉の connections は自室の door、相手の target_door、開口幅 width_cells を持ち、相手も逆向きの同じ接続を記録する。開口幅は通路の設計下限を満たす幅にし、家具のすき間とは区別する。現在の半メートルの格子では、単独の一セルを人の出入口として採用しない。

階段は kind を stair とし、上下の家具記号、下端と上端の使用面を持つ。隣り合う階で、階段の占有範囲と床開口を同じ平面位置に置く。検査は平面位置と使用面を照合するもので、頭上高や踏面、蹴上げ、戸と手すりの可動・立体干渉を保証しない。未解決の条件は issues に残す。

## 共同設備

井戸、洗濯場、窯など、複数の建物や住民が利用する設備も `facilities/` に一設備一ファイルを持つ。site は所属マップと、そのマップに実在する場所のキーを持つ。未配置の設備は status を proposed とし、存在する設備として設計を通過させない。設備を利用する人と、掃除・補修・運転する人は同じとは限らない。

都市の supply_systems は、水、食料、燃料、灰、汚水などの出どころ、加工や保管、使う場所、担当の範囲、未解決の行き先を持つ。既存の一人の職業へ、町全体の配水や廃棄物処理を暗黙に押し付けない。行き先が決まっていない物は、画面の配管や溝を追加することで解決済みとしない。

## 住民と寝台の対応

常用の寝床は一人に一つの固有 ID を持つ。寝間の sleeping_places は寝台 ID、利用する住民 ID、個別寝台であること、設計後の家具記号を持つ。住民資料の bedroom と bed_id はその割当を逆向きに参照する。bedroom_candidates を持つ場合は、選んだ bedroom を含む重複のない候補とする。個室へ分けた案では住民側の候補も同時に更新し、現行の実装との差は本文に明記する。同じ住民を複数の寝台へ登録したり、一つの寝台 ID を複数人へ使い回したりしない。

宿の客室の guest_capacity は常用の住民に割り当てた寝台と別に数える。各寝間の寝床枠は常用の割当数と客用枠の合計に一致させる。客室を宿の家族の寝床に数えて人数を合わせない。各住民の衣服・首巻き・私物の収納は、寝台の使用面と同時に設計する。個別の割当が済んでも、実寸の寝台・着替え・通路・収納が未配置なら部屋の設計は通過にしない。

## 生き物と生息場所

モンスターの ecology は食べ物、水、休息、集まり方、人との接点、警戒と反応を区別する。materials は落とす品がどこから来て誰に使われるかを持つ。戦闘の数値と入手確率はコードの定義を参照し、資料に調整値の正を増やさない。

生息するマップは実際の出現定義と、マップ資料からの逆向きの参照を照合する。マップの ecology_zones は種ごとに必要な地形条件と配置を持つ。placement が null なら未配置である。出現枠の矩形を、餌・水・休息地の設計の代わりにしない。再出現はゲームの復帰規則であり、繁殖や地域全体の個体数の説明ではない。

階段から直接入る上階の部屋は、外壁に架空の扉を追加して到達性を合わせない。connections で階段とその使用面を入口として宣言し、同じ家具の使用面であることと、下階との対応を検査する。家具を使う位置は自由な入口ではなく、宣言された戸口か階段から歩いて届かなければならない。椅子を使う作業と配膳のために立つ面も区別して記録する。

一棟の接続は、各部屋から地上の外部マップまで到達できることも検査する。部屋同士の接続だけで閉じたまとまりを作らない。外部への戸は地上階の建物外周にあり、所属する外部マップへ開くものとして扱う。上階から階段を省いて地上へ直結したり、別の屋内マップを外部として数えたりしない。立体の非常時の安全や複数人の通行を保証する検査ではなく、平面設計の接続の欠落を見つける検査である。

家具の seat_symbols は、その面に座って使う椅子の記号を参照する。椅子は role を seat として持ち、家具の側面に接して置く。部屋の別の場所に椅子があるだけでは、その食卓や作業台を座って使える設計としない。立って使う access と、椅子を引く姿勢・可動域の照合は区別する。

部屋間の接続の kind は door、opening、stair を使い分ける。扉のある戸口と開いた通路を両側で別のものとして記述せず、同じ境界の種別を一致させる。開いた通路も床の幅と移動の経路を持ち、描画の都合だけで通行を妨げる板や棒を追加しない。

## 設計の依存先と索引の網羅

design_dependencies は、配置や生活を成立させるため先に整合する必要のある個別資料の ID を持つ。屋外の仕事への経路を持つ住民は、その経路のマップ・出発する建物と部屋・到着する設備を依存先へ含める。室内干しの計画を持つ部屋は、所属する建物と物干しを担当する住民も依存先へ含める。部屋の常用寝床・個人収納・家庭の食事に利用者を割り当てた場合、その住民も依存先へ含める。仕事場を宣言した住民は work_rooms、担当者や共通の帰宅先を宣言した建物は workers と home_building も依存先へ含める。参照先が存在することと、生活設計が完了していることは分けて検査する。経路だけ検査できても、家や設備が未完成なら住民の生活設計を通過させない。部屋は所属建物と接続先、建物は各部屋と利用する共同設備、住民は寝床と住まい、生き物は生息マップと素材の利用者を関連付ける。依存先が未通過のまま、その資料だけを描画へ渡す判定を通過させない。相互に依存する設計は一緒に整合させてから判定し、循環した参照だけを理由に承認済みと推定しない。

索引の検査は、掲載された資料が存在することに加え、ディレクトリ内に索引から漏れた Markdown がないことも確かめる。ルートの本案内だけは索引の対象から除く。ID の種別とファイル名・置き場所を一致させ、同じ対象を別ファイルに重複させない。検査コードは `vp exec tsc --noEmit -p scripts/tsconfig.settings.json` で、実行する入口と関連テストも含めて型検査する。

## 敷地と屋外の実寸

建物の site_plan は、屋外タイルでの計画矩形の北西位置と、四分の一回転を単位にした向きを持つ。室内のセル寸法を実寸へ直し、屋外の一タイルの実寸で割って置く。見やすくするための室内表示の拡大率を、外観の大きさへ流用しない。

敷地検査は、他の建物の矩形と、道の中心線だけでなく幅を含む範囲への重なりを調べる。他にも敷地案がある場合は、そちらも計画中の矩形で照合する。source の古い建物の矩形だけを見て安全としない。

site_plan の status が proposed の案や、unresolved が残る案は描画へ渡す判定を通過させない。矩形と道幅の重なりがなくても、入口から道への接続、地面の高さ、屋根の張出し、窓と煙突、火と薪、屋外設備と作業姿勢の確認は別に必要である。

## 戸口から道への接続路

site_plan.approaches は、対象の部屋と戸口、通路の実幅、屋外タイルの折れ点を持つ。先頭は室内の共通座標を敷地の回転・位置へ変換した戸口の中心と一致させる。外観の古い扉マーカーを新しい設計の入口として流用しない。最初の区間は建物の外向きに出て、最後は幅を持つ道へつながる。

経路は中心線だけでなく幅を持って他の家や共同設備の占有と照合する。途中から自分の家を横切る線も通さない。共同設備の occupied_rect_tiles は確認できた占有だけを記録し、火口の作業面や薪・灰の運搬の離隔まで含んだものとはしない。路面の高さ、段差、屋根、扉の開閉、人や荷の姿勢とすれ違いは別に設計・照合する。

## 読み込み時の構造検査

資料の読み込みでは、共通の識別情報に加え、グリッド、家具、使用面、接続、階、寝台、敷地と接続路、生態と素材の入れ子の構造を検証する。壊れた配列や座標を、幾何検査の途中で初めて扱わない。未設計のグリッドは null、未確定の条件は issues と設計状態で表し、既知の項目へ不正な型や空の代用品を入れない。

検証は未知の追加項目を削らず、初期値も補わない。メタデータだけの空資料や、先頭の本文見出しが title と違う資料も対象別資料として通さない。この構造検査は、説明の丁寧さや生活上の矛盾が解消されたことを保証するものではない。設計の内容と完了の判定は別に行う。

## 個人収納の区画

寝間の personal_storage は、個人収納の ID、使う住民、しまう物、配置する家具の記号と区画を持つ。住民の storage_ids と寝台の storage_id から同じ割当を参照する。衣服・首巻き・私物の置き先を割り当て、共用の食材や仕事の在庫の収納と混同しない。

家具を配置していない割当は furniture_symbol を null とし、個人収納の ID だけで部屋の設計を通過させない。配置する家具は role を storage として持ち、使用面と持ち主を一致させる。一つの収納家具を共有する場合は owners と compartments を明示し、同じ区画を二人へ割り当てない。別々の ID を付けただけで同じ棚を二人分の容量として数えない。容量、衣服のたたみ方、扉や引き出しの開閉、物を出す姿勢の照合は別に必要である。

## 家具の占有と使う人の空間

家具の use_space は、activity と空ける床の rect を持つ。家具本体の占有とは別の配列として記録し、各使用面に対応する access を含め、用途ごとに家具を使う位置を示す。家具・壁・戸口のセルを使用中に人が立つ空間として数えない。到達できる一セルがあるだけで、寝具を整えたり衣装箱を扱ったりできるとはしない。

使用面の幅と通路の設計下限は `scripts/lib/spatial-rules.ts` が持つ。部屋を描画へ渡す判定では、各家具に使用空間があることも必要とする。平面の空きと幅を調べるもので、箱の蓋の高さ、姿勢、椅子や戸の可動域、複数人の同時使用を検証したことにはしない。既存の自動間取りの通路判定を、新しい設定資料の完成条件へ流用しない。

## 複数人の使用面

部屋の parallel_use は、同時に行う作業の activity と operations を持つ。各操作は occupants にいる住民名、家具記号 furniture、その家具の use_space の space_index を参照する。同じ人を二つの操作へ置かず、同時使用する面どうしを重ねない。境界が接するだけの面は重なりとしない。

指定した組合せでは、他の利用者の使用面を占有したまま、一人が出入口と階段、自分の使用位置へ身体の幅を持って行き来できることも検査する。使用面全体を塞ぐ保守的な平面検査であり、人同士が同時に歩いてすれ違う動きや家具の開閉の計算ではない。食材を取る移動全体、扉や椅子の動き、別の作業への切替、頭上や姿勢は別に設計する。parallel_use にない組合せや生活全体の同時使用を、検査済みとして扱わない。

## 本文の平面図

本文に格子を掲示する場合は grid のコードブロックとし、メタデータの grid.rows と一文字ずつ一致させる。家具の変更で本文の図だけを古いまま残さない。本文の図は配列の読みやすい表示であり、別の配置案の正にはしない。

寝台を格子へ置いた場合は、長辺と短辺を実寸へ換算して `scripts/lib/spatial-rules.ts` の寝台の下限と照合する。向きを変えても同じ基準を使う。人数と所有者が合うだけで、横になれない短い家具を寝台として認めない。この寸法は図面の設計下限であり、寝具の厚さや姿勢・使用面の照合を代替しない。

敷地の回転は `scripts/lib/site-transform.ts` の同じ規則を矩形の寸法、戸口の中心、外向きの方向へ適用する。外形の幅と奥行だけを入れ替えて、戸口の向きを元のままにしない。

寝床容量がない部屋も、寝台や客用枠の割当が紛れ込んでいないか検査する。容量をゼロにしたことを理由に割当の照合を省略しない。寝台を持たない通常の部屋では寝台配列を省略できる。

## 人の幅を含む通路

`scripts/lib/room-clearance.ts` は通路の設計下限をセル数へ切り上げた正方形の占有を動かし、戸口・階段の端と家具の利用位置をつなぐ。格子の軸に沿って一セルずつ移動し、斜めの隙間を飛び越えない。一点の到達検査も残し、人の幅の確認とは分けて扱う。

この正方形は格子上の保守的な平面検査であり、実際の体形や姿勢、回転、荷物、椅子・戸を動かす途中を再現するものではない。家具は図面に記した静止時の占有を使う。使用面の寸法や複数人の同時作業の照合も引き続き別に行う。

通常の `vp run typecheck` には設定資料の検査コードとテストの型検査も含む。資料の内容と参照・配置は `vp run check:settings` で確認する。設計完了の確認は引き続き `bun scripts/check-settings.ts --require-designed` を用い、未完了の資料がある間は失敗させる。

敷地案は屋外の川の中心線だけでなく半幅を含む占有とも照合する。標本点だけでなく点の間の線分を使い、矩形への正の重なりを検出する。接触だけで護岸や安全な離隔が成立したとはせず、川岸・屋根・地面の高さと排水は別に設計する。

本文の説明がなく、平面図のコードブロックやコメントだけがある資料も、本文を持つ資料として数えない。占有配列とは別に、利用者・用途と配置の理由を文章で記述する。

## 階の高さと直階段

floor_levels は階番号、床の高さ elevation_m、階段と踊り場の上の天井下面の最低高さ ceiling_elevation_m を持つ。stair_sections は下階と上階の部屋、家具記号、蹴上げの数 risers、踏面 going_m、進行軸 axis、下端の向き lower_end、両端の踊り場の奥行 landing_depth_m、有効幅 clear_width_m、両側に取る手すりの厚み rail_inset_m、床開口の長さ opening_length_m を持つ。下端の向きは軸の小さい側を start、大きい側を end とし、上端は反対側とする。

上下の床高の差と段数から蹴上げを求め、踏面と段数から直進する長さを求める。両端の踊り場を足して家具の占有へ収まること、幅、上端・下端の利用位置を検査する。設計下限は `scripts/lib/spatial-rules.ts` にある。

床開口は上端の踊り場の先から下り方向へ延ばし、幅は階段の有効幅と同じとする。開口の外では下階の天井下面、内では上階の天井下面までを、各段の高さから鉛直に測る。踏面が開口の境界をまたぐ場合は両側を調べ、踏面の中心だけで判定しない。両端の踊り場の空きも含め、最小の頭上高を計算から求める。

天井の高さや床開口が未設計なら null とし、頭上高の結果だけを推測して書かない。未設計のまま建物の設計を通過させず、階段のある建物は各階段に断面を持つ。格子の一致だけで段・床開口・梁・手すりの干渉を検証済みとしない。この形式は直階段を扱い、折返し階段を同じ長方形の計算で承認しない。

断面の高さは描画へ渡す設計値であり、現在の画像の実測値として扱わない。屋根・梁・床厚・手すりは、この天井下面と開口を侵さないように立体で設計する。ここでの鉛直の空きの検査は、身体や荷物を動かしたときの三次元の干渉を保証するものではない。

## 屋根の下面と軒

roof_section は棟の向き ridge_axis、軒と棟で人が使える屋根下面の高さ eave_underside_m と ridge_underside_m、張出し overhang_m、材質 material を持つ。高さは外の葺材の上面ではなく、部材の下面の計画値とする。切妻の断面を両側の軒から棟へ補間し、利用する床の矩形の四隅で最も低い高さを求める。

家具の使用面は床高から立つ高さを確保し、階段の天井下面の計画が屋根を突き抜けないことも検査する。手すりの厚みは階段の占有から差し引き、有効幅を外形の幅と同じにしない。梁や柱、手すりの取付けと開口の縁は別に立体で設計する。

屋根の平面は建物の回転後の外形へ張出しを足し、道幅、地図の境界、他の設計済みの屋根と照合する。他の建物の屋根が未設計なら壁の占有だけとの比較となり、その隣家との軒の離隔まで確定したとはしない。軒の張出しの検査を排水や火との離隔の代わりにしない。

## 内開きの戸

door_leaves は、壁際の戸口の door、蝶番の端 hinge、両端の枠が占める frame_inset_m、板厚 thickness_m、先に使用を終える必要がある作業 waits_for を持つ。一枚の内開き戸が四分の一回転する案として扱い、幅と蝶番位置は connections の戸口から枠の占有を差し引いて求める。hinge の start は図の x または y が小さい端、end は大きい端とする。

paired が true の戸口は同幅の二枚の内開き板を持つ。枠を除いた幅から合わせ目の逃げ meeting_gap_m を引いて半分ずつ板へ割り当て、両端に蝶番を置き、双方の回転を家具・壁・使用面へ照合する。有効幅からは二枚分の板厚を引く。一人の operation を二枚に流用しない。paired_sequence は最初に開ける端 first と、左右それぞれの身体の操作 start・end、取っ手を移る中心経路 transfer_points_m を持つ。操作の間は一枚が開き、もう一枚が閉じている状態として、板同士の衝突、身体の円弧、取っ手の間を歩く全区間を検査する。身体の大きさを途中で変えず、歩く経路の端を操作の円弧へ一致させる。二枚の操作順序がない案は設計通過にしない。開けた板を保持する金具、腕と姿勢、段差と立体の干渉は別に設計する。長い荷の搬入や旋回も、戸口の幅が足りるだけで確認済みにしない。

蝶番を壁の室内側の面へ置き、閉じた戸と開き切った戸の間を円弧で検査する。円弧の外接矩形の角にあるだけの家具を衝突扱いしない。家具・壁の占有を戸が横切る配置は、作業の順番で免除しない。

人が使う床を戸の開閉と共有する場合は、waits_for に家具記号と使用面の番号を持つ。これは先の作業が終わるまで戸を動かさない計画であり、同時使用を認めたり使用面の検査を省略する指定ではない。重ならない作業や存在しない作業を順序の制約として追加しない。

板厚のある戸は、長方形の回転を途中も含めて検査する。頂点と辺が接触する角度で開閉を区切り、その間の衝突を調べる。板厚や枠が未設計の案は線の検査に留まり、そのまま部屋の設計を通過させない。

戸枠の取付けと金具、操作する人の立体の姿勢、開き切った状態での人と荷物の経路は別に設計する。順序の条件も日課・操作と描画へ反映するまでは、実際の動作で確認済みとしない。

戸の operation は、操作する人の身体の平面半径 body_radius_m、蝶番から身体の中心までの距離 orbit_radius_m、閉じた戸から室内側へ測る開始と終了の角度 start_deg・end_deg を持つ。戸の開閉に合わせて身体の中心が円弧を動く案として扱う。身体の幅を通路の設計下限より小さくせず、戸の回転域の外側に身体を置く。

円弧の両端だけでなく途中も家具と壁へ照合し、戸の取っ手へ届く距離を開閉中に保てるか検査する。届く距離の設計上限は `scripts/lib/spatial-rules.ts` にある。これは平面の身体と腕の距離の計画であり、金具と枠の取付け、頭上、腕・肘と手首、戸や荷物を通る経路を再現するものではない。

開き切った戸の板厚も通路に残るため、枠を除いた戸の幅から板厚を差し引いた幅を、通路の設計下限へ照合する。操作する身体の中心から蝶番までの距離は、板の角の回転半径と身体の半径の合計以上を取る。戸の幅だけを回転半径にして板の端の厚みを落とさない。

検査コマンドの引数は既知のものだけを受け付ける。設計完了の指定を打ち間違えた場合に通常の検査へ戻らず、エラーで終了する。

## 日課の参照と生活の設計

住民の routine_source は file・export・key で `world/town/routines.ts` の ROUTINES にある本人の日課を参照する。時刻・居場所・行動の表を routine として資料へ転記しない。コードが時刻を変更しても資料に古い時刻が残らないようにし、存在しない定義や別人の日課を参照していないか検査する。

資料には、活動前の身支度と食事、活動中の食事、帰宅と片付け、就寝をどの部屋・物・人へつなぐかと、その理由を記述する。夜に働く人を含むため、全員に一律の昼の食事や昼の仕事を当てはめない。日課の定義が読めることを、食事・水・衣服・寝床と実際の移動の設計完了にしない。

## 私室と寝床への経路

部屋の private_for は、私室への出入りを許可する住民のIDを持つ。所属世帯とその部屋を使う人に対応させ、別の世帯の人を混ぜない。その部屋に常用の寝台・個人収納・家庭の食事の席を割り当てた住民は、出入りの許可から除外しない。この対応は全階の平面が未設計の草案でも検査する。住民ごとに許可された区画だけを通り、地上の外への戸から本人の寝台、household_meal の食卓、personal_storage のある部屋へ行けるか検査する。建物全体がつながっているだけで、他人の私室や客室を日常の通路にしない。部屋の接続と許可の照合は、家具と戸の身体幅・段差や荷物の通行、実際の日課の移動を代替しない。

私室の指定がない区画を、私室の設計まで確定したと扱わない。平面が未設計の建物は経路の完成判定をせず、設計未完了として残す。平面を持つ建物では私室の制限を含めて経路を照合し、共用の階段・踊り場と個人の寝室を区別する。戸の開閉、夜の灯り、目隠し、手伝いや手入れのための出入りは別に設計する。

## 参照先の種別

IDが存在することと、その欄に置ける対象であることを分けて検査する。部屋の building は建物、住民の bedroom は部屋、建物の residents と設備の users は住民を参照する。部屋の接続先は別の部屋かマップであり、存在する建物IDを代わりに置かない。寝台の所有者、収納の利用者、設備の所属マップなど入れ子の参照も同じように確認する。

町の外にあるマップは town を null として所属がないことを示せる。部屋や建物の親が未設定であることを、同じ null で正常な所属として扱わない。自由な追加メタデータは保持し、既知の関係を検査するために既定値を補わない。

## 仕事場と住まい

建物の workers は働く住民のID、住民の work_rooms は働く部屋のIDを持つ。仕事場の occupants と所属建物の workers を相互に検査する。建物の residents と本人の世帯・寝台は居住の関係であり、雇用から補わない。居住者へ含めるなら、その建物内に本人の常用寝台の割当が必要である。寝床のない醸造所・納屋・鶏小屋へ世帯全員を居住者として複写しない。共通の帰宅先がある仕事場は home_building で住居資料を参照し、workers と work_rooms は作業の関係として別に持つ。home_building を指定した場合は、担当者がその建物の居住者であり、本人の寝室も同じ建物に属することを照合する。通いの従業員は自宅の寝床を維持する。作業区画の配置案は日課や描画の実装済みを意味しない。

## 荷を持つ通路

cargo_routes は activity と、荷と運ぶ身体を合わせた外形の length_m・width_m、周囲に足す clearance_m、室内の中心経路 points_m を持つ。座標と寸法はグリッド原点からのメートルであり、屋外タイルへ混ぜない。長さは進行方向、幅は横方向に置き、身体の設計幅を外形から省かない。

経路は長さのある縦横の直線で描く。全区間を外形で掃引し、曲がる頂点には余裕を加えた外形の外接円を確保する。外接円は回転する全姿勢を含む保守的な予約面であり、細かな持ち替えで通れるかの判定ではない。室内の家具と壁、開き切った戸の板厚と、壁の奥行き全体に残る左右の戸枠を障害物とする。戸の板厚・枠の寸法や戸自体が未設計なら運搬経路も確認済みにしない。出入口のセルが空いていることを、枠まで空いている根拠にしない。

この経路の検査は室内に描いた区間だけを扱う。戸を越える搬入、屋外との接続、高さと荷の重さ、運ぶ人数、収納への納め方と同時使用は別に設計する。床の途中まで運べる案を、材料の調達から収納まで完了した経路に置き換えない。

## 空の荷車を後退させる予約

parked_cart_departure は空の荷車の駐車の家具記号と担当者、身体の円の半径・柄から身体までの余地、荷車の中心経路と南の専用戸を対応させる。駐車した形と同じ寸法の全体を使い、途中だけ縮めない。北へ向く柄を保持して南へまっすぐ後退させる案に限り、横滑りや据え回しを直線のつなぎで代用しない。

検査は駐車位置から始まり、移動する荷車だけを元の床の占有から外す。他の家具と壁、開いた戸板と金具・枠を残し、荷車の矩形と北に続く身体の円を全区間で掃引する。操作者は荷車の手入れの担当者と同じ町の住民に結び、設計の依存先へ含める。

exterior_apron は南の戸へ接する有限の待機範囲を局所のメートルで持ち、未配置のまま保持する。範囲外を自由な屋外として数えず、終点では荷車と身体の両方が室の外へ出ていなければならない。これは敷地へ割り当てた地面ではない。荷重と持上げ・腕と姿勢、戸を開けて保持する操作、実際の段差と地盤・敷地との接続が残るため、平面の予約だけで部屋の設計ゲートを通過させない。

建物に敷地の案がある場合、待機範囲を部屋の原点と建物の四分の一回転、屋外の尺度で同じ地図へ投影する。地図の境界、他の建物・設備と土地の予約、幅を含む道と川へ照合する。屋内表示の拡大率を使わず、壁と待機範囲を別の物差しで置かない。敷地が未割当なら屋外へのこの照合は未実施であり、局所の経路の合格から割当済みと推定しない。

## 敷地と一緒に付け替える道

地図の road_plan は現行の道への添字と元の両端を照合し、対象の中心線を置き換える案を持つ。同じ道を二重に変更したり参照元が変わった案を黙って適用したりしない。道の本数・幅と材質は保持し、変更しない道も含めて全体を同じ検査へ渡す。資料の案を実行時の地形へ自動採用しない。

両端は preserved なら元の位置を保ち、road なら指定した付替え後の道の中心線に接続し、building なら同じ地図の建物の戸口への経路の終点へ一致させる。道の接続は全ての置換を終えてから照合し、記述順で接続先が変わらないようにする。元の道への参照を持つことは、勾配・路面と排水・補修・荷を運べる動作や橋の耐力を検証済みとする根拠にはならない。

## 家族の食卓

部屋の household_meal は食卓の家具記号 table と、家族の resident と椅子の chair を結ぶ seats を持つ。建物の residents 全員を一度ずつ割り当て、実在する住民が部屋の occupants に含まれることを確かめる。通いの従業員を家族の代わりに置かず、一脚を同時に二人へ割り当てない。椅子はその食卓の seat_symbols に含まれる座席でなければならない。

座面中心の距離を身体の設計幅へ照合し、隣り合う椅子が窮屈な配置を検出する。これは膝・肘・座面高、配膳、全員が椅子を引く動作や同時使用の立体を証明するものではない。食卓の計画がない資料へ既定の椅子を補わず、未設計として残す。

`seated_body_review` を持つ案では、`scope` を `rendered_frames`、`status` を `unverified` とし、同じ `household_meal` の各人の元の着席姿勢を使う。座面の高さと向き、卓の同じ部材へ靴と膝の実際の描画形状を照合する。靴の接地・膝と卓の離隔から、座る途中、衣服と上半身、背もたれや同時利用の完成を推定しない。この状態では設計ゲートを通さない。

`meal_place_settings` と `tea_place_settings` は同じ家の `source_room` にある `dish_drying.items` の ID を、同じ食卓の各人の席へ割り当てる。食器の寸法は元の資料だけに持つ。`places` の resident と chair は `household_meal` と一致し、元の一式の各物を一度ずつ本人へ割り当てる。台所側の ID の重複や、卓上の割当の欠け・共有、別の持ち主の物を本人の物として使う記述は拒否する。

卓上の位置は天板の北西からの x・z とし、鉢は `upright`、匙は `flat` で天板へ直接置く。`quarter_turns` は平面の四分の一回転を表し、同じ物の幅と奥行を回した後の囲いへ使う。位置は回転後の囲いの北西とする。元の外形を使って天板の内側への収まりと `min_gap_m` の隙間を照合する。元の部屋と食べる住民は設計の依存先へ含める。`proposed` の配置は配膳や手の到達、時間を伴う食事と片付けの完成を意味せず、設計ゲートを通過できない。

各席の `reach_review` は、元の着席フレームを使う `rendered_frames` の案とする。`hand` と骨格の座標での肘の `pole` を指定し、物の外形の中心の上にある掌の準備点を `hover_above_m` で置く。骨の長さ・肩と座面の根元、脚と反対の腕を変えず、両腕・掌と袖口の囲いを卓と全ての食器へ照合する。`status` は `unverified` を維持し、姿勢間の動きや掴む接触、身体自身と衣服、食事の完成を推定しない。

`reach_review.withdrawal` の `fixed_native_frame_segment` は元の一つの着席フレームを固定した、開始の掌から `seat_target_m` への直線区間である。目標の x は本人の左を正、z は前を正として座る位置から取り、水平の位置を本人の向きへ回す。y は室内の床から取る。元の肘を固定の向け先にし、始点で元の肘と手首へ一致することを必須とする。各元のフレームで区間全体への到達と、卓・全員の食器に対する腕と袖口の連続した離隔を検査する。検査の分割限度を超えた未解決の区間は成功にしない。`unverified` を維持し、終点から上方の準備姿勢までの接続や、変化する全身のアニメーションを検証済みにしない。

## 戸口と接続の対応

各部屋のグリッドに描いた D は、その部屋の connections の一つの戸口に対応させる。行き先のない戸を描かず、一つの戸口のセルを複数の接続へ重ねない。部屋の戸口は部屋の境界に置き、隣室との共有位置と幅を照合する。上階から外へ出る戸を地上の出口の代わりに数えない。

## 家庭の排泄物と汚水

sanitation_role は privy、treatment、nonfood_planting を区別する。owner_building は持ち主の家を指し、家の facilities から同じ設備を参照する。caretakers はその世帯の住民とし、利用する家族と手入れする人を混同しない。

material_routes は stream と行き先 to、専用の container_id、案か確定かを表す status を持つ。排泄物 excreta と汚水 greywater は、それぞれを accepts_streams に持つ処理区画だけへ運ぶ。処理済みの残さ treated_residue と処理水 treated_water は処理区画から非食用植栽へ向かい、私有の経路では世帯を変えない。容器のIDを経路間で共有しない。処理区画の片方の出力を省いたり、未処理の物を処理済みと呼び替えたりしない。

設備の occupied_rect_tiles は、案の段階でも家・道幅・川・他の設備と地図の境界へ照合する。占有の検査は、処理能力や地下水の流れ、衛生の検証ではない。処理条件・容器容量・搬送・地形と運用が未解決なら設計を通過させない。

## 搬送容器と家具

家具の transport_container は、容器の id、stream、material と蓋の計画 lidded、円筒の外径と高さ outer_diameter_m・outer_height_m、内径と使う深さ inner_diameter_m・usable_depth_m、容量 capacity_l、空の重さ empty_mass_kg を持つ。容器のIDを別の家具や部屋へ重複して置かない。外径が台の占有内へ収まり、壁と底の余地があり、容量が内側の円筒の容積を超えないことを検査する。

material_routes の container_symbol は、出発する部屋や設備の家具記号を指す。その家具の容器のIDと用途が経路の container_id・stream に一致しなければならない。IDだけの案は container_symbol を null として残し、そのまま設計通過にしない。家具との対応や容積の検査は、蓋の固定、実物の重量や形、持ち上げと満量時の搬送、手入れ・衛生の確認ではない。

## 設備の図と敷地

設備にグリッドを持つ場合は、屋外の occupied_rect_tiles と実寸の幅・奥行を照合する。換算には町の実寸の単位を使い、屋内表示の拡大率を使わない。site の rotation_quarters で四分の一回転を指定したときは幅と奥行も同じ規則で回転する。屋根の張出し、地面の高さ、作業床と搬送経路は別に設計する。

## 容器の運搬荷重

material_routes の carry_plan は担当者 carrier と運搬時の充填上限 max_fill_l を持つ。容器の容量まで入れることと、運ぶときの量を分ける。一回は一つの容器を扱う計画であり、ほかの荷を同時に持つ条件を含めない。担当者は持ち主の世帯に属し、行き先の caretakers に含め、私室へ入る場合は private_for の許可も持つ。

住民の handling_plan は max_hand_load_kg、status、basis を持つ。この上限は家庭の運搬作業の設計仮定であり、実際の身体能力の測定値やプレイヤーの所持重量の式ではない。中身の密度上限の仮定は `scripts/lib/transport-load.ts` に置き、中身と空容器の質量を足して上限へ照合する。容器の容量や充填上限を超える案と、担当者や容器が存在しない案を拒否する。

担当者の設計と運搬上限が未確定なら、その経路を設計通過にしない。荷重の数式が通っても、持ち上げ、把手、蓋、戸・階段・屋外の経路と作業の頻度を確認済みにしない。

## 設備への屋外経路

`access_routes` は出発元の建物または設備を `from.document`、建物内の部屋を `from.room`、出発戸口を `from.door`、到着戸口を `door` で参照する。`points_tiles` はマップ座標の直交折れ線、`width_m` は確保する通路幅である。`status` は案を `proposed`、照合済みの設計を `designed` とする。

戸口の位置と外向き方向は敷地の回転から求め、道路への出入口と同じ変換を使う。経路は戸口同士を正確につなぎ、道幅を持つ正方形の身体領域で建物・設備・川・マップ外との交差を検査する。これは平面の占有検査であり、戸の操作、段差、頭上高、夜間の照明、荷を持つ姿勢の証明にはならない。それらが残る設備は設計ゲートを通さない。

処理設備の設計ゲートでは、`material_routes` が指す搬入元ごとの屋外接続を要求する。部屋からの搬入は所属建物と部屋を対応させる。一つの接続があることを、別の搬入元の経路の代用にはしない。屋外接続を持たない開放区画の搬出先と、屋内の使用面までの運搬は別途設計する。

世帯が住む建物の設計ゲートでは、その建物の部屋に `household_meal` が必要となる。別の家の食卓を参照して自宅の食事場所を充足したことにしない。人数だけでなく、一人ごとの物理的な席を照合する。

道路への `site_plan.approaches` は建物と設備の障害物に加え、マップの境界と川の全幅を照合する。折れ線の端だけではなく各線分の間の距離を使い、身体の幅も確保する。この平面検査は橋の構造や地面の高低差の照合を代替しない。

仕事場の所属は、住民の `work_rooms` と建物の `workers`、部屋の `occupants` に加え、その建物の `rooms` に含まれることまで照合する。部屋側の `building` だけを見て建物へ収録済みと判断しない。

部屋の `grid` を作った場合、その段階から普通の寝床と個人収納にも家具の参照を置く。設計ゲートが未通過であることを未配置の寝床を残す理由にしない。普通の寝台の家具は `role: bed` とし、固有の寝床割当と対応させる。家具が寝台と同じ大きさで持ち主も同じ、という理由だけで別用途の物を寝床へ割り当てない。

## 庭と予約された地面

家庭菜園は一つの庭を一つの設備資料で持つ。`ground_feature.kind` は `garden`、`index` は地面定義の庭の配列位置、`source_rect_tiles` はその位置が同じ対象を示すか検証するための元の形である。新しい配置の正は `site.occupied_rect_tiles` に置く。元の地面が編集されたら、移設案も照合する。検査は元データを書き換えず、提案された庭を同じ対象の代わりとして検査する。

元の庭を消したり縮めたりして家を収めない。地上面積を維持し、持ち主と家庭での用途、手入れする人を持つ。面積の維持は収穫量や衛生・作業性の証明にはならない。配置は建物の壁・屋根、設備・道路・川・他の庭と通路に照合し、畝・柵・入口・作業面・土と水・季節を別に設計する。畑・牧草地・豚囲い・墓地も、家や設備と通路が潰せない地面として検査する。

礼拝堂は世帯の家の一覧に含まれない固定建物として、`world/town/chapel.ts` の共通定義と [[building-chapel]] を照合対象に持つ。本堂と鐘塔の占有を分け、張出しも配置検査へ含める。自分の部位を除外する場合も、別の建物がその部位へ重なることは許さない。描画された外形と入口があることを、室内の図面ができた意味にしない。

礼拝堂の `layout_scope: main-body` は本堂だけの平面を表す。`layout` の幅・奥行とセル寸法から求めた実寸を、共通定義の本堂の外形へ照合する。ほかの家と同じセル寸法を前提にせず、軸の入替やセル一つの欠落も不一致として扱う。鐘塔まで設計済みとする範囲の変更は認めない。鐘塔と生活設備、立体が残る間は設計ゲートを通さない。

戸の `operation` は、円弧を歩く身体が家具や壁へ当たらず、身体全体が部屋の平面内へ収まるかも検査する。空のグリッドで衝突がなくても、身体が平面の外へはみ出す操作は認めない。室内戸が一つ成立することを、未設計の外壁の戸や人のすれ違いの代用にしない。

厚い壁の戸は `door_leaves.wall_depth_cells` に壁の奥行を持つ。省略時は従来の一セル壁とする。戸口から内側の面まで、戸口の全幅に床または戸口のセルが連続していることを要求し、その内側へ蝶番と開閉面を置く。壁や家具を飛び越して戸板だけを移動させない。これは平面の戸当たり位置であり、壁の構造、段差と水切り、屋外からの操作を代替しない。

## 宿泊客の寝床と荷物

客室は `guest_capacity` だけで寝床を充足したと扱わない。`guest_sleeping_places` に客枠ごとの寝台IDと荷物置きIDを持ち、住民の常用寝床・個人収納とは分ける。客の名前は固定せず、寝台と荷物置きは宿に属する物として維持する。IDを別の客枠や住民へ重複させない。

グリッドを作る前は家具の参照を null として未配置を明記する。グリッドを作ったら、その段階から全客枠に `grid_symbol` と `luggage_symbol` を要求する。寝台は `role: bed` で常用寝台と同じ実寸の下限を満たし、荷物置きは `role: luggage_storage` とする。二人分を一つの家具へ重複割当して定員を満たさない。所有者と使用面・通路、収納の容量と開閉、清掃と寝具交換は別の照合を要する。

宿の客室への経路は、世帯の private_for を持つ寝室と別の客室を通過せずに外の入口へつながる必要がある。世帯の寝室への経路も客室を通り抜けない。共用廊下と階段を実際の区画として資料化し、建物の全階平面へ含める。単に部屋どうしがつながっていることを、適切な入室経路の証明にしない。

川の占有は建物の壁と屋根の張出しを照合する。壁が川幅の外にあることだけで、軒の配置まで成立したと扱わない。また、道・川・隣家の占有検査を通った候補でも、広場の滞在・通行・設備の利用が成り立つかを別に照合する。未照合の候補を site_plan として確定しない。

複数の建物を移す案では、配置検査は全建物の提案を一度に投影する。壁と屋根を別の位置へ残さず、同じ敷地変換から両方を求める。ある家の移設が別の家の敷地を空ける前提なら、後者の design_dependencies へ前者を含める。提案した一件だけを現行の位置へ混ぜて採用しない。

## 家から屋外の仕事場への経路

住民の outdoor_journeys は提案した自宅の戸口と屋外の到着場所を結ぶ。現在の到着先 washing-upper-landing は共同洗濯場の階段上端であり、洗う足場まで到達した意味にはしない。出発の家に住む本人と仕事場の利用者が一致し、戸口と到着場所、道幅とマップ境界・障害物を照合する。到着場所の位置と幅は地面の共通定義から求める。

経路は身体幅のある軸に沿った線分で持つ。橋がある場合も川の判定を経路全体から消さず、橋の床が支える部分だけを除き、残る身体領域を川の全幅へ照合する。橋の縁から身体が出る配置は通さない。検査は平面の占有であり、荷の長さ・重さ、傾斜と段差・手摺・灯り、すれ違いと一日の日課を証明しない。

## 室内干しの占有と担当

室内の物干しは laundry_drying に木枠と担当する住民を対応させ、家具は role: drying_rack とする。濡れた布が占める範囲を家具の矩形に含め、布の下を空の通路として数えない。担当者はその部屋を使う世帯の住民とし、割当のない木枠や、同じ木枠の二重割当を拒否する。

現在の capacity_status は unverified のみであり、配置した木枠だけで乾燥量や運用を確認済みとはしない。この状態で部屋の設計ゲートを通過させない。布の寸法と重量・掛ける高さ、換気と灰・湿気、交換と乾燥の頻度を照合する仕組みと資料を整えてから、容量の確定へ進む。世界観の室内干しの条件は [[world#気候と灰]] に従う。

## 地上階へ搬入する在庫

ground_storage は、重い物を地上階のまま搬入する置場を家具へ結び付ける。家具は role: bulk_storage とし、中身と担当住民 handler を明記する。担当者はその建物の workers と本人の work_rooms、部屋の occupants に一致させ、所属建物と担当者を設計の依存先へ含める。所属する建物の地上階から、階段と常用・客用の寝室を通らず外の戸へつながることを検査する。private_for のある仕事の倉は、担当者に許可がある場合に限り通れる。担当者ごとに同じ条件を検査し、別の働き手の許可を借りて搬入できるとしない。置台の矩形が実際にグリッドを占め、置台の使用位置と各部屋の戸口へ身体幅で届くことも要求する。グリッドのない部屋や通路を塞ぐ部屋の参照だけで、搬入できると判断しない。置場を重複させたり、二階にある棚を地上階の在庫として数えない。

この検査は階と部屋の接続の照合であり、樽の直径・重量、運搬する身体、戸の開閉と段差、床の強さ・保管環境を証明しない。荷を運ぶ具体的な経路と操作は別に設計する。

## 鶏の個体と飼育設備

動物の所属マップ・数・外見・歩く範囲と速度は `world/town/animals.ts` を正とする。鶏小屋の animal_care は、同じ定義の個体IDを population_ids で参照し、keeper を担当する住民へ結ぶ。描画のスプライトやメッシュとは別の定義を使い、人の常用寝台の割当と混ぜない。同じ個体を複数の飼育室へ登録せず、種類の違う動物を鶏として数えない。止まり木・産卵用の巣箱・餌・飲み水・乾いた敷料・使用済みの受け・卵の受渡しを、それぞれ対応する家具の用途へ結ぶ。

keeper は建物の workers、本人の work_rooms と部屋の occupants に対応させ、部屋の設計依存にも含める。現在の収容と運用は unverified であり、個体IDと家具の対応だけで設計ゲートを通過させない。止まり木の高さと容量、巣箱の利用、各個体の帰路と休む時刻、餌と水の量・回収と衛生、寒さと灰を避ける換気と屋外の囲いは別に照合する。

## 火床と熱い加工品の用途

hot_work の process は forge・wax・smoking・metal_repair とし、省略した既存の鍛冶場は forge として読む。蝋の加熱は wax_heater、成形後に冷ます場所は wax_cooling を用途とし、金属の鍛造の熱源と混同しない。燻製の設備は smoking_heat、燻した後の食品を冷ます場所は smoked_food_cooling とし、金属や蝋の冷却面へ食品を載せる代用を認めない。鋳掛けなどの金属修理は repair_heat と repair_cooling を使い、鍛造炉や食品の作業面へ一律に読み替えない。

鍛冶場の hot_work は担当者 handler、火床 heat_sources、熱い物を冷ます台 cooling、冷めた品の棚 finished、炭などの受け fuel を別々の家具へ結ぶ。用途は forge_fire・hot_cooling・finished_storage・fuel_storage とし、同じ家具を複数の段階へ重複させない。担当者と作業部屋・建物の関係、設計の依存先も照合する。産業用の火床や冷却台、蝋の加熱・冷却を置く場合は、この工程の対応を省略しない。

この対応は火花や熱の離隔、工具を振る身体、熱い金属を運ぶ経路と冷める時間、炭の保管・煙と灰と消火、住まいと木の構造を検証した意味にはしない。家庭の調理炉を鍛冶の火床として読み替えず、鍛冶の物を食卓や寝床へ置く代用にしない。

## 家具の手入れ役

家具の owner は所有者、source は製作と調達の経緯を記す。手入れを担う人は maintainers の住民IDで別に持つ。建物に暮らす人、またはその部屋を担当する働き手へ結び、部屋の設計の依存先にも含める。別の建物の名称を文章で流用したり、存在しない人や所属しない人へ手入れを割り当てない。private_for のある部屋は、その許可のある人へ割り当てる。同じ家に住むことだけで他人の私室へ入れるとはしない。完成する部屋は、家具ごとに一人以上の手入れ役を持つ。

この割当は道具と材料・技能、作業の姿勢と安全、所要時間と頻度の証明ではない。製作する人と日々の手入れをする人も別であり、家具の調達元だけで維持できるとしない。

## 食卓の用途

household_meal が参照する食卓は role: table とし、椅子は role: seat とする。食事の人数と椅子の参照が合うだけでなく、食卓として指定された家具を使う。寝台・棚・炉などに椅子の参照を付けて食卓の代用にはしない。用途の照合は食器と配膳、卓面の高さと広さ、食事の時刻や片付けの証明とは別である。

全員の席を持つことは、全員が同時に勤務を離れて食べることを意味しない。交代で食べる案は meal_service の mode: staggered と routine_source を持ち、全利用者の日課の参照先と照合する。日課の内容そのものは既存の参照検査でコードへ結ぶ。この対応は食事の所要時間や調理・勤務の空白と睡眠の成立を証明せず、それらは別に照合する。

## 現行の家具の未描画

建物の runtime_graphics_omissions は、現行の `world/town/interiors.ts` が描けない元の家具を階と名前で記録する。実行時の間取りは unrenderedFurniture に元の配置・寸法を保持し、描けた家具の一覧へ混ぜない。現行の欠落を新しい平面案の家具の配置済みという意味にしない。

未描画の元の家具の記録だけで設計を未完成へ戻さず、本文と平面を先に整える。記録が残る状態では描画照合済みにしない。検査は全階の現行の内装から欠落を集め、資料の記録と階・名前・個数を照合する。欄を空にしたり削除しただけでは、現行の描画の欠落を解決したことにしない。元の間取りと描画を変更したら記録も照合し直す。描画から消えた家具を、元の配置に存在しなかったことにして検査対象から外さない。

## 元の部屋と現行の間取りの対応

建物の runtime_layout_omissions は、元の部屋の定義に対し、現行の自動間取りで同じ名前・同じ階の独立した区画を持たないものを記録する。間取りは unrepresentedRooms へこの一覧を残す。台所が居間に統合された場合と、燻し部屋のような仕事の区画が失われた場合を、名前の照合だけで同じ機能の欠落とは断定しない。対応のない部屋の用途・家具・出入口を個別に照合する。

全棟の元の定義と現行の区画を比較し、資料の記録と階・名前・個数を照合する。階が違う区画や、同名の一室を複数の部屋の代用として数えない。生成した共用廊下や土間は、それだけで元の仕事部屋を表したことにはしない。未対応の区画の記録が残る建物は描画照合済みにしない。記録を空にしただけで間取りの対応が直ったことにしない。

## 授業と席の対応

教室の classroom は teachers、routine_map、places を持つ。places は学ぶ住民と椅子・卓を結び、椅子は seat、卓は table の用途と seat_symbols で対応させる。学ぶ本人の learning_rooms と部屋の occupants、先生の work_rooms と建物の workers を双方向に照合する。日課の活動は `world/town/routines.ts` の activity を正とし、画面へ出す doing の文章を解析して人数を推測しない。授業の時刻・座標は資料へ写さない。

各人の椅子を重複させず、座る身体の間隔を照合する。席の対応は机の高さ、教材の量、先生の視線、出入りの混雑や授業と集会の時間の成立を証明しない。寄り合いの記録のように住宅でない部屋の private_for は、その部屋と建物を双方向に担当する働き手も指定できる。所属のない人へ許可せず、働き手の作業部屋への経路も他人の私室や客室を通さない。

## 実行時の加工設備への参照

設備の runtime_station は `world/town/stations.ts` の識別子を参照し、資料の site.map と実行時の所属マップ、設計の依存先を照合する。一つの実行時の設備を複数の設備資料で重複して所有しない。存在しない識別子を残したり、設備が移った後も古い地区の資料を照合済みとしない。この対応は火床と金床・冷却・燃料の工程や、身体の作業範囲の証明とは別である。

共同炉の現行の火床・金床・薪の地面は `world/town/craft-yard.ts` から予約地と屋外の障害物へ渡す。設備全体を包む長方形で間の空き地まで塞がず、物ごとの占有を使う。金床の円形の台座は保守的な外接正方形で照合する。これらは描画側の衝突寸法と同じ定義に従い、熱や火花の離隔、身体を動かす範囲として扱わない。

## 地形と床の基礎

建物の foundation は、世界の高さの基準から測る地上階の床面 floor_elevation_m、床の厚さ floor_thickness_m、地面から床下面まで保つ minimum_ground_gap_m を持つ。floor_levels は室内の相対高さのままとし、地上階を世界の地面の高さへ直接読み替えない。現行の地形の高さも平面と同じくタイルから実寸へ換算する。

地形は描画と同じ補間に使う格子の線と敷地の端で最小・最大を求める。四隅だけの試算で途中の盛上がりを見落とさず、床下面と地面の隔たりを全敷地で照合する。この検査は地盤の支持や沈下・石の基礎の断面、床下の通風と雨水の逃げを証明しない。

## 入口の外階段

entry_steps は室と戸、蹴上げの数、踏面、有効幅と手すりの厚み、上下の踊り場の奥行、下の踊り場の世界基準の高さを持つ。上の高さは foundation の床面に合わせる。戸の回転と同じ敷地変換から向きを求め、階段と踊り場の地面の占有を導く。踏面と踊り場が地面へ埋まらず、道・ほかの建物と設備・予約地を潰さないことを照合する。手すりの厚みを有効幅へ含めず、踊り場を省いて収めない。

入口への経路は戸から階段の中心に沿って下の踊り場へ届き、その後で道路へ結ぶ。有効幅より広い身体の通路を階段へ通す代用や、横へ抜けて段を飛ばす案は認めない。階段の支持と基礎・手すり・戸の操作、下の踊り場から道への整地と勾配、雨水と滑り・夜の灯りは別に照合する。

## 下の踊り場から道へつなぐ路面

外階段のある戸の通路は、approaches の section に高さ面の案を持つ。`level_turn_road_profile` は下の踊り場から一度直角に曲がる通路を扱い、曲がる場所の幅全体は踊り場と同じ高さにする。最後の区間は曲がる場所の外側から、road_index が指す道の現況の横断面へ連続してなじませる。道路側の端を一点の高さで平らにせず、道の幅に含まれる接続部分は現況の地形へ戻す。

maximum_longitudinal_grade は最後の区間に沿う縦断勾配の上限とし、幅全体の最も厳しい値を照合する。maximum_cut_m と maximum_fill_m は仕上げ面と現況地面の差の最大の深さ・高さを制限する。地形の格子境界と、高さ面の切替境界で分けた全ての領域を調べ、中央や四隅だけで途中の盛上がりを見落とさない。道路との接続部分が、幅を持つ道路へ全体として収まることも照合する。

status が proposed の案は pending を持ち、建物の設計ゲートを通過させない。designed は pending が空の案を表し、外階段がある戸では高さ面を省いて設計ゲートを通過させない。横断勾配と排水・路肩、路床材と切土・盛土の支持や量・運搬、通行の交代は縦断勾配と高さの一致とは別に設計する。検査によって現在の地形を書き換えたり、通常のゲームの通路へ採用したことにはしない。

## 戸を扱う人と家具の同時使用

操作する身体の円弧は、家具そのものだけでなく、別の人が家具を使う面とも照合する。operation.waits_for は重なる家具記号と使用面の番号、先に空ける理由 reason を持つ。戸板が使用面へ当たるときの door_leaves.waits_for とは分ける。実際には重ならない面を待機条件へ登録して成功させず、必要な条件を省略したり重複させたりしない。二枚戸も左右の操作ごとに照合する。

順番を記録することは、待つ人の立ち位置・移動の連続、外側から戸を扱う身体、同時に来た人の行き違いを証明しない。調理や燃料の取扱いは、手を離せる状態へ落ち着かせてから戸を扱い、火を扱う最中の人を避けて通れるという代用にしない。

## 外から戸を押して入る操作

一枚の内開きの入口戸は push_operation に身体の半径と、戸の角度ごとの身体の平面位置を持てる。位置は蝶番を原点とし、閉じた板に沿う向きを第一軸、室内向きを第二軸とする。閉じた状態で身体は外側、開いた状態では内側にあり、角度は順に増える。記録した位置と角度の間は連続して直線で変わるものとして検査する。

戸板から身体までの距離と取っ手への距離は、移動量と回転による距離の変化の上限を使って区間全体を照合する。端の位置だけが通っても途中で接触する案は認めず、細分しても証明できない区間は未確認として失敗させる。身体と戸板の厚みを減らす代用はしない。

入口の上の踊り場は entry_steps の有効幅と奥行を使い、壁の厚みを含む開口と室内の床へ結ぶ。身体が床のない角へはみ出さず、枠・壁・家具と他の人の使用面へ入らないことを全移動区間で照合する。開いた後も取っ手を保持したまま室内側の operation の閉め始める位置へ移る。この移動で身体を小さくせず、取っ手へ届かない空白を作らない。二枚戸の外からの操作、手と上半身・荷物・戸の重さと保持、複数の人の待機は別に設計する。

## モンスターの形状の参照

モンスターの `appearance.shape_source` は描画と共用する寸法、`footprint_source` は各種の拡大・伸縮と向きから身体を覆う範囲を求めるコードを指す。`look`、`color`、`size` は実行時の種類の定義と照合する。未指定の色と拡大率は null とし、実行時の既定値を文書へ別に写さない。`movement_clearance` の `walk_grid_adopted` は、身体の囲いを休憩地点と経路の通行格子へ採用したことを表す。身体の範囲を求めるだけの状態と区別し、実際の障害物の形や生態の配置まで完了した意味にはしない。

## 野外の生息面の配置案

マップの `ecology_zones` は、実行時に登録された種ごとに一つの条件を持つ。`placement` が null の条件は未配置である。配置を検討するときは `placement.status` を `proposed` とし、独立した生息区画を `sites` に記録する。各区画は固有の `id` と地形に沿う `grid`、餌・水分・休息・退避を分ける `features`、水分収支の `hydrology` と未照合の `pending` を持つ。格子は世界座標の起点と一セルの幅を持ち、既存の通行不能セルを `#`、通れる地面を `.`、各生息面を固有の大文字で表す。各面には矩形、隣接する利用位置、供給源と管理の説明を持つ。湿った地面を水面に読み替えない。

現在の配置案の面は `walkable_ground` に限り、元の通行格子を維持する。利用位置どうしは対象の種の身体全体が通れる経路で結ぶ。身体と経路は配置の格子内に収め、範囲外の未設計の地面を借りて通さない。格子との一致と経路が通ることは、生息面を実際に利用する動作や、その資源を維持できる証明ではない。水分は `hydrology` に供給と損失、乾燥時と灰の影響を記し、未照合の条件を `pending` に残す。未配置と配置案はいずれも設計ゲートを通過できない。地形・生態・人の仕事と描画を照合する前に、状態の文字だけを変えて採用しない。

同じ種が別々の出現範囲を持つ場合、各範囲に餌・水分・休息・退避の利用位置を記録する。各区画の格子全体は少なくとも一つの登録された出現範囲に収める。離れた区画の間をつなぐ未設計の経路は作らず、区画ごとに到達性を照合する。東側だけの資源を西側の個体の資源として数えない。この照合は利用位置と範囲の対応を確認するもので、各個体がいつその位置を使うか、範囲内だけで全経路がつながるかを証明しない。移動と資源利用の動作は別に照合する。

## 運搬の空間と動作の割当

灰箱の `receiving.transport_candidate` は身体の経路と固定した姿勢の空間の案を持つ。`gait_review` は各描画姿勢の離隔、`step_plan` は区間ごとの方向と動作、再生の向きの割当を持つ。既存の `carry` には再生方向を持たせる。足の目標から作る `side_step` はクリップを再生せず `playback` を null とし、歩幅の上限と足の持上げ、腰を落とす量と標本姿勢だけの照合の範囲を別に持つ。区間の歩幅は上限を超えない完結した周期へ距離を均等に配分して求め、端で片足を浮かせて止めない。横移動の `timing` は一周期の最小時間と身体の速度・加速度の上限を持ち、距離と位相を同じ時間から求める。未割当は `animation` と `playback` の両方を null とする。空間が空くことを、足運びの割当や接地の証明にしない。未割当は null と未確認の状態で明示し、条件は [[town#運搬の経路と足運びの向き]] に従う。

## 小さな布の物干しと収納

家具の `cloth_drying` は、一枚ずつ別の横棒へ中央で折り返す布を扱う。横棒の位置と長さ・太さ、布の幅・長さ・厚み、布間の隙間と床からの離隔、受け皿の内側へ収まる垂直な滴下の範囲を持つ。室内物干しの担当は既存の `laundry_drying` から結び、常用の衣服や寝具を小さな布の枚数へ含めない。

`storage` は同じ部屋の棚と布の ID を参照する。棒の本数を布の枚数とし、折り返した各布の二層を全枚数分だけ収納できる寸法を確保する。空の棚や一枚分の厚みを全枚数の収納として数えない。配置と収納の照合は乾燥の時間・換気量・汚れの交換の証明ではなく、乾燥能力は未確認のままとする。

## 食事用の器の水切りと収納

`dish_drying` は、洗い桶 `washed_at` と台 `support`、収納の棚 `dry_storage`、受け皿と格子、個々の器と匙を結ぶ。格子は受け皿の縁より上へ置き、台と皿の内側へ収める。`items` の固有 ID・持ち主・製作元・外形の実寸を同じ物の水切りと収納へ共用する。乾燥位置は格子北西からの x・z、収納位置は参照する箱の内側の北西底からの x・高さ・z とする。器を伏せる向きと、周囲の空気の隙間も持つ。

収納の検査は箱の壁・底と蓋を除いた内寸へ外形を配置する。`storage.support` が `box_floor` の物は高さをゼロにして箱の底へ直接置き、空中へ浮かせたり積み重ねたりしない。中空の器を自動で入れ子にしたり、物の間の空白だけで格子への支持を証明したりしない。`status` が `proposed` の案は設計ゲートを通過できず、縁の仕上げと接触面、格子の固定と強度、運搬と手、乾燥能力と清掃は未照合のままとする。

鉢の `bowl` は平らな底の直径、半径方向の壁厚と底厚を持つ。外形の幅と奥行は同じ円の直径とし、口へ広がる外側の断面と内側の空洞を同じ実寸から求める。使用容量には内側の空洞だけを数える。外形に収まることだけで釉と縁の仕上げ、強度や運搬時の安定を照合済みにしない。

格子は四辺の枠と、その上へ両端を重ねる正方形断面の棒、受け皿の底へ届く四隅の脚を持つ。`frame_bottom_above_tray_floor_m` は受け皿の内側の底から枠の下面までであり、脚の高さにも使う。描画と接触の照合には同じ部材の囲いを渡す。軸対称の空の鉢について、口の厚みの中央の円と棒の中心線の接触点が、中心の周囲の余裕を持つ矩形を囲むことを検査する。これは水平な格子への鉛直荷重の静的なモデルであり、縁の丸み・濡れた状態の滑りや動的な荷重・強度を保証しない。


## 着席した手の準備工程

食卓の `reach_review` は、物の上方の準備点に加え、元の姿勢からの `withdrawal`、同じ掌の位置で肘の向きを変える `elbow_swivel`、本人の脇で持ち上げる `lift` を持てる。持上げは引戻しと肘の切替えを前提とし、工程を省いて姿勢を飛ばさない。各工程の状態は未確認を明示する。座る位置を基準にする目標の座標と具体的な生活の案は [[room-h1-1#右脇で肘を切り替えて卓上へ寄せる区間]] にある。

検査は元の各着席フレームを固定して、同じ骨長と障害物に対する連続した離隔を求める。肘の向きが定まらない区間や、細分の限度で離隔を証明できない区間は拒否する。時間を含む全身の動作や物への接触、実行時の採用の代わりにはしない。


元の着席姿勢に身体自身との干渉がある場合、`reach_review.rest` へ左右それぞれの掌の目標と肘の向け先を明記できる。片手だけの割当は認めず、元の骨長と着席の根元・脚を保って両手を解く。全工程へ同じ開始姿勢を渡し、後続の姿勢で反対の腕を元の位置へ戻さない。開始する前腕と本人の他の描画部材、両腕と卓・全員の器の離隔を全着席フレームで照合する。これは上腕や肩・椅子、全身の連続した動作と実行時への採用の証明ではない。具体的な案は [[room-h1-1#資料から作る両手の開始姿勢]] にある。


着席の `lift.pole` は、低い引戻しの後の肘の切替えと持上げに使う向け先を持つ。省略時は `reach_review.pole` を使う。持上げの終点で掌を固定したまま `reach_review.pole` へ切り替え、その後の前進に使う。`advance` は持上げを前提とする未確認の位置であり、ここから各物の上方へ寄せる。工程を省略して関節の位置を飛ばさない。

資料の `rest` を指定した準備経路は、卓と器に加え、動く前腕・掌と切る前の袖口を本人の他の固定した描画部材へ連続して照合する。固定した元のフレームの幾何の検査であり、上腕と肩への付根、椅子、時間を含む全身の動作や接触を通過と推定しない。具体的な工程は [[room-h1-1#卓と身体を避ける前腕の準備経路]] にある。


## 着席と椅子の枠の照合

`seated_body_review.chair_frame` は `scope: back_and_legs` と未確認の状態を持つ。椅子の実物の部材は描画と共用し、四本の脚と背もたれへ身体の全描画部材を照合する。脚の欠落を自由な床と解釈して通さない。元の着席フレームと、資料の両手の開始姿勢をそれぞれ照合する。

この範囲には座面の支持や衣服、足置きの接触、着席と立上り、姿勢が変わる全区間を含めない。座面のある場所を無条件に身体へ許可するものではなく、内部の重なりが見つかった場合は資料の未完了へ残す。具体的な不整合は [[room-h1-1#椅子の枠と座面の支持]] にある。


## 着席した衣服と座面の照合

`seated_body_review.garment_seat` は `scope: tunic_coat_tails_and_trousers` と未確認の状態、同じ食卓の対象住民の重複しない ID を持つ。描画が返す実際の胴衣と上着の裾、ズボンを座面へ照合し、対象の衣服がない住民を成功として通さない。ズボンの腿は支持面への接触を認めるが、板の内部への侵入は認めず、腿と元の下腿の実形状を囲う範囲をそれぞれ照合する。身体の支持、女性の衣服や着席と立上りの連続した動作は別の設計であり、この検査から完了を推定しない。個別の案は [[room-h1-1#男性の裾を腿へ沿わせる]] にある。


`seated_body_review.skirt_seat` は `scope: skirt_layers_and_trousers` と未確認の状態、対象住民の重複しない ID を持つ。元の住民の外見にあるスカートの全層と左右のズボンを対象とし、欠けた層や囲いを成功にしない。同じ住民を胴衣の照合へ同時に割り当てず、別の衣服の成功を引き継がせない。具体的な布の経路と残件は [[room-h1-1#座ったスカートの布の経路]] にある。


## 住民の外見の参照元

住民の `appearance_source` は `world/town/residents.ts` の `RESIDENT_LOOKS` と本人の名前の key を指す。`RESIDENTS` の同じ名前から位置を解決し、実際の描画へ渡す外見を参照する。資料の並びを配列の添字にせず、別の人と同名の重複、不在の描画定義を拒否する。

元の服装の定義を appearance に複写しない。実行時には首巻きや前髪が補われ、休止中の帽子もあるため、元の定義の写しだけでは現在の描画の姿を表さない。個別資料には服の使い方と手入れ、持ち物と生活の理由を記し、色や形の調整値は参照先を正とする。この参照の検査は衣服の設計完了や描画の承認を示さない。


## 家庭の飲用水の供給案

部屋の `potable_water_supply` は井戸などの source と担当する carrier、配置した容器の記号と ID、一度に入れる上限を結ぶ。status は proposed、pending は未照合の条件を持ち、用水の成立を宣言する用途には使わない。容器の `transport_container.stream` は potable_water とし、排泄物・汚水と処理後の水の経路から分離する。現時点の容器のモデルは蓋付きの施釉した壺で、同じ物を運び保管する。形状・容量・空の重さは容器だけを正とし、供給案へ複写しない。

担当者は同じ家の住民で、同じ町の施設の users に含める。家は施設を facilities へ登録し、使う部屋と担当者が実際に結び付く必要がある。担当者の handling_plan と空の容器を含む仮の荷重を照合し、身体能力・把持・時間と経路の実証とは分ける。供給先の部屋は建物・施設と担当者を設計の前提に含める。

施設の water_collection は potable_supply を目的とする proposed の案で、pending に水質・必要な処理や受渡しと維持の未照合を持つ。汚物の処理施設をこの受渡しへ兼用しない。処理後の水を飲用の水と同一視せず、器を汚水の搬出経路へ流用することも拒否する。供給量と消費の収支、容器の清掃と乾燥中の代替、井戸の回復、手と身体の動作・日課が未照合の間は、部屋と施設の設計ゲートを通さない。


## 井戸の南側の受取り床

water_collection.landing は井戸の全敷地の代わりにせず、受取りと待機・退出に使う床だけを参照元の広場の中心から配置する。origin_m と cell_m、rows と zones が同じ配列と格子を表し、各区画は一人分の capacity_people を持つ。待機から受取り、退出の順に使い、退出する人が次の待機場所を横切らない幅を照合する。待機場所を狭くしたり列を格子の外へ増やしたりして通さない。

床の全範囲を現行の通行格子と井戸の共通の衝突半径へ照合する。四隅だけが空いていても途中の障害物を無視しない。これは井戸口の操作と巻上げ、容器の台と身体、広場全周の往来や家との往復の設計が済んだ意味ではない。既存の通行格子を削って案へ合わせず、描画と日課へ未採用の配置案として残す。


landing.body_review は native_horizontal_bounds の未確認の案で、対象住民と空手を示す item の null、待機・見回し・運搬の全クリップ、各区画の位置と向きを持つ。既存の井戸の描画用の立ち位置を指す native_well_place と、広場からのメートル単位の位置を指す relative_m を区別する。丸めた通行セルの中心を、描画で使う名前付きの立ち位置の代わりにしない。

対象の全区画を一度ずつ割り当て、実際の全描画部材を屋外の縮尺と向きで床へ照合する。根元の点が入るだけで手や衣服の張出しを省かず、クリップを都合のよいものだけへ減らした状態も通さない。これは身体の水平な囲いの検査であり、足裏の接触や壺を持つ手・荷重、時間を含む動作や日課の採用の証明ではない。


## 飲用水の壺の構造と静的な把持

家具の potable_vessel は、同じ transport_container の外形と内側の寸法に底・蓋・つまみと耳取っ手の構造を加える。全高の中へ内側の深さと蓋・つまみを収め、取っ手の根元が水の空洞へ入らないことと、上下の棒が底や蓋に重ならないことを照合する。取っ手を含む全幅も家具の区画へ収める。

potable_water_supply.grip_review は static_native_frames の未確認の案とし、身体に対する壺の位置と両肘の向きを持つ。元の肩と足・骨長を保ち、対象住民の待機・見回し・運搬の全静的フレームを照合する。前腕・掌と袖口の自己干渉、壺の胴と全身、取っ手の各棒の離隔を区別する。

握る縦棒には既存の掌の開口を使い、棒の全体が開口へ入り袖口より前にあることを確認する。手の皮膚を全部消したり、取っ手や腕をまとめて衝突検査から外したりしない。同じ身体と壺を受取り床の全区画へ照合し、空手の結果で持った状態を代用しない。固定した時点の到達と接触は、荷重と握力・強度、上腕の付根、蓋の開閉、持上げと歩行・置くまでの設計の完成を示さない。


## 家庭の壺の支持と持上げの始点

家具の potable_vessel_support は西壁へ固定する棚の寸法と製作者、同じ壺の置く位置を持つ。天板・背板と支えの接続、壁と扉、取っ手を含む壺の収まりを照合する。宙に浮く板や身体を縮めた配置で支持を代用しない。

potable_water_supply.pickup_review は静止した持上げの始点の案であり、本人の室内の位置と操作床、同時に使えない設備、待機と見回しの全フレームを持つ。棚上の壺から握る高さを求め、独立した調整値へ写さない。壺の区画の三次元の棚と全身への離隔を調べてから、周囲の家具と床への収まりを調べる。静的な離隔は壁への固定強度や持上げから歩行までの動作の証明にはしない。


## 壺を棚から離す区間

pickup_review.lift は fixed_native_frames_vertical_lift の未確認の案で、棚上の同じ壺から鉛直に底を離す距離を持つ。身体と足を固定し、壺の向きと壺に対する把持点を変えず、同じ棒へ両手を解く。待機と見回しの各フレームを固定するごとに、速度の上限を用いて中間の全姿勢を囲い、到達と離隔を照合する。

離隔を証明できない大きな区間は分割し、全体が隙間なく通らなければ失敗とする。両端だけが離れていること、固定したフレームでの連続した到達、フレーム間と歩行を接続すること、荷重と握力・時間を区別する。棚へ接する始点の底の接触だけを認め、棚内部への侵入は通さない。


## 壺を持って棚から後退する候補

pickup_review.backstep は sampled_native_backward_steps の未確認の案で、持上げの終点へつなぐ待機のフレーム、身体の後退先、巡回数と先に引く足、足の持上げと腰の下げ幅を持つ。後退先も同じ操作床に含め、真後ろの一直線の経路だけを認める。

同じ壺の底の高さを保って両手を解き、一方の靴を部屋の同じ位置へ残しながらもう一方を引く。巡の境界で姿勢を飛ばさず、最初に接地へ合わせる腰の下げ幅を毎巡足さない。資料の照合は巡ごとに姿勢を標本化し、実際の身体と壺・棚・周囲の家具を検査する。標本間の連続した離隔と支持域・荷重、時間と日課への採用は分けて残す。


## 家庭用水の在庫と不在

potable_water_supply を持つ資料では stock_plan を必須とする。single_vessel_availability の案で、同じ家で水を使う住民、飲用と調理の用途、予備の容器がないことを明示する。全ての利用者は部屋の同居人と一対一に対応し、同じ家と町・設計の前提に登録されていなければならない。未配置の予備の ID を足して不在を解消した扱いにしない。

水量と場所の規則は [[game-system#家庭用水の在庫の設計]]、その家で必要になる補給と手入れは個別の部屋を参照する。運搬の上限を正確なミリリットルへ移せることは、一日の需要や家に水がない時間、水質と乾燥・搬送の設計を完了した証明ではない。


## 取っ手付きの杯と水切りの組

dish_drying.items の cup は中空の胴・底と一つの耳取っ手の寸法を持つ。外形は取っ手を含み、乾燥の支持円は胴の口を使う。非対称な外形の中心へ支持円をずらさず、収納の箱と同時に載る他の器への離隔には全外形を使う。

batches を持つ場合は sequential_empty_between とし、組ごとに全ての物の ID を列挙する。各物は一つの組へ一度だけ属し、省略・重複・未登録の物を許さない。前の組が乾いて収納され、水切りを空にして整えてから次を載せる案である。組がない場合は従来どおり全てを同時に照合する。組の内側の間隔と支持は減らさず、乾燥時間と実際の入替えは別に設計する。

複数の組がある台所を参照する meal_place_settings は source_group で食事の組を指定する。tea_place_settings は杯だけの組を指定し、同じ所有者と席・実物の寸法を照合する。食事と茶は別の卓上配置であり、元の器を全て下げ、天板を清潔にして乾かしてから入れ替える。二つの占有を同時の使用として足し合わせず、入替えの運搬と時間も未確認のまま残す。その組の全てを本人の席へ割り当てる検査を維持し、茶器の追加で食事の器を省略したり、関係のない器まで一度の食事へ強制したりしない。


## 調理炉の鉄板

hearth に cooking_top を持つ場合は、鉄板の厚みと炉の手前からの奥行、左右の石の壁に残す受け幅、製作者と未照合の条件を記す。火室の上端を板の下面へ一致させ、板の体積を同じ石材から除く。上階へ通る煙道の全断面を板で塞がないこと、炉の空洞から煙道へつながることを先に照合する。

同じ定義を設定資料の照合と間取りの出力、室内の縮尺と描画へ渡す。板の形・名目上の受け幅は、加熱と排煙・給気、熱と強度、鍋と取っ手の支持・操作、燃料と灰の日課を確認した証明ではない。


## 湯沸かしの一回分と置き場所

hot_water_service は single_heating_batch の案で、同じ湯沸かしの固有 ID・持ち主と製作者、両手で運ぶ担当者、既存の調理炉と飲用水の壺、杯への一回分の割当を結ぶ。日ごとの必要量を持つ計画とは区別する。容量は片口が変形し始める高さより下の空洞から求め、空の重さと水を担当者の仮の運搬上限へ照合する。

bail_forward_m は本体中心から片口側へ寄せる架け柄の距離で、木の握りと支柱・鉄の芯へ同じ値を使う。現行の中心位置は変えず、ずらした試案も全外形と身体へ照合できるようにする。

pot は平底の中空の胴、上の縁から開く片口、固定した架け柄と木の握り、取り外す蓋の寸法を持つ。heating と rest の位置は炉の北西からの本体中心の位置であり、取っ手を含む全外形の北西ではない。片口を西へ向け、底の高さは同じ炉の上面から求める。rest は先に外した蓋、後に蓋を戻した器が順に使い、両方が別々に同時に載る扱いにはしない。

固定した架け柄がある器は伏せて口で支えず、火が落ちて冷えた炉で口を上にして蓋と分けて乾かす案とする。乾燥中は炉を他の加熱に使わない。収納は取っ手と蓋を含めて箱の内寸へ照合し、cold_clean_dry_empty_closed の条件を要する。水量の割当は加熱や配膳の完了ではなく、乾燥・熱と強度、取っ手と蓋を扱う身体、洗浄水と日課への接続は別に照合する。

## 杯へ湯を受ける作業面

[[room-h1-2#杯へ湯を受ける台]] の serving は、既存の杯への割当と同じ ID を過不足なく使う。台の work_surface と杯の中空・取っ手の実寸から、端からの余白と杯どうしの離隔を照合する。position_m は台の北西隅から杯全体の北西隅までを表し、取っ手の向きは固定する。切る作業を片付けて台を清潔にする条件は、配置の成功から満たした扱いにしない。熱い器は石と鉄板の炉へ戻し、木の台へ直置きしない。

## 注湯前の静止姿勢

[[room-h1-2#片口を杯の上へ向ける姿勢]] の pose_review は、杯の口の上へ片口を合わせた静止姿勢だけを扱う。台と杯の胴中心から位置を求め、片口・胴・固定した架け柄・握りを同じ回転で動かす。蓋はこの形から除き、炉の別置き域へ残す。器全体を全ての杯の口より上へ保つという条件で、台と杯への干渉を避ける。この照合を水の落下や身体の動作・温度の承認に使わない。

## 注湯姿勢の静止骨格

[[room-h1-2#注湯姿勢の両手と立つ場所]] の reach_review は同じ住民の実際の外見定義と待機・見回しの骨格を使う。body_from_lip_m は杯の開口の中心から台の東西・南北の軸で表す足元の位置であり、家具をまたぐ経路ではない。木の握りの中央から両側へ分けた位置へ、肩と足と骨長を保ったまま両手を解く。左右の対応は人物の左手が正の横軸を持つ既存の骨格に合わせる。

台と杯は配置した実寸を使い、身体の全ての部分へ照合する。腕が台の格子と重なることは許すが、その場合も天板と四本の脚への三次元の離隔を免除しない。ほかの家具と壁を空き床として扱わず、前腕と反対側の腕・身体との自己干渉も調べる。掌の開口と袖口の平面は [[room-h1-2#木の握りと掌・袖口の接触]] へ結び、指ごとの把持、静止時の器全体と身体は [[room-h1-2#湯沸かし全体と身体の離隔]] へ結び、上腕の付け根、熱と力・釣合い・移動中は別に残す。

## 丸い握りと掌の接触

[[room-h1-2#木の握りと掌・袖口の接触]] の contact_review は、同じ木の握り全体と各掌の軸・断面を持つ。握りに沿う開口は既存の掌の芯へ収め、手首より後ろの腕と袖口は変えない。棒の全体を掌の開口へ含めた上で、手首の平面との離隔を照合する。短い握りへ切って証明したり、掌を大きくして通したりしない。これを指ごとの把持や力・熱・器全体と身体の干渉の確認と区別する。

## 湯沸かしの全体と身体

[[room-h1-2#湯沸かし全体と身体の離隔]] の body_review は、胴と片口の全体を包む囲いと、全ての架け柄の棒を同じ native figure の座標へ渡す。棒は根元と支柱、通しの鉄の横棒、木の握りを区別する。接触の例外は掌へ全長を照合した木とその芯の鉄だけで、上腕の囲いと他の身体は別に避ける。ほかの棒は両腕も除外せず、全ての身体へ照合する。形が広がった場合は、同じ外形で炉への支持・別置きと収納を再照合する。

## 直立から傾ける未成立案

[[room-h1-2#直立から傾ける途中の未成立案]] の tilt_candidate は、同じ器を握りの位置から回す候補と未成立の条件を持つ。終点の静止姿勢が成立しても途中を採用せず、同じ身体・掌・架け柄・台と杯の検査で拒む。正常な配置と試案の失敗は分けて保持し、未成立の候補を描画照合済みや日課へ移さない。

## 足元を固定した前傾の候補

[[room-h1-2#足を保った上体の前傾案]] の upper_body は骨盤から上の鎖を回し、足元と元の骨長を保持する。前傾を戻す区間は終点より前へ置き、終点で元の姿勢と一致させる。衣服と頭も同じ変換を持つ。手の接触を解く前に適用し、後から肩を動かして既存の掌の開口を壊さない。未成立の全身の干渉と荷重は、前傾の描画の成功から推測しない。

## 寝台の骨組みとマットレスの出所

sleeping_materials は単独の寝台と整えた寝具の案であり、常用寝台の固有 ID へ結ぶ。枠・脚・床板・頭板とマットレスの実寸は furniture の bed と同じ格子の占有を正とする。材料の供給は木工師と木こり、織手と仕立て手、羊毛の供給元を住民 ID で分け、同じ町の役割と design_dependencies を照合する。寝台の所有者は常用寝床の割当と本人の逆参照に一致させる。

[[room-h1-3#寝台の骨組みとマットレス]] と [[room-h1-4#寝台の骨組みとマットレス]] の寸法と出所は各私室に持つ。枕と掛布は [[room-h1-3#整えた寝台の枕と掛布]] と [[room-h1-4#整えた寝台の枕と掛布]] の静止した配列へ結ぶ。この検査は替えの寝具、収納量・手入れや睡眠の動作・夜の移動を含まず、資料の設計状態を通過へ変えない。資料の use が「寝」の場合は描画の「寝間」へ明示して対応させ、未知の用途を通常の部屋へ置き換えない。

## 整えた寝具の配列と頭側の座標

bed の linen は枕と掛布の固有 ID、種類、position_m と幅・長さ・厚みの配列を持つ。ID は常用寝台 ID と種類をコロンで結び、本人の物へ結び付ける。位置は枠を除いたマットレスの頭側の左隅を基準とし、横方向と足側への距離を表す。頭板の向きを変えると寝具も同じ座標基準で回す。

静止した整えた形は枕と掛布を各一つ持ち、枕を頭側、掛布を足側へ重ねずに載せる。全体がマットレスの上に収まり、枠や頭板へはみ出さないことを照合する。寝具の実寸も室内の縮尺へ一度だけ変換する。既存の未設計の寝具は null とし、寸法を黙って補完しない。畳み・身体を入れた形と手入れの動作は別に設計する。

## 個人の衣服箱の閉じた収まり

personal_storage の packing は、実際の家具の占有から得た外寸と、箱の板・蓋を除いた内寸へ持ち物を配置する案である。内側の北西の底を原点とし、横・高さ・奥行の順に記録する。衣服、首巻き、私物は本人の収納 ID に種類を結んだ固有 ID とし、別の人の物を同じ包みとして使い回さない。全て底で直接支持し、重なりとはみ出し・間隔不足を拒む。量だけが収まっても、物の形と配置が通らなければ収納可能とはしない。

対象の箱と持ち主・町の作り手と木材の供給を対応させる。寸法を持たない既存の収納を補完せず、蓋の可動、物を出す姿勢、追加の寝具、衣服の仕立てと洗濯は別に設計する。具体的な二人の案は [[room-h1-3#衣服箱の内寸と持ち物]] と [[room-h1-4#衣服箱の内寸と持ち物]] にある。

## 衣服箱から外す蓋の平行移動

個人の衣服箱に opening を持つ場合、真上へ持ち上げ、水平に運び、室内の指定した床か専用の支持面へ置く。蓋だけを移し、底・側板と中身は箱に残す。rest_center_m は室内の北西を基準とする板の中心と下面の高さであり、収納する包みの内側の座標とは区別する。戻す経路も同じ板の逆向きの移動とする。

経路は端の状態だけでなく全区間で箱・中身・壁・他の家具と照合する。rest_support を持つ案は実在する本人の蓋専用の台へ結び、天板全体で板を受け、天板と脚を障害物へ含める。台が無い高さ指定や天板からのはみ出しは通さない。階の水平な天井と未確定の家具を保守的に障害物へ含める検査であり、梁・屋根や手と身体の未設計を補完しない。二人の固有の経路と残る使用条件は [[room-h1-3#衣服箱の蓋の経路]] と [[room-h1-4#衣服箱の蓋の経路]] にある。

蓋の reach_review は本人の体格を用いる未解決の静止候補であり、operator はその収納の持ち主へ一致させる。膝と靴の接地を持つ低い姿勢で端へ届いても、端の間を運べること、掌の接触と力、杖や立上がりの成立とは区別する。床の板へ手が届かない案は、板だけの経路の成功で採用せず再設計する。

床の板を拾い直せない旧案に対し、[[room-h1-3#衣服箱の蓋を受ける低い台]] と [[room-h1-4#衣服箱の蓋を受ける低い台]] は箱の南側の台へ同じ蓋を置く案とする。台は本人の使用面を持ち、箱の収納量とは分ける。台上の静止した到達と連続した運搬・把持の成立は区別する。

## 衣服箱の蓋に属する取っ手

lid_handle は本人の箱へ結ぶ固有 ID と、横棒・支柱の寸法、横棒の向き、板の中心からの位置を持つ。位置は横棒の向きとその奥行の座標であり、室内の北西からの位置とは分ける。取っ手全体を板で支え、箱の総高は取っ手を含む。取っ手の高さを内部の容量に含めず、底・側板と蓋の板の寸法を維持する。

reach_review.target が lid_handle の場合は、同じ移動・描画部品の横棒の二点へ届く姿勢を求める。取っ手が無いのに高さだけを足した目標へ置き換えない。縁を使う旧案の否定例を保持し、掌の接触と動く蓋・取っ手からの離隔は別に照合する。個別の案は [[room-h1-3#蓋の西側の木の取っ手]] と [[room-h1-4#蓋の西側の木の取っ手]] にある。

## 宣言された横棒の静止した掌の接触

grip_review は同じ人物の骨長と接地を保つ静止した案であり、横棒に垂直な前腕と曲げる側を持つ。横棒は描画する実際の断面全体を囲み、掌と手首の面に収まることを証明する。証明のある横棒の接触だけを扱い、上腕と他の部位、板・支柱や固定家具へ検査の例外を広げない。

各静止した候補は戸の実際の位置と本人の全身・選んだ腕の自己離隔を求める。位置を置き直した点の間で靴が固定されたことや、反対の手で杖を使えることを推定しない。本人ごとの残件は [[room-h1-3#立った本人が片手を近づける静止した候補]] と [[room-h1-4#立った本人が片手を近づける静止した候補]] にある。
