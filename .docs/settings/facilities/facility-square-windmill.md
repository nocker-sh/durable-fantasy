# 農家の製粉用風車

## 仕事と所有

[[building-farmhouse]] の農家が扱う麦を粉にする設備の案である。[[resident-カール]] の既存の世帯の仕事にある製粉をこの資料へ結ぶ。風車だけで町の全需要を賄えるとは決めず、他の仕事を止めずに扱える量と時間を設計する。

## 現行の外観と稼働する設備の区別

runtime_reference が指す現在の描画には塔と戸、回る羽根がある。内部の挽き臼・伝動・原料と粉の収納、操作者の足場、停止と固定の機構は定義されていない。描画の回転は風や麦の量、操作者に結び付いていないため、製粉した量や動作の証明にはしない。

site は稼働する設備の設計上の敷地を未割当のまま示す。外観の位置にそのまま製粉室を足さず、羽根の掃く全域・接地と地形・境界、歩く人と運ぶ容器、農地と隣の設備を照合してから確定する。現行の外観を新しい平面とグリッドから作った結果として扱わない。

## 麦を受けて粉を渡す順序

operation_plan は、受入れ、異物の除去、製粉、粉とふすまの分離、受渡しを順に持つ。原料の受入れと完成した粉の容器を兼用せず、灰を避ける覆いを受入れから受渡しまで保つ。停止を宣言しただけで羽根と伝動が固定された扱いにしない。実際の停止・固定と再始動、詰まりの解消、手入れの操作は機構と身体の設計へ渡す。

粉は [[room-bakery-2]] へ渡し、そこで生地を整えて [[facility-bakery-oven]] へ進む。パン屋の家と農家の両方へ同じ粉を二重に割り当てない。ふすまを無条件に家畜の餌へ消したり、異物を畑へ捨てたりせず、それぞれの行き先と受取る担当を決める。現行のアイテム定義に製粉用の麦・粉・ふすまの在庫と加工がない間は、資料の流れを実在の数量として数えない。

## 平面と一日の設計

操作者の立つ面、挽き臼と回転する伝動、袋の持上げ、受入れと出荷、清掃と廃物の一時保管を分けた配列とグリッドを先に作る。作業場の格子は下節の未配置の予約案とし、製粉室の内部の設計とは分ける。塔の中に収まりそうな空図で内部を設計済みにしない。粉塵・換気と湿気、火と灯り、清掃の水を食品から分け、蓋と囲いを扱う身体と機構を同じ図へ照合する。

畑と家畜の世話、家の仕事と夜市を残して製粉と運搬を割り当て、パン屋が受け取れる時刻へつなぐ。予定の名前だけを製粉へ変更したり、必要量が毎朝増える在庫で不足を埋めたりしない。敷地と一巡する供給・作業が成立するまでは、都市のパンの供給も設計ゲートを通過させない。


## 機械域と受渡しを分ける作業場の平面案

windmill_yard は描画へまだ採用していない局所の作業場である。北の囲いの内側に T として塔・機構の予約を持ち、南側へ麦の R、完成した粉の F、受渡し台 B を分ける。南端の D は搬入出の開口、囲いの南面の D は機械域へ入る門の開口であり、開いた状態の平面の到達性を読む。# は境界を残す予約であり、壁・柵・屋根をこの文字だけで描画へ決めない。

R と F の容器は蓋を持つ別の組とし、麦と粉を同じ箱で入れ替えない。作業面とその使用面も機械の予約域へ入れず、受渡しは原料と完成品を同時に開けない順序とする。台と容器を覆う屋根の支持と高さ、箱の内寸・蓋と手入れ、運ぶ人と荷物の立体は未設計であり、覆いの宣言を防塵と乾燥の保証へ広げない。

機械域の門へ入る条件は羽根の停止、伝動の隔離、回転体の固定の三つを全て満たすこととする。現在は機構も確認する人の動作も未設計のため、条件が true と記載されていても実際に確認済みとはしない。囲いの全周と単一の連続した南の開口、作業場と機械域の平面の分離だけを検査する。羽根の実際の掃引域を囲いが包むことや、閉じた門の保持・操作を検証した扱いにしない。

## 現行の羽根の全回転を囲う平面の照合

羽根の寸法は `world/scene/construction/windmill-rotor-shape.ts` を描画と検査で共用する。梁の厚みと布の面の張出しを含め、それぞれの矩形の最も遠い角から全回転の囲いを求める。止まった一方向や粗い角度の標本だけで羽根を囲ったことにしない。

回転中心は T の予約の中心へ結び、共通の町のメートル換算を使う。rotor_review の余白も含む床への投影を囲いの内側へ収め、境界セルを羽根と兼用しない。前の幅ではこの条件が不足したため、作業場の予約を拡幅した。

これは平らな仮の地面と現行の羽根についての囲いである。敷地の境界や地形、塔・内部と軸受け、風と回転速度・停止固定、門と屋根・人と荷物の立体、素材の強度を保証しない。現行の外観の配置をこの予約の設計済みの敷地として採用せず、内部と日課の未解決点を残す。


## 麦畑の一部を使う未採用の敷地候補

windmill_yard_site は、北東の麦畑の一部を作業場へ回す位置の候補を持つ。格子の実寸と共通のメートル換算・回転から敷地の全域を求め、建物と屋根・他の設備、道と川の幅、町の境界へ照合する。現行の外観の原点をそのまま流用せず、この候補を現在の風車の位置や歩行格子へ採用しない。

field_index が指す現行の畑だけを分割し、使う部分と残る全ての矩形を `get-windmill-field-partition.ts` で求める。面積はここへ数値を写さず、コードが共通の縮尺から求める。残る農地と同じ敷地の予約をほかの建物と住民の経路の検査にも渡し、同じ畑を別の案へ二重に割り当てない。ほかの畑や保護する土地は除外しない。

この候補では麦畑が減る。減った面積だけで収量を推定せず、既存の世帯の食事とパン屋の需要、収穫と加工・保管、代わりの生産を照合する。作業場が平面に収まっても、農家の収入や食料を維持したことにしない。

南の搬入出の開口から既存の道への平面の接続案は次節にある。荷物を持つ身体と往復、地形と既存の岩・植生、塔と屋根の据付けは未設計である。crop_supply_status と terrain_status、native_obstacles_status は unreviewed を保ち、製粉が稼働する設備として描画や日課へ採用しない。


## 南の搬入口と既存の農道の接続案

windmill_yard_site.approach は南の二セルの開口を実寸で投影し、農道の元の終端まで南へ進んでから西へ折れる接続路を持つ。幅は開口と道路の幅を超えず、曲がる場所にも同じ幅の正方形の予約を含む。road_index と road_end_tiles は既存の道の取り違えと端の変更を検出するための照合値である。始点と曲がる点は開口・終端から検査コードが求め、本文に別の座標を写さない。

元の敷地だけでは、開口の南に残した麦畑を通らないと道へ出られない。接続路の全幅も同じ畑から差し引き、敷地との重複を二重に数えず、残る全ての農地と除く面積を求める。敷地と接続路は他の建物・設備・農地と経路からも見える予約として登録する。他の道と水の幅は保ち、接続する道へ入る最後の区間だけ、その道との合流を認める。

これは幅を持つ平面の案であり、実際の舗装や地盤・排水、岩・植生、荷物と人の高さ・姿勢・転回、通行中の受渡しと日課は未照合である。接続路で追加で減る麦も収量と供給の残件へ含め、格子や日課・描画へ採用しない。

## 配置案の地形の測定

`bun scripts/check-settings.ts --terrain-report` は、敷地と接続路の各区間の全幅について、道路の配置案を反映した検査用の補間済み地形の最低・最高の標高と高低差を出力する。四隅だけを読むのではなく、領域内の格子境界と切られた端を含めて求める。測定値はコードから出力し、この資料へ転記しない。地形の保持範囲を外れる領域は、端へ丸めず拒否する。

この出力は道路の配置案を反映した検査用地形の形状だけを示す。実行時の元の道と同じ地形を測った結果とはしない。地盤の支持、造成と排水、舗装、斜面の通行と荷物の保持、岩・植生の占有は含まない。平面の接続路と標高の範囲が求まっても terrain_status を変更せず、据付けと歩行面の断面を設計する入力として扱う。


## 作業場から道へ下る中心線の断面案

接続路の section は、作業場と曲がり角を同じ高さの予約とし、曲がり角から道の中心へ下る二つの区間を持つ。作業場の予約は検査用地形の最高点より上に置き、第一の区間は受渡しから曲がり角まで高さを変えない予約とする。荷物を置く面と待機・転回する身体は別に照合する。道側の標高は資料へ写さず、同じ配置案の地形から接続先の中心を読む。最大勾配はこの案の比較条件であり、荷物を持つ身体が通行できる認定ではない。

`get-windmill-approach-section.ts` が中心線の標高と各区間の長さ・高低差・勾配を求める。地形や道の案が変われば再計算し、比較条件を超えた案を通過させない。これは造成前の標高の予約である。全幅の横断勾配と道への継目・段差、曲がり角の足元、地盤・締固めと舗装の断面、雨水の流路と排出先、荷物と人の連続した動作は pending に残す。羽根の囲いの局所の仮の地面を、この絶対標高へ自動的に採用した扱いにしない。


## 道との継目の全幅の測定

中心線の終端の標高を道へ合わせても、幅の両端とその間の地形までは同じ高さにならない。`get-windmill-road-seam.ts` は最後の区間に直交する全幅の線について、格子境界と切られた端を含む地形の標高範囲を求める。中心線と同じ平らな面を置くときに削る側と埋める側の最大の高さの差を出力し、中央の一致を全幅の段差なしへ読み替えない。

切土と盛土の出力は高さの差であり、土量でも工事済みの地形でもない。道を変えず接続路の横断面をなじませるか、道も含めた整地の範囲と傾きを計画する必要がある。現段階ではどちらの施工面も採用せず、道路と残る農地を勝手に削らない。全幅の継目と横断勾配・足元、支持と排水は断面案の pending に残す。


## 道路を変えず横断形状へなじませる施工面の案

section.surface は、水平な曲がり角の西端から道路の継目へ、道路の現在の横断形状へ徐々になじませる未採用の施工面を持つ。曲がり角の中心から始めると最初の区間の全幅の予約と異なる高さで重なるため、最初の区間が占める西端までは水平を保つ。継目では幅の各位置で道の地形と同じ標高を使い、その西の予約の端は元の道路面を保つ。道路や農地の描画・通行判定は変更しない。

施工面の標高は `get-windmill-approach-surface-height.ts` が求める。継目の全幅の地形の最高・最低の標高から、水平な曲がり角と継目の間の最大の縦断勾配を求め、中心線と同じ比較条件へ照合する。これは道路側の境界と曲がり角で高さを連続させる案である。横断勾配・実際の身体と荷物、路肩と地盤の支持、切土・盛土の全域と土量、排水と施工・維持は未設計のまま残す。前節の平らな継目の差は未整地の比較値として保持し、これを施工後の段差と混同しない。


断面の出力の anchors は作業場・曲がり角・道路の三つの高さの支点、anchor_segments はその支点を直線で結んだ比較値である。施工面そのものの断面とは区別する。surface がある場合は曲がり角の西端まで水平を延ばすため、実際になじませる長さと全幅の最大勾配は surface を使い、支点間の直線の長さで代用しない。
