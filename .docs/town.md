# 町の地区と店

前提は [[README#完全な生活]]。都市と人の名前の付け方、気候は [[world]]。

最初の都市ファンティエット（id の頭に `phanthiet`）は、広場を真ん中に、商店通り・職人通り・南門の 4 つのマップに分かれている。どの地区も 1 マップ = 1 Durable Object（[[game-system#1. 世界とマップ]]）。地区どうしのつながりは「世界の升目」で決まる。

## 地区

広場は町の真ん中で、井戸と市場の屋台、鍛冶場、パン屋、宿、礼拝堂、川と洗い場、畑と牧場、風車がある。商店通りは石畳の通りと小さな井戸の広場に、酒場・薬屋・道具屋・仕立て屋・結晶屋・買取所が並ぶ。職人通りは工房の並ぶ通りで、共同の作業場と、裏庭の共同の炉がある。南門には城壁と門、門番の詰所、町の倉庫がある。

## 店

店の店主・品揃え・買取の倍率は `world/core/shops.ts`、アイテムは `world/core/items/catalog.ts`。結晶は結晶屋でしか買えない（[[economy#0. 原則]]）。買取所は売り物を持たず、素材を高めに買う。

## 世帯と建物

住民はみな、どこかの世帯に属する。世帯には住まいが一つあり、住人の数だけ寝床がある。年中寒い町なので、人の住む建物にはどれも暖炉があり、煙突から煙が出る。職業に要るもの（パン窯・炉と金床・調合台・機織り機・なめし場など）は、その家の作業場か裏庭にある。

建物の外見（間口・階数）は間取りから作る。階数は部屋のある階の数である。

入れるのは店と公共の建物（宿・酒場・寄り合い所・倉庫・共同の作業場）だけ（`houses.ts` の `enterable`）。民家と仕事場（鍛冶場・窯場・醸造所）には入れない。民家の扉は開かず、夜は窓に灯りがともり、住人は家に入ると姿が見えなくなる。

空き家は、いずれ借りられるように貸家として残しておく。

暮らしの出どころは、食料が町の農家・漁・羊飼い・猟師と市場、燃料が木こりの薪と炭（炭焼き窯は樹海の入り口）、水が各地区の井戸である。

どの家も、間取りの家具を実寸で並べて通路が取れ、住む人数に比べて広すぎないことを確かめる（`world/town/fit.ts`、`fit.test.ts`）。

世帯と建物の一覧は `world/town/houses.ts`、間取りは `world/town/floorplan/floor-plan.ts`。

## 家の見た目

同じ家を並べない。どの家の見た目も、住む世帯の仕事と暮らし向きから決める（`world/town/style.ts`）。乱数の種は、そのなかでの選び方を変えるだけ。

壁の材は仕事で決まるものがある。火の粉を使う仕事、金目の物を置く店と倉庫、酒蔵を冷やす酒場は石積みにし、木を扱う仕事と農家・羊飼いは板張りにする。それ以外は暮らし向きで決め、ゆとりのある家ほど木組みや石積み、慎ましい家ほど漆喰や板張りになる。窓と扉も暮らし向きと建物の用途で変わる。煙突は暖炉と仕事の火の数だけ付き、炉のない納屋や小屋には付かない。

隣り合う家は、屋根の形・壁・屋根の色・窓の組み合わせが必ず違う（`style.test.ts`）。小物も同じ物を並べず、樽・木箱・柵は置き場所ごとに形と傷み方が違う。

二階建ての家の多くは、正面の扉と反対の側の二階に張り出し窓を持つ。張り出し窓は自分の腕木と小さな屋根を持つ。空き家でない家のおよそ半分は、横か裏の壁に下屋を差し掛け、その下に薪か樽を置く。下屋は、空いた地面で、道から離れ、どの扉からも離れた壁にだけ付ける（`world/scene/build.ts`）。張り出し窓と下屋のあるなしと、下屋の下が薪か樽かは、今は家の種で決まる。

## 屋内マップ

全建物の各階を昼夜で撮るスクリプトは `scripts/shoot-building-floors.ts`。開発サーバーを起動して実行すると、民家と仕事場も含めた建物詳細の3D表示を `public/tmp/interiors/` に保存する。`manifest.json` で建物・階・昼夜と画像を対応させる。生成画像は Git に含めない。入場可能な室内を実際のゲーム画面から撮る従来のスクリプトは `scripts/shoot-interiors.ts` に残す。

入れる建物は、それぞれが一つのマップで、サーバーでは一つの部屋 = 1 DO になる。マップ id は `phanthiet-in-<建物 id>`。通りの扉の前の青い輪を踏むと中へ入り、部屋の扉を踏むと外の扉の前（一歩外）へ出る。

部屋の大きさ・扉・カウンター・店主の立ち位置・家具は、建物の定義と間取りから決まる（`world/town/interiors.ts`）。サーバーの歩ける格子と画面の部屋は同じ定義から作るので、ずれない。室内は実寸より広く描く（[[decisions#2026-10-25 室内は実寸の 1.5 倍]]）。

従来の自動間取りの汎用家具は名前ごとに形を描き分け（`world/scene/construction/furnishings.ts`）、もたれている壁から部屋の内側を向けて置く。資料から採用した配置と実寸指定、専用種別の道具は、それぞれの形状と支持面を優先する（[[decisions#家具の名前より実寸と専用の形を優先する]]）。木は世帯の暮らし向きで決まり、慎ましい家は松、ふつうの家は樫か白樺、ゆとりのある家と公共の建物は胡桃・黒樫・樫になる。塗りの文化のある家（建物の seed で決まる）は、衣装箱・長椅子・揺りかごを青・赤・緑に塗る。同じ家具の一覧は /dev のオブジェクトで見られる。

室内は家具だけでなく、暮らしの跡で埋める（`world/scene/interior.ts` の `dress`、`world/scene/construction/belongings.ts`）。1 階の各部屋の奥と左右の壁に掛け場所を割り、間取りの壁掛けの品（干し網、吊るした革、斧掛けなど）を先に、残りに部屋の使い道に合った物（台所なら鍋とひしゃく、作業場なら道具、売り場なら値札の板）を掛ける。窓の前と背の高い家具の前には掛けない。台所・貯蔵・作業場・住まいの梁からは薬草や玉ねぎの束を吊るし、食卓の下と炉の前には敷物を敷く。床の暮らしの跡（脱いだ靴、繕いかけの服、遊び道具など）は平らな板ではなく物の形で描く。店の開いた棚は 1.2 マスほどの区画に分け、店の品（パン屋はパン、薬屋と結晶屋は壺、酒場と宿は瓶、道具屋は壺・袋・縄・蝋燭）を、下の段ほど多く、上の段は売れて空いた所を残して並べる。

店主はカウンターの奥に立つ。ただし店先でも売る店は、売り子が外に残る（パン屋の店先の売り台など）。鍛冶場は庭に開いた作業場なので、中には入らない。

画面では、カメラ側の壁を腰の高さまで切り下げて、部屋の中が見えるようにする。カメラを回すと切る壁も替わる。切り下げた壁の窓と枠は隠し、壁が戻ってから表示する。窓だけを部屋の途中へ残さない。暖炉と吊りランプが灯り、窓は外の明るさで少し光る。

店内での飲食は後回しにする（[[economy#4.5 食事]]）。

テスト（`interiors.test.ts`）では、扉は両側とも歩ける場所にあり着いた場所が扉に重ならないこと、扉から店主に話しかけられる距離まで歩けること、店主が通りに残っていないことを確かめる。

入れる建物の室内の絵は、開発サーバーを動かして `bun scripts/shoot-interiors.ts` で撮る（既定の置き場は ~/Pictures/durable-fantasy-houses/）。

## 軒先と路地

家の周りの物は、手で置かず、世帯の定義から決める（`world/scene/dressing.ts`）。暖炉の薪の山・水桶・植木鉢は暮らし向きと家族から、網干し・薪割り台・革干し・粉袋などは仕事から決まる。灰の始末の道具・蓋をした桶・籠・梯子・荷車のような暮らしの小物は、世帯ごとに持つ物の表がある（`world/scene/props/catalog.ts` の `THINGS_BY_HOUSEHOLD`）。灰が降るため、屋外に物干しは置かない。洗濯を仕事にする住民は、洗い終えたものを帰宅して室内に干してから、夕餉や夜市の支度に移る。日課は `world/town/routines.ts`、室内干しの台詞は各世帯の台詞定義にある。洗濯を仕事にする世帯の家は、土間の壁沿いに縄と洗濯物を描く。配置は `world/town/interiors.ts`、描画は `world/scene/construction/indoor-laundry.ts` にあり、通路を塞がず、縄と布を一つの静止した面にまとめる。住む人のいる家は、裏の地面が空いていれば低い柵で裏庭を囲い、一か所を出入りの切れ目にする。裏庭か家の横には、その世帯が自分で食べる野菜の畝を一つ置く。扉が道から離れている家は、扉から一番近い道まで踏み石を敷く。店の家は、扉の上に業種ごとの色の縞の日よけを張り、扉の横に鉄の腕で業種名の看板を道に沿う向きに吊る。売り物を描ける店（酒場・宿・薬屋・パン屋）は、営業中だけ扉の横の長椅子に売り物を並べる。並べるのはその店が売っている物に限る。柵は道・扉の前・住民の立ち位置・ほかの家の扉にかからない深さにし、かかるなら置かない。空き家には「貸家」の札だけを立て、煙突から煙は出ない。どの家も、扉の前と、扉からまっすぐ二タイル分は空けておく。住民の立ち位置にも物を置かない。

テスト（`things.test.ts`）では、どの世帯にも自分の軒先の物があり、どの種類の物も誰かが持っていることを確かめる。

商店通りの北の並びの裏に路地があり、醸造所へ返す空き瓶の箱や、蓋をした雨水の樽がある。洗濯物は屋内へ運び、路地では干さない。

物の一覧は /dev/objects（3D のプレビュー）。

## 道

道はまっすぐに引かない。地形と暮らしに沿って曲げ、幅を揺らし、縁を崩す。道の真ん中には物を置かない（広場の井戸とベンチ、建物の中は除く）。マップの渡り口は描かれた道の上に置く。どの道も地図のほかの部分から歩いて行け、扉・渡り口・採集場所・住民の立ち位置には道から届く（`world/maps/paths.test.ts`）。町の地面には、人の住む家の扉から一番近い道まで、踏まれて土の出た跡を描く（`world/maps/layouts.ts` が家の表から足す。描くだけで、歩ける場所は変えない）。草地は広い範囲で乾いた草と青い草がまだらになり、日陰のくぼみには霜が残る。

## 暮らしの時間

住民一人ひとりに一日の予定がある（`world/town/routines.ts`）。予定は「何時から、どこで、何をしているか」の並びで、その時間帯はその場所に立っている。家にいる時間は姿が見えない。予定は世帯と仕事から決まり、乱数を使わないので、同じ時刻なら全員に同じ住民が同じ場所に見える。

町の大半は夜型で、日が落ちるころに起きて夜通し働き、朝に帰って眠る。昼は短く暗い世界なので、灯りの下で暮らすのが普通だからである。昼の通りは夜より人が少なく、昼は町の過半数が眠っている。昼に働く少数派には、それぞれ生業からの理由がある。日の光が要る仕事（畑・家畜・羊・洗濯・木を伐る・猟）、夜明け前の漁、朝の焼き上がり、昼番の衛兵がそれにあたる。

店は、店番がカウンターにいる間だけ開いている。サーバーも、その時刻に店番がいなければ売り買いを断る。それでも、いつ来てもどこかは開いているようにする。交代制の店は時間帯で店番が替わり、店の手伝いは二人目の店番としてカウンターに立つ。店の扉の脇の札は、店番がいる間は「営業中」、いない間は「準備中」になる。屋台は、売り手がいる間だけ品を並べ、いない間は布をかけておくか、屋台ごと片付ける。

酒場の席は、同じ時刻に飲む人の数より多い。

ここに書いた時刻の決まりは `routines.test.ts` で確かめる。一覧は /dev/npcs（一人ずつの一日）。

## 人柄と台詞

頼まれごとの台詞は、その日の引き受け状況と持ち物に合わせて選ぶ。材料が揃った状態と受け渡し完了は区別し、受け渡す前に完了のお礼を言わない。配達は頼んだ人と受け取る人だけが話題にし、期限を過ぎた頼まれごとの台詞は出さない。条件の判定は `world/town/lines/fit.ts`、進み具合の判定は `world/core/errand-progress.ts` にある。

住民それぞれの性格（数語）・話し方・口癖と、住民どうしの関係（家族・友人・仕事仲間・師弟・幼なじみ・距離のある関係など）は `world/town/people.ts` にある。悪人はいない。テスト（`people.test.ts`）では、関係が実在する住民どうしで一組につき一度だけ書かれていること、家族は同じ世帯に住み親子と祖父母と孫の年齢が合うこと、何人かの世帯の全員が家族か何かの関係でつながっていること、誰にも誰かがいること、家族と友人と幼なじみが一日のどこかで顔を合わせること（わざと離れている組を除く）を確かめる。

台詞は地区ごとのファイル（`world/town/lines/` の `square.ts`・`market.ts`・`craft.ts`・`gate.ts`）に、住民ごとに書く。一行ごとに、合う時間帯・していること・近くにいる人・親しさ・その日の出来事（`world/town/event-of.ts`）・初めて話すときか、を条件に持てる。条件を多く満たす行ほど先に言う（`world/town/lines/fit.ts`）。テスト（`lines.test.ts`）では、誰にも十分な数の台詞があること、同じ行が二度出ないこと、世界観に合わない言葉を使わないこと、近くにいる人の条件は関係のある相手だけで、していることの条件はその人の一日にあることだけであること、時間帯の条件は起きている時間であること、「おはよう」は起きたばかりの時間帯に言うことを確かめる。

/dev/npcs で一人ずつの人柄・一日・台詞を、/dev/lines で台詞を条件ごとに見られる。

## 都市と旅の道

都市はファンティエット・クイニョン・フエの 3 つ（[[world#場所]]）。クイニョンとフエは、まだ門の前まで。門は閉じていて「この先は工事中」の札が立つ。外のマップの並びは「世界の升目」、どこまで行けるかは [[game-system#1. 世界とマップ]]。町から実装済みの屋外マップと両都市の門前まで往復できることを `world/maps/maps.test.ts` で確認する。 内部の未配置の区画案は [[town-hue#未配置の区画案]] と [[town-quynhon#未配置の区画案]] にあり、門が開いた実装や成立した生活として扱わない。

外のマップは、町の暮らしの出どころと、大戦の跡を置く場所である。南の草原にはオットーの果樹園とぶどう畑（ぶどうは醸造所へ）があり、スライムと野うさぎがいる。浜の網小屋はヤコブの海の漁の場所、樹海の入り口はヨーゼフの炭焼き場で町の炭と原木の出どころ、樹海の奥は宿のきのこの出どころ。赤い砂丘・樹海の奥・海沿いの崖道には、半分埋もれた機関、苔むした砦、崩れた見張り塔のような大戦の跡がある。峠道には誰もいない祭壇がある。

木・岩・枯れ草・切り株・きのこはインスタンス描画にして、マップあたり数十の描画呼び出しに収める。どのマップも 60fps を保つ。

## 世界の升目

世界は升目（`world/maps/grid.ts` の `WORLD`、北が上）で、外のマップは一つが一マスで、大きさはどれも同じ。町は 4 マスにまたがる。まだ作っていない都市もマスを持ち、地図には描くが入れない。

隣り合うマップは、向かい合う辺でつながる。西の端から出ると西隣の東の端に出て、端に沿った位置は同じ。つなぎ目（地面の光の輪）は辺ごとに一つで、両方のマップで歩ける所のうち、描いた道（`world/maps/ground-layouts.ts` の `roads`）がその辺に出る所に近い所に自動で決まる（`world/maps/index.ts`）。通れない辺（町の壁、崖、海）はマスの属性 `walls` で表す。したがって手書きのワープは屋内の扉だけになる。

ワールドマップ（ゲームの全体地図）も /dev/maps の升目の図も、この表から描く。

テスト（`maps.test.ts`）では、外のマップがどれも升目に一マスずつあり大きさが同じであることを確かめる。開いた辺ごとにつなぎ目が一つあり、向かいのマップの向かいの辺の同じ位置に出て、帰り道は出た所に戻る。壁の辺は何も通さない。ワールドマップの向きも升目と同じ。どのマップも、出現位置とつなぎ目が歩ける場所にあり、出現位置からすべてのつなぎ目へ歩いて行ける。

## これから

鉱山（鉄鉱石・石材）を旅の道のどこかに置く。今はまだなく、鉄は川底から上がる大戦の錆びた鉄くずを溶かして得る。

## 灰の降る町

降っているのは雪ではなく世界樹の灰で、灰の暮らしは [[world#気候と灰]]。画面では、灰色の細かい粒がゆっくり降り、夜は灯の色を少しだけ帯びて見える（`world/scene/ash.ts`）。

空を向いた面には灰が積もる。平らなところほど厚く、まだらに積もる。物ごとに灰の板を足さず、材質のシェーダーで面の向きから決める（[[decisions#2026-10-25 灰はシェーダーで積もらせる]]）。屋内には積もらない。

地面には薄い灰の膜がどこにでもあり、風の溜まりで厚くなる。道は掃かれていて、道の両脇に掃き寄せた灰の土手ができる（`world/scene/terrain.ts` の `ashen`）。

住民の一日には、屋根の灰下ろし、店や倉庫の前の灰掃き、灰をふるって灰汁を作る仕事が入っている（`routines.ts`）。軒先には灰掃きの箒・灰かきのシャベル・掃き寄せた灰の山・屋根の灰下ろしの熊手・灰ふるいの笊と台・戸口の灰落としの筵・筵をかけた荷・蓋をした水桶と雨水樽を置く（`things.ts`）。

## 戸板の取付断面

入口戸の閉位置は roomDoorSwing が外壁セルから求める。wall_depth_cells は入口から取付面までの厚みを表す。戸板の上下は完成した床と開口上端へ接触させず、vertical_clearance_m の bottom と top でそれぞれ隙間を持たせる。横の通り幅と戸板の回転範囲は枠の内端を基準にする。上下の隙間がゼロ以下、または隙間を引くと戸板が残らない資料は拒否する。描画へ採用する外観戸と、設計ゲートを通す戸には上下の隙間を必須とする。

fittings は戸板の両面から出る補強材と取っ手の寸法を持つ。開閉と身体の平面検査では板厚へ両面の最大突出を加えた厚みを使う。部品の上下位置が異なることを利用して通す判定はしない。描画する外観戸と設計ゲートを通す戸では、この寸法を省略しない。

取っ手の平面上の取付位置は fittings.handle_along_m に蝶番から握る位置までの距離として持つ。戸板の先端を握る位置の代わりにしない。押して入る間と室内側で開閉する間、閉め始めるまでの移動は同じ握る位置への到達を検査する。戸板への身体の干渉検査には握る位置ではなく板全体を使う。取っ手の上下位置と肩・腕の高さを含む到達は別途照合する。

## 寝台の断面

寸法を持つ寝台は家具のグリッドの外形を保ち、bed に完成床からの枠の高さ、床板と枠と脚の寸法、寝具の厚み、頭側の高さと向きを持つ。脚は床から床板の下面まで接続し、枠の内側の床板に寝具を載せる。頭側の板は寝具より上へ出す。部材の寸法を満たしても、持ち主の寝返り・乗降、寝具の乾燥と材料・交換、床の荷重まで設計済みとはしない。

## 棚板と保管区画

寸法を持つ棚は shelf に高さ・板厚・棚板上面の高さ・開く向きを持つ。側板と背板は床へ接し、棚板は側板の内側に納まる。保管内寸には板厚を含めない。中身を描く場合は contents に名前・持ち主・出どころ・置く段と位置・寸法を持たせ、棚板へ支持させる。次の板へ届く物、枠からはみ出す物、同じ場所で重なる物を認めない。物の寸法と取り出す際の経路や使用可能な量は別に照合する。寸法を持つ家具を異なる種類の描画へ割り当てて、資料を無視する状態は資料検査で拒否する。

## 収納から取り出す区間

収納の retrieval は物を正面へ引く距離と身体の左右位置、最初と最後の正面からの距離、身体の半径、使う操作面を持つ。物が完全に棚の正面より外へ出ることと、同時に下がる身体が操作面に収まることを確かめる。物と身体の相対経路、壁やほかの家具、先に置かれた物を途中で横切らない。箱と寝具は手を掛ける左右の前縁への距離も照合する。中央だけへ届くことを、両手で扱えることの代わりにしない。これは物を手前へ出す平面の設計であり、箱の蓋を外す姿勢、持ち運び、空中で傾ける操作まで通過した意味ではない。

小箱は壁と底を同じ板厚とし、取り外す平蓋は別の厚みを持つ。使用内寸と容量はこれらの厚みを除いて求める。設計ゲートを通す棚の物には取り出す区間を必須とする。未設計の取り出し方を、棚に収まることだけで代用しない。

## 炉と煙道の断面

炉は部屋資料の `hearth` の高さと焚口・火室の寸法で石積みから空間を抜く。焚口の横位置は正面の中央を基準にし、北面は東、東面は南、南面は西、西面は北を正方向にする。火室の奥行は正面から内側へ取り、上端から煙道の内寸そのままの喉部を立ち上げる。火室の天井で煙道を塞がず、内寸の全幅が接続しなければならない。炉の本体は天井まで届かせず、立上りを残す。炭は火室の床上へ置き、焚口を表す黒い板を炉の外へ貼らない。

## 炉の手入れ

火室を冷まして燃え残りを除いた後の手入れは `hearth_maintenance` の担当者と身体位置で行う。身体の幅を使用面へ収め、炉や家具へ食い込ませない。掻き出し具の幅と高さを焚口へ照合する。握る位置は使用面の内側に明示し、身体から手が届くことを確かめる。その位置から火室の奥の左右へ道具そのものの長さで届き、刃幅の余裕を残して焚口を通り、ほかの家具に当たらない平面の経路を持たせる。腕と道具の長さを足した距離だけで接続を認めない。これは道具の持ち替えや膝・上体の立体を証明しない。道具の保管先は `tool.storage` の同じ部屋の家具記号と収納物 ID で結び、使う道具と収納物の長さ・刃幅・厚みが一致しなければならない。灰の道具は食材や本と分けた専用棚に収める。棚の内寸と取り出しを照合しても、使用位置へ運び戻す工程が未照合なら `storage_status` は未確認のままにし、設計ゲートを通さない。灰の受け容器と搬出、煙道の煤を落とす掃除口は別途設計する。

## 炉の道具の運搬

`carry` は棚から引き出した直後の身体と道具の相対位置から始め、手入れの身体位置へつなぐ。道具は縦に保ち、身体の位置を結ぶ直線ごとに身体の幅と道具の外形を照合する。向きを変える場所では身体を動かさず、身体から最も遠い道具の角を含む円全体を空ける。帰りは同じ姿勢と経路を逆にたどる。運搬の終点は持ち替えの準備位置へつなぐ。運搬だけの確認は縦の道具を作業姿勢へ移す動きを証明しない。これらが残る間は保管の全工程を照合済みにしない。

## 炉の道具の持ち替え

`handoff` は縦に運び終えた道具から、火室の床へ届く作業の握りへつなぐ。握る場所は刃ではなく柄の途中とし、道具からの距離を保つ。準備場所では道具を持ち上げ、握りと身体を止めて向きを変える。道具が身体を横切る横移動や炉の石積みを抜ける回転を認めない。向きを合わせてから炉の手前で高さを下げ、火室へ差し込む。身体の場所は準備場所と炉の使用面の内側へ収める。

道具の回転は途中で端点の外へ張り出す分と厚みも含め、立体の範囲を照合する。炉の火室・喉部・煙道と石縁の支持は描画と同じ部材へ照合する。この手順は冷えた空の火室に限る。腕・膝・上体と指の姿勢、日課と実際の動作は別途照合し、それらが残る間は保管から手入れして戻す全工程を照合済みにしない。

## 身体の到達と作業姿勢

平面の手の到達距離は配置案の上限であり、実際の腕の長さを保証しない。実際の身体は `world/scene/rig.ts` と `world/scene/figure/animation.ts` の骨格に従う。肩・肘・手首と掌の握り位置から到達を求め、届かない目標へ腕を伸ばして合わせない。道具の握りが立体の空間を通っても、身体の向きと曲げ、腕と膝・上体と周囲の干渉が未照合なら作業姿勢の設計を完了にしない。

`work_pose_candidate` は作業位置への移行前の静止姿勢の候補である。既存の足形を床へ置き、固定長の腕と、炉の石積み・煙道の支持・壁・開いた戸・ほかの家具・床・天井への境界を照合する。家具の立体形状が未定義なら占有の全高を空け、身体の境界が重なる場合は未解決にする。候補の通過を、手首の回転、道具を持つ指、持ち替えからの移行や日課への採用の証明にしない。

靴の接地は描画と同じ左右の靴形状から求め、図形の追加順で足を推定しない。最下点を床へ合わせた後も、それぞれの靴の床からの隙間を保持する。`shoe_contacts` がある候補は指定された靴と実際に床へ触れる靴が一致しなければならない。最下点の一つが触れることは、膝や足の支持面・荷重・重心の安定を証明しない。

`kneeling` を持つ候補は、腰の下降量と接地する膝の左右を明記する。靴の向きは元の姿勢を保ち、両靴の最下点を床へ合わせる。膝の衣服の半径は描画する脚の形状から取り、その表面が床へ触れる高さへ関節を解く。太腿とすねの長さを保ち、指定した高さや足の位置へ届かなければ候補を拒否する。接触点が増えても、荷重・重心と支持面の安定、動作中の支持の移替えを完了した扱いにしない。

作業しない手の位置を指定する場合は `off_hand` に持たせる。`palm_m` は部屋原点からの x・床からの高さ・z で掌の位置を表し、`pole` は骨格の局所座標で曲げる側を指定する点である。作業する手と反対の腕を固定長で解き、届かなければ候補を拒否する。道具から離す位置を指定したことを、膝に手を置いて荷重を支えた証明にはしない。

袖口の前端は手首で止める。前腕から掌へ向かう軸の手首の平面より先へ、丸い袖口の端を伸ばさない。握る位置は掌側にあり、衣服の内側に埋めない。袖口と握る位置が離れることだけで、指が柄を包む接触や手首の可動域を照合した扱いにはしない。

握りの軸は道具の刃から柄の末端へ向く軸に合わせ、元の手首の回転から最小の回転でつなぐ。握りの位置と軸を一致させることを、指の閉じ方や手首の可動域の証明にしない。

`stroke_motion` の `fixed_support` は、身体の位置・両靴・膝を固定し、作業の腕だけで左右へ届かせる候補である。握りを結ぶ直線全体が固定長の腕の到達範囲の内側にあることと、中央と両端の身体の境界を照合する。両端に届いても、途中で肩に近すぎて曲げ切れない区間は認めない。腕と袖口は描画と同じ形状から区間内の移動量の上限を含む囲いを求め、炉・壁・戸・家具と部屋の断面へ全区間を照合する。囲いが重なる区間は細分化し、解消できなければ未解決とする。道具も同じ握りの全区間へ照合する。刃と柄は保管する実物と同じ形状を回転し、上体・脚・反対の腕など固定した身体との離隔も全区間へ照合する。刃は握る腕と手の全体から離し、柄は上腕から離れて手首より掌側だけへ収める。手首の平面は姿勢とともに動くため、前腕の向きが区間内で変わる量も囲いへ加える。柄の握る断面が描画する掌の内部に収まることを照合しても、指が柄を包む接触面や隙間を証明した扱いにはしない。

肩の接続と上腕全体の身体自身との干渉、手首の可動域、指の関節と柄の接触、握力が残るため、現在は `stroke_clearance` を `unverified` とする。室内への離隔だけで連続した動作へ採用しない。

## 炉へ差し込む道具の傾き

作業の握りの高さは `grip_height_m`、刃を水平にしたときの厚みは `blade_thickness_m` に持つ。握りを火室の床の高さへ下げるのではなく、刃の下面と奥の端が床・奥壁へ食い込まない傾きと握る長さを求める。平面で届いても、斜めにした分の長さが不足する道具や焚口の上端へ当たる姿勢は拒否する。

火室の奥の左右へは、刃と握りを一緒に横へずらし、奥壁へ平行に刃を当てる。握りを固定して刃だけを斜めに向け、奥の角を横切る形にしない。道具の傾きと持ち替えは同じ握る長さへ結び、回転途中の端の張出しも照合する。腕が届く候補があっても、全身の姿勢と周囲の干渉を通すまでは作業姿勢の設計を完了にしない。

## 作業姿勢の掌と柄の接触

作業姿勢候補に実物の柄の断面を渡した場合だけ、既存の掌の内部に柄の軸に沿う開口を作る。開口は手首より掌側に限定し、袖口と前腕を削らない。断面は収納資料から組み立てた道具形状を正とし、姿勢資料へ寸法を複製しない。掌の内部に収まらない断面や直交しない軸は拒否する。開口の接触面も既存の手の素材で描く。これは掌と柄の形状の整合であり、指の関節、握力、手首の可動域、全身の支持を証明するものではない。

## 作業する前腕と身体の離隔

前腕・掌・袖口は上体、脚、反対の腕、頭と衣服から全区間を通して離す。骨格の関節を囲う実物の形状を使い、境界の重なりだけで衝突と断定せず、解消できない重なりを通過にも変えない。作業する腕に盾を付ける候補は、盾の動きの照合がないため拒否する。肩でつながる上腕の付け根はこの前腕の検査から分け、上腕全体の離隔を済ませたとは扱わない。

囲いだけでは判定できない場合は形状の符号と、空間内で値が変わる上限を使って領域を細分化する。時間の区間内に前腕が動く量も余裕へ加える。領域の全体がどちらかの形状の外側であることを示せない場合は未解決とする。区間の端や有限の点が空いていることを通過理由にしない。

## 炉の灰の受け容器

冷えた灰の受け容器は掻き出し具と別の収納物として持たせる。蓋付きの鉄の箱とし、本、教材、食材、衣服とは共用しない。収納した空の容器の寸法、壁と底、蓋、使用できる容量は同じ資料へ持たせる。容量は内側の空間を超えない。燃え残りや熱い灰をこの手順へ入れない。使った容器は灰を処理して清掃してから戻す。

`ash_receiver` は同じ部屋の棚と収納物を参照する。`door_approach` は棚から引き出した後の身体位置と、閉じた箱の相対位置を保って戸口の手前へ運ぶ配置案である。身体の幅、箱の全体、向きを変える場所を壁・家具・開いた戸へ照合する。蓋を戻して床上で閉じた箱を `carry_bottom_m` へ移す直線区間は、底・側面・蓋・持ち手の実際の部材で照合する。蓋を戻した直後の部材配列をそのまま持ち上げ、引出し直後の高さへ無操作で戻さない。運搬経路では身体の立位の余裕と箱の上端までの空間を空け、低い灯りや生活の小物も省かない。箱を持つ腕と手、受ける場所への移動、蓋を外す手、灰を受ける動き、荷重と屋外への搬出・処理は別途照合し、`status` は未確認のままとする。経路の終点を町での処理先までの工程と混同しない。

## 灰箱の蓋の持ち手

蓋の中央に鉄の帯を曲げた固定の持ち手を付け、二つの脚と上の握る部分の間を空ける。蓋と持ち手は一緒に外す。持ち手の向きは箱の幅に沿い、棚の向きを変える場合は箱と一緒に向きを変える。収納物の高さは持ち手の最上部までを含む。箱の内側の容量へ持ち手の高さを足さず、持ち手も棚板、天井、運搬の外形の照合へ含める。

持ち手を置いたことだけで指の関節や蓋を持つ手の動きを照合済みとはしない。蓋は棚の外で持ち上げる。蓋と持ち手の移動は箱本体から分け、置き場所と物の経路は [[town#灰箱の蓋の置き場所]] に従う。身体との離隔と荷重は別途照合する。

## 灰箱の蓋の置き場所

`lid_rest` は蓋を置く専用棚と、その上面に収まる蓋の中心を部屋の座標で指定する。教材用の卓や通路は置き場所にしない。棚から箱を引き出した後は、同じ場所で箱を床まで下ろす。蓋を持ち上げ、棚板より上を水平に通してから、持ち手を上にして棚の上面へ下ろす。蓋の裏面全体が棚板に支えられ、箱本体は床に支えられる。

棚板と蓋の高さは実物の寸法から求め、資料に別の高さを書き写さない。箱を下ろす区間と、蓋・持ち手を動かす区間を分け、箱本体、棚、残る収納物、家具、壁、開いた戸、炉の石積みと天井へ全区間を照合する。動かした収納物を元の棚にも残して二重に置かない。蓋を戻すときは同じ部材の経路を逆にたどり、床上の箱へ閉めてから運ぶ高さへ持ち上げる。手の動きと身体の移動、荷重、灰を受ける工程と日課は引き続き別途照合する。

## 炉の横の灰の受け位置

`ash_receiver.receiving` は炉の横で灰を受ける箱の位置と、まだ未確認の移載方法を持つ。収納する箱と同じ部材と向きを使い、蓋を外した底と側面を床へ置く。炉の石積み、家具、壁と戸、灯りと小物、作業する身体と道具へ照合する。固定した支持で左右へ動かす作業の検査にも箱を含め、箱がない空間を前提に通過させない。

現在の箱の縁は炉床より高いため、炉から箱へそのまま灰を掻き落とす方法にはしない。`lift_transfer` は冷えた灰を掻き集め、道具で持ち上げて縁を越えて移す方法の案である。左右へ掻き集める道具の離隔と、灰を持ち上げて傾ける動作は異なる。灰を保持できる道具の面、移載の経路、身体の移行、箱の搬送・持上げと支持・荷重が未照合の間は `receiving.status` を未確認に保つ。位置が空くことだけで灰の処理工程を完成にしない。

## 空の灰箱を炉の手前へ運ぶ

`receiving.approach` は、棚の前で蓋を外した空の箱を炉の手前の空いた床へ運ぶ身体の位置を順に持つ。最初の身体位置は収納からの引出しの終点へ一致させる。箱を運ぶ高さと身体の幅は既存の灰箱の運搬条件を使い、向きと身体からの相対位置を保ったまま卓の間を通す。床から持ち上げ、身体の各移動と同じ変位で箱を動かし、最後の位置で床へ下ろす。床へ下ろす前に箱だけ受け位置へ飛ばさない。

棚へ置いた蓋は障害物として残し、箱の実物の底と側面を全区間で照合する。身体の幅と立位の余裕、箱の全体は壁、開いた戸、家具、低い灯りと小物へ照合する。この手前の位置は最終の受け位置と区別し、そこから箱を置く手と身体の動き、作業姿勢への移行は未確認のままとする。灰を入れた箱の運搬や、空箱の経路の逆走が日課として成立するとは扱わない。

## 空の灰箱を両手で持つ姿勢

`receiving.grip_candidate` は、引き出して床へ置いた箱へ近づき、立位で運ぶ両手を縁へ届かせる候補である。両手の目標は箱の底と側面、運ぶ高さと身体の向き、描画する掌の半径から求める。箱の手前の角を外側から支える案とし、掌の目標は側面の外へ置く。肩と元の上腕・前腕の長さを保って左右を同時に解き、どちらかの腕が届かなければ候補を拒否する。手首の角度と指の接触はこの関節位置の計算から推定しない。

引出しの終点の身体位置では実際の両腕が届かないため、通行幅を調べた `approach` をそのまま実際の運搬へ採用しない。箱へ近づく位置と、腕の長さと上体の囲いを両立する運ぶ高さへ設計案を改める。元の身体の幅や腕の長さを小さくして通過させない。箱と、両腕を除く実際の身体の保守的な囲いも照合する。

この候補と元の経路をつなぐ身体の移動、床の箱を掴む姿勢、立上りと歩行、両腕と手・指と箱の接触、手首の可動域、支持と荷重は未照合である。通行のために予約する幅と身体の実体の離隔を区別して再照合するまでは、候補の未確認を解除せず実際の日課へ採用しない。

## 灰箱を持つ腕と袖口の離隔

立位の灰箱の候補は、左右それぞれの上腕、肘から手首までの前腕、袖口を箱の底と側面から離す。形状は描画と同じ腕の制御点と半径を使い、各円錐を囲うカプセルと箱の部材の距離で照合する。袖口は手首で切る前の保守的な囲いを使うため、接触を通すために描画の外形より細くしない。

箱の縁の中央へ掌を置く案では腕と袖口が箱へ入るため、手前の角の外側へ目標を移し、肘は外へ曲げる。掌の目標と側面の間隔は実際の掌の半径から求める。これは指が縁へ掛かり、重さを支える接触を保証しない。掌と指の表面、手首の向き、両腕と身体自身との離隔、持上げと歩行は未確認のままとする。

## 灰箱を持つ候補と室内の立体

立位の候補は頭・靴と両腕を含む描画の部材の保守的な囲いを、床と天井、壁と開いた戸、家具と灯り・小物、棚へ置いた蓋へ照合する。身体の中心と通路幅だけで、伸ばした腕が空くとは判定しない。これは固定した姿勢の照合であり、持上げと歩行、身体自身や箱との接触、指と手首・荷重を証明しない。

寸法を持つ卓は描画と同じ天板と脚で身体への接触を照合する。卓を天井まで詰まった柱として、天板より上の腕を拒否しない。一方で、灰の箱を置く面と通路の検査は卓の床の占有を保ち、脚の間が空いていることを理由に卓の下へ灰箱を置かない。実形状による接触の検査と、暮らしのために予約する床の用途を混同しない。寸法がない家具は、引き続き占有全体を未確認の障害物として残す。

## 灰箱と身体を同時に移動する空間の案

`receiving.transport_candidate` は、両手の届く `grip_candidate` から炉の手前の身体の待機位置まで、箱と身体を一緒に移す案を持つ。`fixed_pose_translation` は両腕と全身の固定した姿勢を、同じ向きと高さのまま各線分に沿って移す空間の照合である。身体の幅だけを調べた従来の `approach` とは別に持ち、開始位置は握りの候補、終点は手前の身体の待機位置へ一致させる。箱の部材は開始時の身体との相対位置を維持する。途中で箱だけ元の経路の位置へ戻さない。

頭・足と両腕を含む描画部材の囲いと、箱の底と側面を全区間で室内へ照合する。両端だけが空く線分や、途中で卓の間を斜めに抜ける線分をそのまま通さない。卓の実形状で身体への接触を調べても、箱には卓の床の占有を残す。棚に置いた蓋は両方の検査へ残す。

これは足運びや重心の移動を持つ歩行ではない。床の箱を掴んで立位へ移る動作、歩幅と膝・靴の変形、手首と指・荷重、向きを変える動作は未確認である。終点は身体の待機位置であり、箱を灰の受け位置へ置く最終動作ではない。同じ身体の終点でも従来の経路とは箱の相対位置が異なるため、受け位置への引渡しを済んだ扱いにしない。`status` は未確認に保つ。

## 運搬の各描画姿勢と箱の離隔

`transport_candidate.gait_review` は既存の `carry` の全描画姿勢を対象にする。歩行の各姿勢の肩・脚と元の骨の長さを保ち、床へ接する靴を基準に身体の高さを定め、同じ箱の縁へ両腕を解き直す。各姿勢で身体と箱が重ならず、身体と箱を候補の経路に沿って移して室内へ当たらないことを照合する。姿勢の数と元の動きは `world/scene/figure/animation.ts` と `world/scene/rig.ts` を読む。

元の立位だけの位置と箱の高さでは、運搬姿勢の脚の囲いが箱へ重なった。腕や身体の寸法を縮めず、箱の高さと身体の位置を両方見直す。立位と全描画姿勢で両腕が届き、頭と脚、箱と室内の離隔を同時に保つ。高さを上げるだけで頭へ箱を近づけない。

これは各描画姿勢の離隔であり、姿勢間の連続、移動方向と足運び、足を床に残す時間と滑り、速度・歩幅と重心・荷重を証明しない。特に既存の前向きの運搬を、固定した向きで後退・横移動する候補へそのまま当てない。`gait_review.status` は未確認に保ち、固定姿勢の経路を実際の歩行として採用しない。

## 運搬の経路と足運びの向き

`gait_review.step_plan` は身体の経路の各区間に、身体から見た前進・後退・左・右の横移動と、その区間へ割り当てる動作を記録する。方向は画面の左右ではなく、握りの候補の向きに対する移動から求める。`carry` を使う前進は `playback` を forward、後退は reverse とし、横移動へはどちらも流用しない。独立した足の目標で動かす `side_step` は横移動だけに使い、クリップの再生ではないため `playback` は null にする。動作を作っていない区間は `animation` と `playback` の両方を null のままとし、空間の照合が通ったことを足運びの設計完了に置き換えない。

現在の案は固定した向きを維持するため、後退して卓から離れ、横へ移り、前進してから再び横へ移る。後退は既存の姿勢を逆順に再生する候補を持ち、横移動は進行側の足から踏み出し、反対側の足を寄せる候補を持つ。単に前進の姿勢を位置だけずらして実装せず、脚が運ぶ方向と床へ残す足、速度と歩幅、方向が切り替わる位置の姿勢の連続を別に設計する。斜めの区間を追加するときも、その動作を設計するまでは検査で受け入れない。

## 後退の描画姿勢の順序

後退の候補は、同じ `carry` の姿勢を `playback` の reverse で逆順にたどる。負のフレーム番号を渡さず、周期の端でも元の姿勢の並びを逆向きにつなぐ。脚や身体を鏡像へ置き換えず、同じ箱の位置へ両腕を解き直す。元の脚の各姿勢と腕の長さ、箱と身体の寸法を維持する。

姿勢の順序が逆になることと、後退する身体の速度で足が滑らず接地できることは別である。立位から後退の最初の姿勢への移行、移動速度と歩幅、支持する足の切替、荷重と方向が変わる場所の移行は未照合である。前進を逆順にすれば横移動にもなるとは扱わない。候補と設計ゲートは未確認を保つ。

## 箱を持った横移動の足の目標

横移動の候補は進行側の足を先に出し、その足を接地してから反対の足を寄せる。身体の移動分を足の相対位置から差し引き、床に残す足の目標を身体と一緒に滑らせない。踏み出しと着地で足の移動の速さと持上げが急に切り替わらない目標とし、周期の終わりには両足の相対位置を元へ戻す。逆方向も進行側の足を先行させ、足を交差させない。

`gait_review.side_step` は歩幅と足の持上げ、腰を落とす量を持つ。元の身体全体を少し下げて膝を曲げる余地を作り、同じ靴の向きで両足を床へ揃える。大腿と下腿の長さを保って足の目標へ膝を解き、届かない目標は脚を伸ばさず拒否する。両手は同じ箱の縁へ解き直す。前進の脚の姿勢を横向きに回す代用にはしない。

床に残す足の目標と脚の長さ、靴の向きと膝・箱・室内の離隔を標本姿勢で照合する。`scope` は sampled_poses とし、標本の間の立体の離隔や、全経路での速度・接地、支持する足へ重心を移す動き、荷重と方向の切替まで保証しない。候補の状態と設計ゲートは未確認を保つ。

## 横移動の区間と一歩の配分

横移動の各区間は、`side_step.stride_m` を超えない歩幅の完結した周期へ距離を分ける。最後に小さな余りだけを作ったり、周期の途中で到着させたりせず、同じ区間の各周期へ均等に配分する。左右の移動とも区間の終点で両足の相対位置を元へ戻し、次の動作への切替の前に揃える。

区間の始点と終点は元の経路の値を保持し、補間の誤差で外へ通り過ぎない。周期の途中の身体の位置と足の位相を同じ区間の進行から求める。箱と全身の姿勢は、設計した最大の一歩だけでなく、実際に配分した歩幅へも照合する。これは距離と姿勢の対応であり、各周期の時間と加減速、次の動作への移行、荷重の証明ではない。

## 横移動の時間と加減速の候補

`side_step.timing` は一周期の最小時間と、身体の移動速度・加速度の上限を持つ。区間の始まりと終わりで身体の速度と加速度がゼロになる進行を使い、一周期が最小時間より速く進まず、速度と加速度も上限を超えないよう全体の所要時間を求める。短い区間でも急な加速で時間を合わせず、必要なら所要時間を延ばす。計算は `world/town/get-side-step-timing.ts` と `lib/engine/get-rest-to-rest-profile.ts` が持つ。

身体の位置と足の周期・位相は同じ時刻の同じ進行から求める。身体だけを減速して足の周期を一定の速さで進めず、接地している靴の目標を床に残す。開始前と到着後は元の端点で両足を揃え、身体の速度と加速度をゼロに保つ。区間を完了した瞬間に終点を通り越さない。

この上限は身体の移動を対象とし、足の持上げや膝・腕の関節ごとの速さと力を保証しない。重心と荷重、前進・後退と横移動の姿勢の切替、標本間の立体の離隔は別に照合する。候補の状態と設計ゲートは未確認を保ち、日課へ自動採用しない。

## 手続き的な姿勢の描画範囲

脚を開いた姿勢を通常の固定フレームへ収めるために縮小すると、人物の大きさが変わる。必要な姿勢は透明な余白を付け、足元の原点も同じ量だけ移して描く。輪郭と陰影の位相は元の座標へ合わせる。画像と原点は対で扱い、通常の素材の枠へそのまま差し替えない。描画範囲を用意したことは、運搬の日課への採用や接地・荷重の確認を意味しない。

## 寝具の原布と工程の受渡し

供給者の textile_orders は、受取人の部屋の blanket_cutting または pillow_cover_cutting と同じ原布の固有 ID を cloth で参照する。これは完成前の羊毛や糸そのものの識別ではなく、その原布へ回す予定の割当先である。beneficiary は最後に寝具を使う本人、recipient は次の工程へ受け取る相手を持つ。羊毛の供給者から紡ぎ手、織手、仕立て手、本人まで、各工程に同じ原布を一度ずつ割り当て、受取人と工程を照合する。受取人側の必要な工程だけでなく、供給者が宣言した全ての工程からも対象の裁断案へ戻れることを求める。対象の案がない注文や、同じ注文の識別を複数の宣言へ共有する状態を残さない。掛布と枕の側布は別の原布と工程の割当を必要とし、一方の受渡しで他方を代用しない。枕の内袋と詰物の量は側布の裁断や割当へ含めない。

spin は羊毛から糸を紡ぐ独立の工程であり、紡ぎ手が織手と同じ人でも省略しない。同じ担当への recipient はその人の次の工程へ回す案であり、他人からの納品や完成品の取得ではない。紡ぎの workplace は部屋と糸車の家具記号を持ち、同じ町の利用者と、糸車専用の使用面へ結ぶ。共同の部屋の users は利用する住民の固有 ID を持ち、設備を手入れする職員や所有者とは区別する。利用する本人も部屋の設計の前提へ含め、利用時間と交代が未照合のまま設計を通過させない。

status は未成立の案であり、実物の重量・歩留りと製作時間、作業面と身体、受渡しの日課と支払いはまだ設計していない。原料や製品を実在庫へ加えず、発注・納品が済んだ記録として使わない。裁断面と必要な布の外形は受取人の部屋に持ち、供給者の資料へ数量を複製しない。各人の担当と残件は [[resident-マティアス]]、[[resident-ベルタ]]、[[resident-マグダレーナ]] に持つ。

## 寝具の原料予算と工程の収支

裁断案の material_budget は原布の全体の面積と仮の目付を使い、乾いた布の重さを一グラム単位で切り上げる。裁断片は縫い代も含む同じ配置から面積を求め、原布と裁断片の差は端切れとして残す。織り・紡ぎ・準備の歩留りから必要な糸・準備した羊毛・未洗浄の乾いた原毛へ逆算し、それぞれ必要量を切り上げる。工程の前後の差分は実物の損失と丸めの余裕を含む予算上の差であり、実際に捨てた重量ではない。端切れの予算上の重量にも同じ整数化の差を含む。行き先と処理を設計するまで消滅した扱いにしない。

供給者の textile_wool_lots は実在量を未確認の有限の予算案である。原布の raw_lot と羊毛の工程の raw_lot、供給者の allocations を同じ識別で結び、原布ごとに一度だけ割り当てる。各原布が単独で予算へ収まっても、全ての必要量の合計が予算を超えたら拒む。残る予算を別の用途へ自動で使わず、詰物や本人の世帯・売り物の需要も、この割当がないまま確保済みとしない。

目付と歩留りは実測していない条件であり、羊の飼育と季節・毛刈りから得た生産量ではない。準備に使う水と原毛の水分・汚れと脂分、洗浄・乾燥と繊維を整える担当・場所、工程の差分と端切れの行き先、量に応じた保管・運搬・時間と納品は未照合を保つ。ゲームの素材の個数やレシピから重量を換算せず、原料と製品の実在庫を増減しない。未成立の工程と予算を持つ供給者の設計ゲートも通過にしない。
