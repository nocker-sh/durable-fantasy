## 遊び始めと継続した遊びの充実

初回作成から移動・会話・持ち物・戦闘・採集・売買・保存と再開まで、実際のプレイでつながることを優先して確認する。武器・アイテム・住民・生き物・攻撃技・魔法は、定義の数だけでなく、入手場所、使い道、成長段階、住民の生活との対応に欠けがないか調べて増やす。可読性と責務の整理を並行して進め、低スペックのブラウザで遊べることを実測する。軽量化で町の物や人物の見た目を削らず、懐かしい絵の美しさを保つ。

採集のブラウザ検証で、薬草のそばまで移動できた後に経験値待ちが一度タイムアウトした。再試行は通過したが、最初の失敗理由は未特定である。採集 API の完了結果を待ち、失敗時に通知・接続状態・操作中かどうかを記録する検証へ改めた。再発時はこの結果から、資源切れ、拒否、通信失敗を区別して調べる。

## 実行時性能の継続測定

`check-runtime-performance.mjs` で町の単独接続を CPU 制限付きで測定できる。持ち物を開く応答とフレーム速度には実行ごとの揺れがあり、複数回の計測と CPU プロファイルで原因を分ける。初回作成画面の待機失敗では、開発サーバーの差し替え後のページモジュール取得エラーを診断データで確認した。編集を止めた状態と本番ビルドでも再発するかを分けて検証する。低性能 GPU、少ないメモリ、複数接続、戦闘中の性能は未検証である。

## 初回プレイの間欠的な失敗

三人でのパーティ会話の検証中、ひとりの再読込後に準備完了待ちが二度タイムアウトした。他の二人は接続と描画が正常で、再読込した画面は診断取得にも応答しなかった。後の実行は再読込と履歴復元まで通過しているが、原因は未特定である。`check-party-chat.mjs` にはスクリプトの取得失敗、接続・描画準備・画面エラーの記録を加え、診断取得にも期限を設けた。ゲームの準備完了の期限は延ばしていない。再発時に通信と描画のどちらで止まるかを分けて調べる。

キャラクター作成の保存失敗を一度観測したが、以降の作成・入力下書きの復元・保存と再開のブラウザ検証は通過している。間欠的な失敗の再発時は応答と接続状態を記録し、診断なしに通信タイムアウトと断定しない。連続討伐で追跡が解除される原因として、復活時刻が過ぎても敵の HP が描画側でゼロのまま残ることを確認し、接続中のサーバー状態の更新を追加した。初期装備での討伐・同じ部屋での復活・再戦・食事と休憩・保存復元のブラウザ検証は通過した。連続討伐の検証で、前の敵への遅い攻撃拒否が次の追跡を止めることも確認し、対象を指定した取消へ修正した。戦技を含めた検証の範囲は [[game-system#14. サーバー権威と検証]] を参照する。

キー移動後の会話待ちで移動拒否を確認した。キー入力から経路を作る処理を既存経路の移動更新後に移し、作成・キー移動・会話・チャット・保存復元・退出のブラウザ確認は通過した。間欠的な失敗すべての解消を示すものではなく、`check-first-play.mjs` でも拒否内容と停止位置を記録して継続確認する。

## 戦技の消費と攻撃確定

戦技は攻撃要求を先に `wild` DO へ保存し、Player DO の支払い記録とアラームで命中まで再送する形に置き換えた。Void の実際の保存処理を使うメモリストレージで、応答消失、支払いと命中の保存失敗、予約の保存失敗、再起動とアラームの保存失敗を確認する。実 Workers の長時間停止・高遅延を伴う確認は残る。

討伐報酬・分配・反撃は、抽選と分配先を予約へ保存し、命中と配送要求を一緒に保存した後、受取人ごとのキューで送る形へ変更した。受領記録と持ち物・経験値・HP を一緒に保存し、応答消失、両側の保存失敗、再起動、対面取引の保留、復活後の古い反撃の拒否をメモリストレージで検査する。実 Workers の障害と長時間停止、部屋の切断や移動を伴う実プレイの反復確認は残る。

## 都市・マップ・部屋・住民・モンスターの個別設定と描画の再設計

全都市・全マップ・建物と各部屋・住民・モンスターを、一対象一ファイルで資料化する。`.docs/settings/index.json` の対象を、生活と仕事の文章、メタデータ、配列・グリッドで設計し、関連資料の矛盾を解消してから描画へ渡す。コード側の改善、描画と通行判定の切替、全対象の実画面照合まで依頼範囲に含む。基礎資料の網羅と設計完了を混同しない。

対象の一覧と各資料の設計判定は `.docs/settings/index.json` と個別資料を正とし、検査の時点の件数は [[consistency]] に記録する。全建物に平面案があるが、礼拝堂の鐘塔など未設計の部分は残る。平面案の存在を設計完了に置き換えず、未実装の二都市内部を現行の町の流用で完成扱いしない。

配置済みの家具には占有と使用面があり、戸口・階段・利用位置は一点の到達と人の設計幅を含む到達を検査する。指定した一部の同時作業では担当する住民と使用面の重なりも調べる。これは静止した平面の検査であり、扉・椅子・蓋・織機の動作、頭上高、体形と姿勢、荷物を持つ移動、他の人とのすれ違いは引き続き照合する。屋根裏の織機と三人の就寝には、音・埃・明かりと目隠しの干渉も残る。

site_plan を持つ建物は、室内実寸から換算した敷地と、回転後の戸口から道への接続を個別資料で照合する。ほかの建物の敷地も順に詰め、屋根の張出し・窓と煙突、地形と基礎・段差、火と薪・屋外の作業と物流をつなぐ。現行の建物位置と外観はまだ切り替えていない。

全住民の日課は本人のコード定義を参照し、時刻を資料へ転記しない。常用寝台と個人収納は固有IDを持ち、宿の客用枠とは分けて相互に参照する。配置した寝台と収納は実際の家具へ結び、共有収納は人ごとの区画へ分ける。残る家具の配置と収納容量・着替え・日課から寝台への移動を個別に照合する。飲用水、食事、手洗い、便所、燃料と灰、汚水とごみ、仕事着と衣服の手入れを、町の設備と搬出先までつなぐ必要がある。

六種の生き物には個別の食性・水・休息・集まり方・人への反応と素材の由来を記述し、四つの生息マップに必要な地形条件を対応させた。生態の場所を格子へ配置し、採集路と仕事場との干渉、休息・採食・警戒・退避の実装と描画、未決の由来と素材回収の演出を照合する。出現範囲の参照が一致しても、生態と配置が完成したとは扱わない。

仕事場は各世帯の生活と分けて設計する。羊毛・搾乳・チーズを家庭の食卓へ兼用させず、炭焼きと薪割り、荷車の駐車・修理、窯の作業面と熱い天板・薪・灰の搬出入、地図の防湿と納品、織機の部品と糸の搬入を実際の場所につなぐ。暮らしと仕事の関係が閉じるまで、描画済みを理由に設定を承認しない。

エドガーとマルグリットの家は地上の二室に寝台・衣服箱と食卓を分け、揺り椅子、編み物の籠、古い槍の壁掛けを置く案を持つ。元門番の私物と現役の詰所の装備を混同しない。揺り椅子の揺れと立上り、槍の支えと高さ、夜の段差・灯りと生活設備は立体・日課と引き続き照合する。

ヘレナとリーゼルの家は床高・直階段・天井下面・床開口・屋根の傾斜を持つ断面案へ進め、手すりの厚みを有効幅から差し引いた。戸口の位置を見直し、戸の板厚と枠を含む開閉、操作する身体の平面占有と取っ手への距離、道への接続を再照合した。洗濯の籠と桶の取扱いには順序の条件がある。未設計の隣家の屋根との離隔、梁・柱・手すりと開口縁、戸枠と金具の取付け、頭上と姿勢、開いた戸の脇の通行、窓と煙突・排水・火の離隔、日課・操作と描画への反映は残る。他の二階建ての階段と屋根・戸の個別設計も引き続き進める。

## 人物の事前生成画像の更新と再開

登録されている住民の事前生成の対象を現在の描画版で更新し、実際の全画像の復号と寸法・完成資料と現在の定義の一致を確認した。範囲と読み込みの HTTP キャッシュの修正は [[consistency#全住民の事前生成と HTTP キャッシュの識別]] にある。全ての動作・モンスター・建物・部屋を再生成した意味ではない。

一人分の二画像の確定後からの再開は、完走した全画像と一致した。同じ端末のローカル出力先の排他も実プロセスで照合した。符号化の子プロセスが書込み中の強制停止と、古い子の完了を伴う再開は引き続き照合する。途中の計画と完成資料を混ぜず、判定を弱めたり異なる版の一部の画像を混ぜたりして完了にしない。


## 製粉を担う風車と麦畑の供給

[[facility-square-windmill]] に製粉と受渡しの順序、未配置の作業場の格子と現行の羽根の囲い、麦畑の一部を使う敷地候補と全幅を農地から差し引く農道への接続案を持つ。これらの平面の検査を実際の製粉の成立には使わない。検査用の地形について敷地と接続路の全幅の標高範囲を出力し、作業場と曲がり角を同じ高さに置いて道の中心へ下る中心線の標高の予約を持つ。道路を変えず全幅の横断形状へなじませる施工面の予約を追加し、水平な曲がり角と道路側の境界の高さを一致させた。基礎と造成・排水、全幅の横断勾配と継目の施工、荷物と身体の歩行面の断面は未設計である。残りは同資料の pending と issues にある敷地・機構と食品の取扱い、減る収量と世帯・パン屋の供給、搬入と身体・日課の接続である。
