## 複数人で遊ぶ基盤の継続検証

長時間の複数接続、高遅延、マップ移動と切断が重なる場合、取引中の切断について、実サーバーでの反復検証を増やす。取引は Player DO の保留・決定・確定とアラーム再送に置き換えた。Void の実際の保存処理を使うメモリストレージのテストで、準備応答の消失、決定保存の失敗、片側確定後の保存失敗、再起動からの再送を確認している。実 Workers のストレージ障害・長時間停止・アラーム再試行を伴う検証と、復旧待ちの表示の改善は残る。ブラウザの所有権と復帰の現在の範囲は [[game-system#13. 永続化]] にある。別端末への引継ぎと Cookie 消失時の復旧は、アカウントの本人確認方法を決めてから実装する。

## 遊び始めと継続した遊びの充実

初回作成から移動・会話・持ち物・戦闘・採集・売買・保存と再開まで、実際のプレイでつながることを優先して確認する。武器・アイテム・住民・生き物・攻撃技・魔法は、定義の数だけでなく、入手場所、使い道、成長段階、住民の生活との対応に欠けがないか調べて増やす。可読性と責務の整理を並行して進め、低スペックのブラウザで遊べることを実測する。軽量化で町の物や人物の見た目を削らず、懐かしい絵の美しさを保つ。

採集のブラウザ検証で、薬草のそばまで移動できた後に経験値待ちが一度タイムアウトした。再試行は通過したが、最初の失敗理由は未特定である。採集 API の完了結果を待ち、失敗時に通知・接続状態・操作中かどうかを記録する検証へ改めた。再発時はこの結果から、資源切れ、拒否、通信失敗を区別して調べる。

## 実行時性能の継続測定

`check-runtime-performance.mjs` で町の単独接続を CPU 制限付きで測定できる。持ち物を開く応答とフレーム速度には実行ごとの揺れがあり、複数回の計測と CPU プロファイルで原因を分ける。初回作成画面の待機失敗では、開発サーバーの差し替え後のページモジュール取得エラーを診断データで確認した。編集を止めた状態と本番ビルドでも再発するかを分けて検証する。低性能 GPU、少ないメモリ、複数接続、戦闘中の性能は未検証である。

## 初回プレイの間欠的な失敗

初回戦闘の自動確認で、生きている草原のスライムを選んだ後に経験値が増えず、入口付近に留まるケースがある。復活待ちの対象を除外しても再発したため、追跡先の選定、到達可能な経路、行動の取消とサーバーの移動拒否を切り分ける。`scripts/check-first-combat.mjs` は要求・応答の種類と経過時間を失敗時に出す。キャラクター作成の保存失敗も一度観測したが、後の二回は成功した。診断なしの失敗を通信タイムアウトと断定しない。

キー移動後の会話待ちで移動拒否を確認した。キー入力から経路を作る処理を既存経路の移動更新後に移し、作成・キー移動・会話・チャット・保存復元・退出のブラウザ確認は通過した。間欠的な失敗すべての解消を示すものではなく、`check-first-play.mjs` でも拒否内容と停止位置を記録して継続確認する。

## 戦技の消費と攻撃確定

対象の確定と SP 支払いは `wild` DO の一つの逐次処理に移したため、ほかの人の獲物や復活待ちへの攻撃は消費前に拒否する。ただし `player` DO で支払いが保存された後、応答の通信や `wild` の命中保存に失敗すると、消費だけが残りうる。支払い・攻撃・失敗後の回復を、途中の通信失敗と再試行でも重複しない形にする。異なる DO の保存が一つの取引になったわけではない。討伐報酬も、確定後からプレイヤーへの保存までの DO 間の通信・保存失敗に備える必要がある。ブラウザへの通知失敗だけでは報酬保存を中断しないが、報酬の永続的な再送と重複防止は未実装である。

## 武器と術の射程

攻撃の射程は現在、ブラウザの追跡とサーバーの距離検証のどちらも `MELEE_REACH` に固定され、弓や術も近接と同じ距離まで歩く。遠距離の役割を設ける際は、追跡停止・遮蔽物・敵の反撃を合わせて設計する。敵の位置は時刻だけで決まり、一撃ごとの反撃で戦う現行方式との整合を取り、射程だけを延ばして安全な場所から無制限に攻撃できる形にしない。
