降るのは雪ではなく灰である。空を向いた面に積もる灰、地面の灰と道端に掃き寄せた灰、灰の始末の小物、灰下ろし・灰掃き・灰汁作りの日課は済（[[town#灰の降る町]]）。残りは、灰の上の足跡、屋内の入口と窓辺の灰、蓋を使う暮らしを時間割と台詞に少し入れること。屋外の物干しの撤去、室内干しの日課・台詞と、洗濯を仕事にする世帯の屋内の物干しは済（[[town#軒先と路地]]、[[world#気候と灰]]）。最後に、雪の記述が残っていないか矛盾をチェックする。

## 複数人で遊ぶ基盤の継続検証

長時間の複数接続、高遅延、マップ移動と切断が重なる場合、取引中の切断について、実サーバーでの反復検証を増やす。取引の途中で Durable Object の呼出しが失敗した場合の補償も確認する。 `world/server/map-room/trade.ts` は相手への入庫成功後に自分への入庫が失敗すると、相手へ渡した品を回収せず元の品を両者へ返す経路がある。RPC 例外も補償されない。取引ごとの永続的な保留・完了記録と再試行を含め、途中失敗で品や G を複製・消失させない処理へ改める。保留・確定・取消の純粋な状態遷移は `world/core/trade-transaction.ts` に追加したが、Player DO への保存、保留中の変更禁止、決定の永続化と再送、部屋の旧処理の置換は未接続である。ブラウザの所有権と復帰の現在の範囲は [[game-system#13. 永続化]] にある。別端末への引継ぎと Cookie 消失時の復旧は、アカウントの本人確認方法を決めてから実装する。

## 遊び始めと継続した遊びの充実

初回作成から移動・会話・持ち物・戦闘・採集・売買・保存と再開まで、実際のプレイでつながることを優先して確認する。武器・アイテム・住民・生き物・攻撃技・魔法は、定義の数だけでなく、入手場所、使い道、成長段階、住民の生活との対応に欠けがないか調べて増やす。可読性と責務の整理を並行して進め、低スペックのブラウザで遊べることを実測する。軽量化で町の物や人物の見た目を削らず、懐かしい絵の美しさを保つ。

採集のブラウザ検証で、薬草のそばまで移動できた後に経験値待ちが一度タイムアウトした。再試行は通過したが、最初の失敗理由は未特定である。採集 API の完了結果を待ち、失敗時に通知・接続状態・操作中かどうかを記録する検証へ改めた。再発時はこの結果から、資源切れ、拒否、通信失敗を区別して調べる。

## 実行時性能の継続測定

`check-runtime-performance.mjs` で町の単独接続を CPU 制限付きで測定できる。持ち物を開く応答とフレーム速度には実行ごとの揺れがあり、複数回の計測と CPU プロファイルで原因を分ける。初回作成画面の待機失敗では、開発サーバーの差し替え後のページモジュール取得エラーを診断データで確認した。編集を止めた状態と本番ビルドでも再発するかを分けて検証する。低性能 GPU、少ないメモリ、複数接続、戦闘中の性能は未検証である。
