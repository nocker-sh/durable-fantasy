# 仕様書

## 完全な生活

この町のあらゆる物と人は、暮らしとして説明がつく。誰がどこで寝て、何を食べ、それはどこから来て、誰が作り、いくらで、いつ手に入るか。説明のつかない物は置かない。

物を一つ置くときは、持ち主と使い道と出どころを言えなければならない。軒先の樽にも、誰の家の何が入っているかがある。人を一人置くときは、その人の世帯、寝床、食事、仕事、そしてその時刻にそこにいる理由を言えなければならない。売り物を一つ置くときは、作り手、材料の出どころ、値段の理由、売っている時間を言えなければならない。

どれを先に作るか迷ったら、派手な機能より生活の欠けを埋めるほうを先にやる。矛盾がないかは [[consistency]] のチェックリストと自動テストで、節目ごとに何度も確かめる。

## 文書の置き場所

文書どうしは `[[名前]]` でつなぎ、節を指すときは `[[名前#見出し]]` と書く。名前はファイル名から `.md` を除いたもので、フォルダは書かない。

世界観と設定は `.docs/world/` に置く（[[world]]）。開発の文書とは分けておく。これは持ち主が書く文書で、ほかの文書はここに合わせる。読むだけで、書き換えない。

言葉の意味は [[glossary]] で決める。コードの各部分がどうつながって動くかは [[architecture]] にある。

仕様のうち、[[game-system]] はシステムの約束ごとで、サーバー、マップ、所持品、戦闘、成長を決める。[[economy]] は経済で、採集、加工、依頼、店の価格、取引所、お金の出入りを決める。[[town]] は町の地区、店、世帯と建物、屋内マップを決める。[[ui]] は画面の作りを決め、[[game-system]] にあるものだけを画面に出す。

住民・世帯と建物・アイテムの一覧は文書にしない。定義表（`world/town/residents.ts`・`routines.ts`・`houses.ts`、`world/town/people.ts`、`world/core/items.ts`）をそのまま読む。同じように、コードが決めている数・値段・式・時刻・品揃えは文書に写さず、どのファイルにあるかだけを書く。文書には、コードからは読めない狙いと決まりと理由を書く。同じことを二つの文書に書かず、持ち主の文書に書いて、ほかからはつなぐ。

作業の記録のうち、[[backlog]] は受けた指示のうちまだ終わっていないもので、終わったものはその仕様書に移す。[[decisions]] は持ち主の確認を待たずに決めたことと、その理由を残す。[[consistency]] は生活の整合を確かめるチェックリストと、これまでの検査の記録である。
