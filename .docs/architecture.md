# コードの作り

ディレクトリの役割と依存の向きは `AGENTS.md` の「ディレクトリ構成」で決めてある。この文書は、それらがどうつながって動くかを書く。言葉の意味は [[glossary]]、サーバーの決まりは [[game-system]] にある。

## 操作が流れる順

倉庫の預け入れ・引き取りは `world/core/storage-command.ts` が扱い、共通の回復・行動不能の判定後に呼ぶ。料金、品質を保った移し替え、空き枠・重量の判定をここにまとめる。店と倉庫の利用で親しさを増やす日付の規則は `commerce-friendship.ts` を共用する。

攻撃技・魔法・祈りの効果は `world/core/skills.ts` で種類ごとの型に分ける。`combat.ts` の攻撃計算は物理技と魔法の効果だけを受け取り、必要な倍率・能力値の指定漏れを既定値で補わない。祈りの回復と技の消費・待ち時間は `skill-command.ts` の状態遷移が扱う。

店全体の営業と、会話相手本人の店番は `world/maps/index.ts` の `keeperPresent` を共用して判定する。交代相手が営業していても、休んでいる本人には買い物や製作依頼を出さない。会話の選択時にも現在の店番を確認する。

採集道具の選択は `world/core/gathering-tool.ts` で行い、袋と装備中の使用可能な道具を品質込みの性能で比べる。同じ性能なら装備中を優先する。選んだ道具の所在を型で区別し、採集成功時だけその道具の耐久を減らす。

製作依頼の受注と受け取りは `world/core/commission-command.ts` の状態遷移で扱う。`apply.ts` は共通の回復・行動不能判定を済ませてから呼び出す。材料や所持金が不足した受注、持ち物が満杯の受け取りでは、依頼・材料・代金を変更しない。

ブラウザでは `world/game.ts` の Game がゲーム全体を持つ。Game は three.js の場面、キー入力、部屋との接続、プレイヤーのデータを持ち、画面に出すものを一つの値（`world/state.ts`）にまとめる。React の部品（`components/`）は、`components/game/context.tsx` を通してその値を読み、Game のメソッドを呼ぶだけで、ゲームの状態を自分では持たない。セッションの状態と、接続・サーバー通知・会話・生産や装備操作・交流の処理は `world/client/` が受け持つ。各処理は同じ GameSession を参照し、必要な操作だけを渡される。`world/parts/` はキー入力、開いている窓、部屋の先読み、会話の選択肢、出来事の知らせなどを受け持つ。

製作依頼の残り時間は、表示中の職人に未完成の注文がある間だけ更新する。閉じた窓、注文のない窓、すべて完成した窓にはタイマーを残さない。期限の更新には `hooks/use-deadline-clock.ts` を使い、長い製作待ちは低い頻度で更新しつつ最後の期限では完成表示へ切り替える。

プレイヤーの経路移動は実際の経過時間から距離を計算し、マスの境界で余った距離も次の区間に使う（`lib/engine/path-follower.ts`）。低い描画頻度でもサーバーと同じ歩行速度を保ち、停止中に経過した時間も現在の経路の終点まで反映する。演出の時間刻みの上限は移動距離に使わない。

キーを押し続けた移動では、既存の経路をそのフレームの経過時間だけ進めてから、次の経路を作って送信する。新しく送った経路に直前のフレームの待ち時間を使うと、サーバーが経路を受け取るより先に進みすぎるため、入力と移動更新の順序を保つ。

生き物の出現定義は `world/core/monsters.ts` に置き、読み込み時に ID とマップの索引を作る。戦闘の対象検索は `spawnOf`、マップ入場・復活確認・描画の生成は `spawnsOn` を共有する。マップ内の全 HP を読むときに各個体を全定義から探し直さず、定義順を保った読み取り専用の一覧を使う。未知のマップには空の一覧を返し、問い合わせのたびに索引を増やさない。

移動先に着いて行う会話・採集と、戦闘の追跡は `world/scene/runtime/action-target.ts` の `PendingAction` が一つだけ保持する。新しい行動は前の予約を置き換える。到着した会話・採集は通知前に取り出して消費し、通知中に設定された次の行動を同じ到着で実行しない。戦闘は短い追跡経路の到着では消費せず、停止・別の行動・対象の戦闘終了で解除する。 敵への接近は、攻撃範囲内の空きマスへ実際に経路を引けることまで確かめる。最初の候補が到達不能なら周囲の別候補を試し、経路が受理された時点で探索を止める。

ブラウザはマップの部屋と WebSocket でつながる。送り合うメッセージの形は `world/protocol.ts` にあり、サーバーは受け取ったメッセージを zod で確かめる。部屋の入口は `routes/map/[mapId].ws.ts` で、メッセージの種類ごとの処理は `world/server/map-room/` にある。周囲への発言と叫びの範囲・頻度の確認は `chat.ts` が受け持つ。連投判定には直近の上限件数だけを保持し、拒否した発言も待ち時間に含めながら、接続状態の配列が送信回数に比例して増えないようにする。戦闘の受付・命中・反撃は `combat.ts`、討伐報酬とパーティへの経験値分配は `combat-rewards.ts` が受け持つ。ブラウザは命中通知で描画とセッションの敵 HP・復活時刻を更新し、倒れた対象が自分の戦闘対象なら解除する。描画がまだない場合も状態を保持する。敵がいるマップでは既存の接続確認に合わせて `wild.ts` がサーバーの現在の HP と復活時刻を読み直し、接続中のブラウザへ返す。接続ごとに更新間隔を制限し、敵のいない町と未参加の接続では問い合わせない。復活はこの応答で反映し、ブラウザの時刻だけでは HP を戻さない。攻撃の拒否通知には対象の識別子を付け、描画側は現在追っている対象が一致する場合だけ停止する。前の討伐に対する遅い拒否で、次の敵への移動や別の行動を取り消さない。報酬処理は討伐が確定したときだけ呼び、分配の計算は `world/core/party.ts` に置く。戦闘の演出・結果通知の失敗で、報酬や反撃の保存を中断しない。通知の失敗は内容を含めず記録し、再接続では保存済みの状態を読み直す。保存や DO 間の呼び出しの失敗は通知の失敗として握りつぶさない。

部屋は位置にかかわる確認をする。歩いた道がそのマップの歩けるマスを通っているか、店主や扉に十分近いか、などである。確認が済むと、部屋はそのプレイヤーの Durable Object に規則の実行を頼み、結果を本人に返す。食事・薬の回復、満腹と時間付き効果は `world/core/consume-command.ts` にまとめる。効果がないなどの拒否条件を確認してから持ち物を減らし、所持品から使う操作とショートカットから使う操作で同じ規則を通す。戦技・祈り・応急手当の消費と回復は `world/core/skill-command.ts` にまとめ、共通の条件確認を通す。技の種類ごとに威力や回復の定義を型で必須にする。

規則そのものは `world/core/` の純粋な関数で、状態とコマンドを受け取り、受け入れて新しい状態と出来事を返すか、理由を付けて断る。同じ関数をブラウザでも使い、押せないボタンを灰色にする。結果を決めるのはいつもサーバーである。

## Durable Objects

Durable Object の入口は `durable-objects/` にあり、どれも Void の規約に従う。プレイヤー一人ごとの `player`、町ごとの `directory` と `nature`、全部の町で一つの `market` と `exchange`、生き物の具合を持つ `wild`、パーティごとの `party` がある。どれをいくつ持つかは世界観と対応させてある（[[world#世界の作りと Durable Objects]]）。マップの部屋は誰もいなくなると何も持たずに閉じ、続けて残すべきものは `player` などほかの Durable Object に置く。

## 定義表

住民、世帯と建物、日課、台詞、店、アイテム、レシピ、マップは TypeScript の定義表にあり、状態は ID だけを持って定義表から引く。住民の日課は定義を読み込むときに一度だけ時刻順に並べ、営業・会話・表示の判定で再利用する（`lib/engine/cyclic-schedule.ts`）。住民と町の表は `world/town/`、ルールにかかわる表は `world/core/`、マップは `world/maps/` にある。住民と台詞は世帯単位、建物は地区単位でファイルを分ける。製作の定義と品質計算は `world/core/crafting.ts`、レシピの表は `world/core/recipes/` に分ける。コマンドの共通検証は `world/core/apply.ts`、製作時の材料・品質・費用・経験値の処理は `world/core/craft-command.ts` に置く。採集の道具選択・耐久消費・成果の受け取りは `world/core/gather-command.ts` にまとめる。装備の着脱・持ち替え・品質と耐久の引継ぎは `world/core/equipment-command.ts` にまとめる。取引の持ち物・所持金の出入りは `world/core/trade-command.ts`、持ち物と装備の合計重量は `world/core/inventory-weight.ts` にまとめる。取引の保留と確定は `world/core/trade-transaction.ts` が扱い、出入りの規則を共通の入口から呼ぶ。承認と拒否の結果型は `world/core/transition.ts` で共有する。職種ごとの現行レシピと将来の節目のレシピを元の順でまとめ、ID からの参照には一度だけ作る索引を使う。住民の一覧順は焼き出したスプライトの番号に対応するため、定義の置き場所を変えても順は変えない。マップの歩けるマスと住民の立つ場所は、描画の側の地形から `scripts/export-map.ts` で `world/maps/<マップ>.json` に書き出し、サーバーはこの JSON だけで確かめる。場面を組み立てなくてよいようにするためである。地形や建物を変えたら書き出し直す。

## 描画

プレイヤーと他の接続者の地面の高さは、人物ごとに座標が変わったときだけ求める（`lib/engine/position-sample.ts`、`world/scene/runtime/walkers.ts`）。配置済みの高さをカメラ追従・遮蔽の照準・名札と吹き出しでも使う。マップごとに人物と保持値を作り直し、外見の変更後も同じ座標の高さを新しい姿へ適用する。地形が途中で変わる場合は保持値を作り直す必要がある。

マップの描画の入口は `world/scene/index.ts` の MapScene で、地形・住民配置・照明・歩行者・入力は `world/scene/runtime/` に分ける。建物・野外・小物・テクスチャはそれぞれ `construction/`・`fields/`・`props/`・`textures/` に、人物の体・服・髪・装備・描画は `figure/` に分ける。描画は `world/scene/` が受け持ち、ゲームに依存しない部品は `lib/graphics/` と `lib/engine/` にある。地形の高さ・道・川の計算は、選んだマップのデータが必要になった時点で行う。Worker の読み込み時に未使用の初期マップを計算せず、保存済みの地形があればそれを使う。道・川・踏み跡までの距離は、地形生成の開始時に線分を `lib/engine/polyline.ts` のインスタンスへ写し、線分の方向と長さを各地点で計算し直さない。地面の絵は重いので、いくつかの Web Worker で帯に分けて描き、描いた絵はブラウザの IndexedDB に残して次からはそれを使う。残した絵は描くコードそのものを鍵にしているので、コードを変えれば描き直される。先読みと入場時の地面生成は、同じマップなら進行中の処理を共有する。入場先が先読みの順番待ちなら先に開始し、失敗した読み込みは次回にやり直せるようにする。描き終えた地面は保存完了を待たずに表示へ渡す。保存中も同じ地面を共有し、IndexedDB の取引完了まで確認してから進行中の処理を外す。住民の姿はドット絵のスプライトで、`scripts/bake-sprites.ts` で前もって八方向の動きを `public/tmp/sprites/` に焼いておく。この生成物は Git に含めない。配信時は `public/.assetsignore` で `tmp/` の診断ログ・スクリーンショット等を除外し、ゲームで読む `tmp/sprites/` だけを残す。焼いていない組み合わせ（プレイヤーの見た目など）は、スプライト用の Worker がその場で描く。`world/scene/anims.json` は生成されたモーションデータであり、実装ファイルと同じ理由では分割しない。地面の灰は不透明な画素として先に判定し、灰で隠れる草や石は計算しない。灰は物ごとに板を足さず、材質のシェーダーで空を向いた面に積もらせる。

マップ入場の計測は `bun scripts/check-map-loading.mjs` で行う。新しいブラウザで地面の先読みと部屋の先行接続を止め、初回入場と別のマップを経由した再訪を比べる。結果は Git 対象外の `public/tmp/map-loading.json` に書く。これは実際の接続と描画の準備を含むが、出口を踏んでサーバーが移動を許可するまでの時間は含まない。

複数接続の基本確認は `bun scripts/check-multiplayer.mjs` で行う。独立したブラウザの保存領域で二人を作成し、同じ町とチャンネルへ入り、相互の入場通知・チャット配送・パーティへの招待と承諾・退出の通知を確かめる。町をまたぐ入場は開発サーバーの許可を使うため、本番の糸による訪問権限の検査には使わない。失敗時の画面と接続・読み込み状態は Git 対象外の `public/tmp/` に残す。Cookie や保存済みプレイヤーの全データは出力しない。

町の実行時性能は `bun scripts/check-runtime-performance.mjs` で確認する。ゲームの描画 FPS と別に、ブラウザのアニメーションフレーム通知の間隔を記録する。間隔の中央値・上位の値・最大値と長い停止の割合を残し、平均だけでは見えない引っかかりを調べる。この通知の回数をゲームの描画回数として扱わない。新規キャラを実際に作成し、接続中の町で通常速度と CPU 制限時の描画速度、メインスレッドの稼働時間、持ち物を開く応答と移動を調べる。出力は Git 対象外の `public/tmp/runtime-performance.json` に保存する。操作時間には自動操作の通信時間も含む。開発サーバー上の単独接続での測定であり、遅い GPU・少ないメモリ・多数のプレイヤーを再現したものではない。

描画は低い性能の機械でも動くことを優先し、設定画面は置かない。動かない物は、材質が同じで、いちばん近い「動く親」（薄くなる家、消える屋台、揺れる木の冠など）が同じもの同士を一つのメッシュにまとめて描く（`lib/graphics/batch.ts`）。物の数も見た目も変えず、GPU に出す命令の数だけを減らす。動く物は作るときに登録し、動かない物の変換行列は毎フレーム計算し直さない。煙突の煙は同じテクスチャを使う板を一括描画し、カメラからの距離順に並べる。共有する描画済み画像は容量と件数に上限を設け、最近使っていないものからデコード済みデータを解放する（`lib/graphics/bitmap-cache.ts`、上限は `world/scene/sprite-pool.ts`）。人物の表示用キャンバスへコピーしてから共有キャッシュに渡すため、追い出しても表示中の姿は消えない。再び必要になった画像は保存済みデータから読み直すか、Worker で再生成する。材質キャッシュは元画像を弱参照で保持し、使わなくなったマップの画像を引き留めない。破棄した材質はキャッシュから外し、再訪時に作り直す。人物ごとの表示用キャンバスにも保持数の上限を設け、表示中のテクスチャを避けて古い動作・方向から解放する。解放後に届く描画結果は破棄する。人物の描画要求は同じフレームを重複登録せず、マップを離れるときと姿を交換するときに、その人物のテクスチャを解放する。生き物の表示位置はサーバーと同じ時刻の計算を使い、描画側だけ直近の休憩地点を保持して毎フレームの地形判定を減らす。保持する地点は固定数とし、地形が固定されたマップごとに作り直す（`world/core/monsters.ts` の `MonsterMotion`）。倒されて復活を待つ生き物は、破片演出が終わった後の位置計算を止める。サーバーが復活を通知した時点の時刻から位置を計算し、待機中のフレームを再生しない。生き物の描画用の地面の高さは、位置が変わったときに計算し直す。静止中と破片の間で同じ高さを共有し、座標配列も再利用する。高さの保持はマップごとに作る描画オブジェクトに閉じる（`world/scene/monsters.ts`）。灰の粒の揺れは `lib/engine/phase-oscillator.ts` で固定の位相を事前計算し、時刻の三角関数を粒どうしで共有する。粒数と元の運動式は保つ。うさぎの形状は同じ材質と影の設定の部品を本体の下でまとめ、移動・選択の輪郭・部品ごとの影を保ちながら描画命令を減らす。統合後の不要な元形状は直ちに解放する。戦闘の破片演出は、終了時と再発生時に古い形状と材質を解放し、生き物と共有するテクスチャは残す。影は毎フレームではなく、決まった間隔と太陽が動いたときにだけ描き直し、描画は 60fps を上限にする。ブラウザのフレーム時刻を使い、微小な時刻の丸めで描画を飛ばさず、高リフレッシュレートの画面でも過剰に描画しない（`lib/engine/frame-limiter.ts`、影の間隔と描画上限は `world/scene/runtime/create.ts`）。

人物は `world/scene/actors.ts`、町の鶏・猫・豚・羊の行動と配置は `world/scene/animals.ts` に分ける。住民と町の動物の地面の高さは `lib/engine/position-sample.ts` で直前の座標と結果を保持し、歩行や配置換えで座標が変わったときに求め直す。立ち止まっている間も姿勢や向きの更新は続ける。住民と生き物の名前表示には、配置に使った地面の高さを渡し、画面投影で地形を重ねて調べない。保持する値の寿命はマップ内の描画オブジェクトに合わせる。

名前・体力表示・吹き出しの画面位置は `lib/graphics/screen-labels.ts` が保持し、ピクセル位置と表示状態が変わったときだけ DOM のスタイルを書き換える。非表示中は位置を書き換えず、再表示時に現在の位置へ更新する。住民名のホバー装飾も対象の切替時だけ更新する。

ポインター移動によるホバー判定は、各描画フレームで最後に届いた座標だけを使う。クリック時の判定はそのクリックの座標で即時に行い、描画待ちによる入力の取り違えを避ける。

## 開発用の道具

`/dev` のページ（`pages/dev/` と `dev/`）では、定義表を一覧し、住民や物を一つずつ見て、描画を試せる。建物詳細は間取りから各階の室内を組み立て、階と昼夜を切り替えて表示する。民家の表示用データはゲームの入場可能マップには登録しない。サムネイルは画像へ変換した直後に、回転表示は閉じるときに、使ったGPUリソースを解放する。共有している形状・材質・テクスチャは重複して解放しない（`lib/graphics/scene-resources.ts`）。サムネイルの保存キーには表示サイズも含める。ゲームの画面には開発用のものを出さず、開発用のパネルは開発中のビルドにだけ出す（[[ui#1. 原則]]）。

`scripts/` のスクリプトは bun で動かす。マップの書き出し、スプライトの焼き込み、屋外のマップと屋内の写真撮り、`/dev` の全ページがはみ出していないかの確認、経済の試算がある。写真を撮るものは開発サーバーを動かした状態で使う。

## テスト

初回戦闘と採集のブラウザ検証は `CPU_SLOWDOWN=4` で CPU 制限付きにもできる。キャラクター作成前から再読込後まで同じ制限を適用し、結果にも倍率を記録する。既存の操作・保存の検査と待機期限を維持する。GPU の遅さやメモリ不足を再現する設定ではない。

テストは実装と同じディレクトリに `*.test.ts` で置き、`vp run test` で動かす。規則のテストは `world/core/` の関数を直接呼ぶ。町の暮らしの整合（寝床の数、日課、通れる道、軒先の物の置き場など）もテストで確かめ、テストにできないものは [[consistency]] のチェックリストで確かめる。`lib/engine/` には、依存の向きと実行時の import に循環がないことを確かめるテストがある。型だけの依存は `import type`・`export type` で明示し、実行時の依存に含めない。

HP・SP の表示は回復が残る間だけ定期更新し、満タンまたは行動不能で停止する。満腹・温まり・集中の表示も、すべて尽きたらタイマーを止める。プレイヤーの状態が更新されたらその場で表示を計算し直し、回復や効果が生じたら再開する（`components/hud/status-frame.tsx`）。

## ブラウザの所有権と復帰

`routes/api/session.ts` は `world/server/session.ts` を呼び、ブラウザの所有権を Cookie とプレイヤーの Durable Object で照合する。マップ接続は認証済みの所有者を接続状態へ置く。プロフィールの入力規則は `world/core/player.ts`、復帰位置の計算は `world/core/location.ts` にあり、描画や UI を参照しない。作成途中の入力は `world/client/profile-draft.ts` が扱う。プレイヤーの保存先でも HP がない間の歩行とマップ移動を拒否する。倒れたときは、その時刻までに歩いた位置へ経路を止め、HP と同じ状態保存で確定する。再接続後に残りの経路を歩き終えた扱いにせず、復活で HP が戻った後に町への移動を受け付ける。保存・移行の約束は [[game-system#13. 永続化]] を参照する。
